# Matmul 单侧全载的复用键、Scale 切片与 L1 预算

当单核沿 N 连续计算多块输出而 A 的同一 M×K 区域不变时，可将 A 及其 scale 常驻 L1，只让 B 流式加载；沿 M 复用固定 B 的情形对称。适用条件是数据在复用范围内不变、实际物理布局可容纳、消费者能从驻留布局取数，而且节省重复加载值得增加的资源占用。

## 复用范围比循环计数更重要

驻留对象至少由数据地址、batch/group、M或N起点、K区间、dtype/format和scale坐标共同识别。跨 `operator()` 或外层循环保留计数器，只能表达“曾经加载过”，不能证明下一个任务需要的是同一数据。M tile、专家、batch、K分区或量化元数据变化时，必须更新对应驻留内容，或证明其共享关系。

来源的 A-Full-Load 示例分别采用“首个外层任务分段搬完 A”和“一次搬全 scaleA”的组织方式；文中也有一次搬完全部 A 的示意图。这些是不同发射粒度，不应混为固定配方。驻留复用保证的是每个相同片段无需在每个外层迭代重复加载，不保证数据必须在单条搬运指令中装完。

第 j 个 K 段从驻留 A 的全 K 坐标读取，scale也要按该段量化块定位。例如先取 `j*kL1`，再叠加 L0 内偏移，并按量化 group size 和实际 scale layout 转成 scale 坐标。总是读取 scale 驻留区首片，会让不同 K 段使用错误量化参数。

## 预算与事件

A常驻时，L1总占用应逐项计为：A实际物理字节 + scaleA实际物理字节 + B流式各槽字节 + scaleB各槽字节 + 其他常驻/对齐区。FP4 的数据字节须按打包及补齐计算，不能直接使用C++类型的sizeof；scale的group数、存储单位和多份布局也不能省略。L1容量以目标硬件/库配置为准，524288B是512KiB，不能写成524KB后混算。

常驻侧在首次完成加载后向其消费者发布就绪；在内容确实不再被覆盖的复用区间内，无须为每个只读消费者重新获取可写槽。区间结束后的回收仍须等待全部消费者完成。流式侧保留独立的就绪/释放协议。SetFlag本身不会发起覆写，是否错误覆盖取决于实际后续生产者和地址；不能只删一个事件就声称常驻安全。

选择较小的流式 K 覆盖可能为常驻侧腾出空间，但会增加迭代和发射开销。A/B全载互斥、必须保留半个L1、A全载禁止M尾再切、固定window=4、禁配StreamK等，属于所述调度器的实现选择，不能推广为所有Matmul的物理限制。拆分K之后仍可能复用本核的固定K子区，需重新推导缓存键和输出归约合同。

## 正确计算节省量

若相同驻留侧实际大小为 R，对侧共迭代 T 次，原总流量为 `T*R + S`（S为所有不被本优化减少的流量），改造后为 `R + S`。节省字节数是 `(T-1)*R`，总流量下降比例是 `(T-1)*R/(T*R+S)`；`(T-1)/T`只代表该重复侧的下降比例。T=1没有这项重复加载收益。

来源报告 MXFP4 `[M,K,N]=[128,4096,81920]` 的Task由183.87到170.07μs，属于其特定案例，不能作为5%–15%的通用保证。Bias、LUT、mask、位置编码或KV片段也可考虑驻留，但必须分别证明内容不变、布局可达及所在存储可被对应流水消费，不能仅因数据小就放入L1。

验证应覆盖复用键不变与变化、第二个外层任务、全部K切片、量化块边界、尾块和多核任务调度。结合实际MTE2字节数、资源预算、事件与完整时延，判断是否真的消除了重复加载。基本所有权见[缓冲指南](../../guides/memory/buffer_ownership_and_slot_layout.md)。
