# 带尾部折叠的树形求和及其精度边界

对较长向量，树形求和可缩短连续累加的依赖链。一个组织方式是先找不大于 count 的最大二次幂 P，把 P 之后的尾部并入前面对应元素，再逐轮合并相距当前半区长度的元素，最后对剩余短向量做局部归约。

尾部折叠要保证每个有效元素恰好贡献一次。count=0 需要按算子定义单独处理；非整向量长度的折叠调用需要有效 mask 或合法 count。若使用原地折叠，输入会被修改，后续计算不能再把这份缓冲当作原始数据使用。

树形结构改变了浮点加法顺序，通常能改善某些长链累加的误差与并行性，但它不会自动把数值按量级配对，也不能保证每种输入都比原实现更精确。现有 ReduceSum 的内部实现也未必是简单顺序累加，不能仅按函数名宣称替换必然有收益。

多行版本还需验证 repeat 数、行间步长、缓冲重叠与输出布局。来源中的 64 元素收尾阈值是示例设定，应根据目标 dtype、指令接口和平台确定实际阈值。

比较时使用相同输入和输出契约，覆盖二次幂及其相邻长度、符号抵消、大量小值混入大值、特殊值与多行尾块，同时记录误差和耗时。本文保留算法候选及其条件，未将来源示意实现标为已编译或已测量的性能结论。

## 独立累加器、依赖深度与尾部有效性

把行归约分到多个独立累加器，可以在最终合并前暴露独立指令链。每个累加器必须先初始化为相应单位元：求和为零，最大值可用算子合同允许的负无穷/最小值，并另行保持 NaN、index 和 tie 语义。原片段中先声明累加器再直接参与 Add 的写法不能证明寄存器已初始化。行数不被累加器数整除时，剩余行仍需恰好参与一次，不能依赖 d0/4 截断。

四个完整块 c0、c1、c2、c3 的 `(c0+c2)+(c1+c3)` 需要三次向量加法，依赖深度为两层；从第一个块开始的线性相加也是三次加法，但依赖深度为三层。若线性基线先把零与首块相加，它多出的初始化加法不能作为“二叉折叠必然把指令数减半”的证据。独立累加器与树形最终合并可以组合，数量四也不是平台通用最优值。

当 c3 只有部分有效 lane 时，尾部 Load 本身必须合法；后续 Add 上的 mask 不会补救此前的越界加载。无效 lane 若采用合并式 mask，应保留已有合法部分和，不能留下未初始化寄存器值；若通过填充规避尾部，需保证已分配容量和正确单位元。零块、少于四块、多行 stride 和最后一行均需独立验证。

浮点重排在抵消场景下可能显著改变相对误差，不保证只影响末几位。按既定算子精度合同比较同一输入，不因优化需要擅自把 golden 容差改为 1e-3。性能比较同时记录总时延、真实指令数、发射间隙与寄存器压力，不能只用结构上的依赖深度预测收益。
