# EXEC_NPU_CMD 参数序：inputs → attrs → 输出 tensor 必须最后——按 msopgen 自动生成的 GetWorkspaceSize 签名对齐

`EXEC_NPU_CMD` arg order must match the msopgen auto-gen `aclnn<Op>GetWorkspaceSize` wrapper — inputs → attrs → output (output LAST); interleaving the output tensor with inputs/attrs segfaults at runtime.

- **Severity**: HIGH (silent runtime segfault — compiles clean, crashes at first launch with no AscendC-side diagnostic).
- **Symptom**: the op compiles and installs, but the first `EXEC_NPU_CMD(aclnn<Op>, ...)` call in the op_host aclnn ext wrapper segfaults. No error code, no aicore exception — the host process dies inside the aclnn workspace-size resolution.
- **Root cause**: the `aclnn<Op>` wrapper auto-generated by msopgen (`scripts/rename_aclnn_autogen.py`) calls `aclnn<Op>GetWorkspaceSize(...)` with a FIXED argument order: **all inputs → all attrs → the output tensor LAST**. `EXEC_NPU_CMD` forwards its variadic args to that `GetWorkspaceSize` call in the same order, so the ext file's `EXEC_NPU_CMD` arg list MUST follow `inputs → attrs → output`. Putting the output tensor anywhere earlier (e.g. interleaved between inputs/attrs) misaligns every subsequent arg → the workspace-size resolver dereferences a mistyped pointer → segfault.
- **Fix**: order the `EXEC_NPU_CMD` args as `(aclnnOp, in1, in2, ..., attr1, attr2, ..., out)` — the output tensor is the LAST positional arg. Derive the exact order from the auto-generated `aclnn<Op>.cpp` `GetWorkspaceSize` signature, NOT from the op's logical dataflow.
  - Wrong: `EXEC_NPU_CMD(aclnnOp, in1, in2, out, attr1, attr2)` → segfault
  - Right: `EXEC_NPU_CMD(aclnnOp, in1, in2, attr1, attr2, out)` → runs
- **Detection**: grep the op_host aclnn ext for `EXEC_NPU_CMD` and diff its arg order against the auto-gen `aclnn<Op>.cpp` `aclnn<Op>GetWorkspaceSize(...)` signature; any positional mismatch is the bug.
- **Cross-ref**: EC-87 (the other msopgen-auto-gen / MIX-kernel build artifact trap — clearWorkspace injection).
