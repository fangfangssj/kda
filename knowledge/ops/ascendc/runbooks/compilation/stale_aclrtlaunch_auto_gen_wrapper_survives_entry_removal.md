**EC-204** — **stale autogenerated `aclrtlaunch_*_debug.h` in `kernel/build/auto_gen/` survives debug-entry removal** — the raw-launch build chain autogenerates per-entry wrappers at configure time with no prune pass, so REMOVING/RENAMING an entry point then incremental-rebuilding fails against the orphan wrapper (adding/changing entries is incremental-safe; deleting is not). Fix: `rm -rf kernel/build` + full rebuild. Detection: build error names an `aclrtlaunch_*` wrapper whose source entry no longer exists in the tree → stale `auto_gen/`, not a source bug. gelu 310p 2026-08-12 (failures_ledger build iter 2 → clean final .so). Cross-ref CAND-DAV-M200-HARDCODED-EVENT-ID-HANG, [PB-112](pb_112_select_with_selmode_vsel_cmpmask_spr_applies_the.md).

`unverified_on: soc=Ascend950PR, Ascend910 build chains (the auto_gen-into-build-dir mechanism is shared harness code — likely transfers; unverified)`

- **Symptom**: after REMOVING a temporary debug kernel entry (`Kernel<Op>Debug` + its
  `run_<op>_debug` launcher) from the shipped sources, the next INCREMENTAL build still
  trips on the autogenerated launch wrapper `aclrtlaunch_<op>_kernel_debug.h` under
  `kernel/build/auto_gen/` — the build fails against a wrapper no shipped file references
  anymore.
- **Root cause**: the raw-launch build chain autogenerates per-entry `aclrtlaunch_*.h`
  wrappers into the build directory at configure time and has no prune pass for entries
  that vanished from the source — the orphan header from the previous configure persists.
- **Fix**: `rm -rf kernel/build` + full rebuild whenever an entry point (debug or
  otherwise) is REMOVED or RENAMED. Adding/changing entries is incremental-safe;
  deleting is not.
- **Detection**: a build error names an `aclrtlaunch_*` wrapper whose source entry no
  longer exists in the tree → stale `auto_gen/`, not a source bug. Check before editing
  any shipped file.
- **Evidence**: gelu 310p (2026-08-12, first instance) — failures_ledger build iter 2:
  debug scaffolding (`KernelGeluDebug` + `run_gelu_debug`) removed before the final
  build; incremental rebuild tripped on the stale `aclrtlaunch_gelu_kernel_debug.h`;
  `rm -rf kernel/build` + full rebuild produced the clean final .so (workspace scratch,
  gitignored).
- **Cross-ref**: CAND-DAV-M200-HARDCODED-EVENT-ID-HANG (the removed debug entry used
  pool-fetched event ids), PB-112 (the stage-dump bisect the debug entry served).
  backend=ascendc.
