# 量化参考的两种失效：共用有损步骤，与容差大于信号

## 适用场景

- 工程形态：低精度/量化算子的精度验收，尤其是反向与梯度类输出。
- API 路径：自建 CPU golden；`eco_open_source_v1` 一类带固定 `atol` 的分档判据。
- 验证过的平台与 CANN 版本：Ascend950DT_9582 / CANN 9.2.0。
- 适用粒度：`platform_wide`。
- 路线优先级：`required_precondition`，在报告任何精度结论之前。
- 明确不适用或未验证场景：非量化算子且输出量级为 O(1) 时，第二种失效通常不触发。

## 失效一：golden 共用实现的有损步骤

若参考在某一步施加了与被测实现相同的有损转换，该步骤的误差在两侧**抵消**，一个坏实现会测成正确。实例：反向 golden 对 `ds` 施加了与 kernel 相同的 HIF8 取整，于是主导误差不可见。

**判据**：逐项检查 golden 的每一步，问「被测实现是否也做了这一步？」。参考应当在该步骤上比实现**更精确**，而不是相同。

## 失效二：容差大于信号

固定绝对容差是按 O(1) 张量标定的。梯度、残差与增量常在 1e-2 以下，此时 `atol` 可以超过整个信号。实例：`eco` bf16 档 `rtol = atol = 2^-6 = 0.015625`，被测梯度量级在 `1e-3` 量级，该档对任何实现都失去分辨力。两次实测与原始分数见下。

### 两次实测，以及一条比「atol 大于信号」更准的判据

判据是 `matched = |a-g| <= atol + rtol*|g|`，再对全部元素取 `matched_ratio`，门为 `>= 0.99`。bf16 档 `atol = rtol = 2^-6 = 0.015625`。

| 实例 | `max|golden|` | `atol / max|golden|` | 该档结果 |
|---|---|---|---|
| A | 约 `9e-4` | 约 `17.4` | 全档失去分辨力；`fp32` 档（`atol=2^-16`）才有信息：dq 0.88%、dk 7.97%、dv 79.3% |
| B | `0.01809` | 约 `0.86` | **仍然无法失败**，见下表 |

实例 B 的三臂原始分数（同一 golden、同一比较器）：

| 臂 | bf16 `2^-6` | fp16 `2^-10` | fp32 `2^-13` |
|---|---|---|---|
| device dq | 1.0000 | 0.7471 | 0.1367 |
| **全零** | **0.9995（通过 `>=0.99`）** | 0.1743 | 0.0220 |
| golden 取反 | 0.9097 | 0.0894 | 0.0132 |

实例 B 里 `atol` 其实**小于** `max|golden|`，全零仍以 0.9995 通过。**所以「atol 大于信号」只是充分条件，不是判据。** 真正的判据是元素分布：`matched_ratio` 是按元素计数的，只要**绝大多数元素**的量级低于 `atol`，无论峰值多大，该门都不可能失败。

**判据**：每次报告分档结果都同时跑**全零对照**，并把原始分数行一起发布。全零若也通过，该档是无法失败的门，结论无效。不要只比较 `atol` 与 `max|golden|`——要比较 `atol` 与元素量级的分布（例如低于 `atol` 的元素占比）。可放大被测量到真实量级（只放大被测张量、不动输入、scale 与判据）后重测。

## 报告要求

分档精度结论必须与**其全零对照分数**一起发布，或明确声明该结论所绑定的量级。只报 `matched_ratio` 而不报对照，无法区分「实现正确」与「判据无法失败」。

## 工件身份

- 比较器：A5Ops `eco_open_source_v1`（`DEFAULT_PROFILE_ID`），bf16 行 `rtol = atol = 2^-6`，门 `matched_ratio >= 0.99`。
- 两次实测均为 QFAG MXFP8 反向的 dq/dk/dv 转储，SoC `Ascend950DT_9582` / CANN 9.2.0，2026-09-22。
- 失效一（golden 共用有损步骤）出现在同一算子的反向 golden 对 `ds` 的 HIF8 取整上；更正后的参考实现见 `agent-team-wiki` 仓 `projects/mxfp8-fa/harness/oracle_fix.cpp`。
