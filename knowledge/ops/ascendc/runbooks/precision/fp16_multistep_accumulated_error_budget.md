# FP16多步计算链误差累积超单步阈值：按步数×ULP预估

## 现象

Mish 类激活算子（FP16 路径在 UB 内全程以 FP16 计算九步：Abs→Muls→Exp→Adds→Log→Maxs→Add→Tanh→Mul）新增大 shape 多核用例后，ST Real 模式报：

```
[FAIL] MERE=3.59e-03, MARE=6.47e-02 (threshold=9.77e-04, mare_limit=9.77e-03)
```

用例值域 [-5,5]、shape [4096,4096]（16M 元素）。同批 [-10,10] 的 FP16 用例失败更重（那是 Adds+Log 的 1+ε 舍入边界，另一张卡）；而本条 [-5,5] 的失配元素 x≈-5 时 exp(-5)≈6.7e-3 完全在 FP16 正常范围内，`1+exp` 舍入并未发生——失败机制不同：逐步舍入的**累积**。逐元素推演（以 x=-5 为例）：golden（FP32）mish(-5)=-0.0335760；FP16 九步链每步结果都舍回 FP16（11 位有效位，每步相对误差可达 ~2^-11≈4.88e-4），九步串联后实测 MERE=3.59e-03。

## 适用场景

- 工程形态：AscendC elementwise 算子 FP16 路径——中间量以 FP16 存储的多步向量 API 链；ST 用 MERE/MARE 对 CPU golden（FP32/更高精度计算）比对。
- API 路径：`AscendC` 标准向量 API（Abs/Muls/Exp/Adds/Log/Maxs/Add/Tanh/Mul）；精度阈值按 CANN 社区标准（FP16 MERE < 2^-10）。
- 验证过的平台与 CANN 版本：Ascend950PR（arch35），CANN 9.1.0（与 frontmatter `platforms` 一致）。
- 适用粒度：platform_wide——FP16 舍入累积是数值机制，与算子种类无关，步数与值域分布随公式变化。
- 路线优先级：safety_fallback——**fallback 声明**："FP16 全程计算 + 值域收窄到精度达标区间"是当前可交付路线；追求更宽值域需升精度计算（改设计），本卡不提供 kernel 修复。
- 明确不适用 / 未验证场景：FP32/BF16 路径（FP32 累积远低于阈值；BF16 另有量化主导的误差形态）；中间量升 FP32 计算的混合精度方案（本算子 BF16 路径采用，FP16 路径未改）；"每步舍入误差独立同分布"只是量级估算模型，不是精确界。

## 根因

多步链的相对误差不是单步阈值可约束的：FP16 每步运算结果舍回 11 位有效数字（含隐含位），单步相对误差上界 ~2^-11；n 步串联且中间量幅度逐级压缩（softplus 输出 << 输入 x）时，误差可按 ~n×2^-11 量级累积。九步链的量级上界 9×2^-11 ≈ 4.4e-3，实测 MERE=3.59e-03 落在该界内、但数倍于单步阈值 2^-10=9.77e-4——即**精度表现符合 FP16 舍入的必然规律，不是 kernel 实现 bug**。判别式：`MERE_observed ≤ n_steps × ULP_rel(dtype)`（量级判断）且失配均匀分布于"输出幅度小"的元素 → 累积误差；`MERE_observed >> n×ULP` 或失配集中于特定 shape/尾块 → 实现缺陷。

## 判别方法

1. 读出失败用例的 MERE/MARE 与值域分布：本例 MERE=3.59e-03、MARE=6.47e-02，失配样本 golden 在 1e-2~1e-1 幅度（正常值域，非近零），排除小值域失稳与 Adds+Log 舍到 0 两个已知机制。
2. 数计算链步数 n（本例 9），按 `n × 2^-11`（FP16）估累积量级：9×4.88e-4 ≈ 4.4e-3 ≥ 3.59e-03 ✓。
3. 抽单个失配元素手算逐步舍入（x=-5：每步中间值舍回 FP16，最终 -0.0335 vs golden -0.0335760，相对偏差 ~2e-3 量级），确认逐步舍入可解释观测值。
4. 对照实验收窄值域到 [-1,1]（softplus(x)≈x 附近、输出幅度与输入同量级）复跑：MERE 回到阈值内 → 证实值域幅度比驱动的累积误差。
5. 只有 1~4 全部吻合仍超标时才怀疑实现缺陷（尾块/tiling/搬运），转入 shape 相关排查。

## 解决配方

本轨迹的处置（FP16 路径保持全程 FP16 计算，测试值域按精度能力划定）：

```cpp
        // --- FP16 多 shape: 大 shape 多核 / 非对齐 ---
        // [4096,4096] = 16M 元素，验证多核切分与 UB 多轮搬运
        // 值域 [-1,1]：FP16 9步计算链在此范围内精度达标（MERE < 2^-10）
        {"L0_025 FP16 大shape多核 [4096,4096]",
         {4096, 4096}, DType::FP16, {-1.0, 1.0}, 1025},
```

若产品要求更宽值域的 FP16 精度，替代路线是中间量升精度（参考同算子 BF16 路径的 Cast 上/下精度模式：BF16→FP32 计算→BF16），FP16 路径同理可 Cast FP16→FP32 计算→FP16，代价是 Cast 开销与 UB 占用翻倍——本轨迹对 FP16 路径未采用（值域收窄已满足验收），属可选升级。

## 设计决策

- FP16 路径不升精度：[-1,1] 值域内 MERE 达标（实测用例 MERE ≤ 3.28e-04 量级、全 20 条 FP16 用例通过），升精度会引入 Cast 开销与双倍 UB 压力，收益仅限宽值域。
- 值域选择写进用例注释并给出量化理由（"9步链在此范围内精度达标"），使后续扩域有据可查。
- 判别顺序上先排除两个已知机制（小值域失稳、Adds+Log 边界）再下"累积误差"结论——三个机制在 FP16 大负值区会叠加，混在一起会误判成实现 bug。
- 当前方案路线档位：safety_fallback（相对"升精度全值域"路线：[-1,1] 内精度达标，宽值域精度不承诺）。

## 预防

- FP16 全程计算的算子在测试设计阶段先算 `n_steps × 2^-11`，把 MERE 预期写成"单步阈值不适用"的显式说明，避免验收阶段误报。
- 用例值域分层设计：精度主验区（幅度同量级）+ 已知边界区（单独阈值或单独用例），不混在一个 MERE 里。

## 验证信号

以下信号来自该算子 FP16 大 shape 用例上板联调会话。

- 失败实测：FP16 [4096,4096] [-5,5] MERE=3.59e-03、MARE=6.47e-02（阈值 9.77e-04/9.77e-03），16M 元素（来源平台：950；证据等级：tool_observed）。
- 量级吻合：9×2^-11≈4.4e-3 ≥ 3.59e-03，且单元素推演（x=-5，逐步舍入）可复现 ~2e-3 量级相对偏差（来源平台：950；证据等级：tool_observed）。
- 处置后：值域收窄 [-1,1] 后同 shape 用例通过；全量 20 条 FP16 用例（含多核/非对齐/极值/空 tensor）在 NPU 通过，MERE_max=3.28e-04 < 2^-10（来源平台：950；证据等级：tool_observed）。

## 失效边界

- `n×ULP` 是量级模型不是严格界：误差相关性与幅度分布会让实际值偏离上界；不能反过来用"低于上界"证明无 bug。
- 值域 [-1,1] 的达标结论依赖"输出幅度与输入同量级"的分布；换公式/换值域需重算。
- 升精度替代路线（FP16→FP32 Cast 计算）未在 FP16 路径实测（BF16 路径实测过同型结构），采用前需单独验证开销与精度。
- 其他平台未验证，推断可迁移（FP16 舍入机制与平台无关，未验证，推断可迁移）。

**未决项**：

- 累积误差的严格界（考虑中间量幅度比的传播分析）未推导，当前只用一阶量级模型。
## 坏实践

- 见"FP16 链 MERE 超单步阈值"就直接放宽容差——把累积误差当成容差问题。
- 把 [-5,5] 失败归因到多核切分/搬运（失配均匀分布、与尾块无关时），浪费一轮 shape 排查。
