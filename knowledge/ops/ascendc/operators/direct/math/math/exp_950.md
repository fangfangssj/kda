## 接口与语义

### 计算语义

Direct 入口先把 `scale/shift` 从 C++ `double` 窄化为 `float`；`base` 的正负判断仍在 `double` 上，只有 `log` 的实参先窄化为 `float`。定义：

```text
l     = (base(double) > 0.0) ? log(float(base)) : 1.0f
s0    = float(scale)
s1    = float(shift)
alpha = float(s0 * l)
beta  = float(s1 * l)
```

部署语义由 Route 决定，而不是对所有输入都等同于单一代数公式：

- `base==1.0` 且 `scale/shift` 有限时，H1 直接选 R-005，对每个输入位写 `1`，Device 不读 `x`。因此即使 `x` 含 NaN/Inf，也不会先形成 `(scale*x+shift)*0`；这是一条明确的 Direct 专门化语义边界。
- H1 未命中且三个原始 `double` 属性都有限时，H2 以 FP32 顺序形成 `alpha/beta`，R-001～R-004 计算 `exp(alpha*x+beta)`。折叠改变了官方通用 DAG 的乘加顺序；它是转换派生语义，不是逐位等价声明。
- 其余输入走 R-006，保持 `Cast→Muls(s0)→Adds(s1)→Muls(l)→Exp→Cast` 的 Device 顺序。

`base<=0`（包括默认 `-1`）在 Direct Host 中统一令 `l=1`，任意正数则取 `log(float(base))`。对**有限属性域**，官方 Host 的意图规则是 `base>1e-6` 或在 FP32 relative-epsilon 判定下等于 `-1` sentinel；其他有限非正 base 与极小正 base 不属于该意图域。但官方实现没有 `isfinite` guard：`base=NaN` 会让 `base<=1e-6` 为 false 而穿过校验，随后得到 `lnBase=NaN` 并选择通用模板；`base=±Inf` 会在 sentinel 表达式中形成 `Inf<=Inf`，使 `isBaseValue=true` 并令 `lnBase=1`，在其余恒等条件也成立时可选择 identity 模板。`scale/shift` 的恒等判定使用同类 relative-epsilon 表达式：NaN 比较为 false，而 `±Inf` 也可能形成 `Inf<=Inf` 并被判为恒等。因此不能把上述有限域意图规则写成官方实现对所有浮点属性的严格合法域。

Direct 的非有限分流与此不同：`base=NaN` 或 `-Inf` 时 `base>0` 为 false，故 `l=1`；`base=+Inf` 时 `l=log(float(+Inf))=+Inf`。随后三个原始 `double` 的有限性检查失败，均保留初始化的 R-006；非有限 `scale/shift` 也同样进入 R-006，不参与 identity/scale/shift 快速 selector。对于有限属性，极大或极小值仍可能在窄化、`log` 或 FP32 乘法后成为 Inf/NaN，并继续由 H2 按精确比较落入某条快速 Route，而不会回退 R-006。

### 输入、输出与属性

| 参数 | shape/layout | dtype | 约束、默认值与语义 |
|---|---|---|---|
| `x` | 任意 rank；Device 按 `[0,numel)` 连续 ND 解释 | `float16/float32/bfloat16` | Meta 只校验 dtype；未校验非空、contiguous 或 stride，正确复用要求物理连续 |
| `base` | 标量属性 | Host `double`，入 Kernel 前为 `float` | 默认 `-1.0`；`>0` 时取自然对数，否则令 `l=1` |
| `scale` | 标量属性 | Host `double`，入 Kernel 前为 `float` | 默认 `1.0`；有限快速路线中与 `l` 折叠 |
| `shift` | 标量属性 | Host `double`，入 Kernel 前为 `float` | 默认 `0.0`；有限快速路线中与 `l` 折叠 |
| `y` | `empty_like(x)`，与 `x` 同 shape | 与 `x` 相同 | R-001～R-004/R-006 逐元素写；R-005 写常量 1 |

### 入口与版本

转换交付件通过 `TORCH_LIBRARY_FRAGMENT(cann_bench)` 声明 schema，Meta 实现 `exp_meta` 负责 dtype 检查和 `empty_like`，`TORCH_LIBRARY_IMPL(cann_bench, PrivateUse1)` 绑定 `exp_npu`。`exp_npu` 取得当前 NPU stream，以 `OpCommand::RunOpApi("ExpDirect", aclCall)` 提交直接 Kernel；它不是 `aclnnExp` 两段式接口。官方固定 Commit 的 README、OpDef、arch35 Tiling、DAG 和 `exp_apt.cpp` 仅证明同名语义、950/950 支持及转换基线；六路 Direct selector、按值 POD、`exp_fill_one_kernel` 和三种 C launcher 均来自转换交付件。

## Host/Launcher 执行流程

### 参数校验与前处理

调用顺序为：schema/Meta 校验三种 dtype→以输入 device 建立 guard→`empty_like(x)` 分配输出→取得当前 NPU stream→读取 `numel()` 与元素字节数→先窄化 `scale/shift`、再按 `base(double)>0` 计算 `l`→按原始 double 有限性和折叠后 FP32 的精确等值选择 Route→调用 `calc_exp_tiling_params`→按 dtype 选择 C launcher。没有 `Contiguous`、ViewCopy、stride 修复、checked arithmetic 或空张量提前返回。

### 参数、Workspace 与生命周期

设 `N=x.numel()`、AIV 核数 `C=max(GetCoreNumAiv(),1)`、元素字节 `d∈{2,4}`、查询的 UB 字节数 `U`（查询为 0 时取 `253952`）：

```text
blockFormer = ceil_align(ceil(N/C), 512)             # 元素
blockDim    = ceil(N / blockFormer)
A           = 256 / d                                # 对齐元素数
B,M         = Route 对应的 bufferNum,maxDtypeBytes
ubFormer    = max(floor((U/(B*M))/A)*A, A)           # 元素，窄化到 int32
```

R-001～R-004 使用 `(B,M)=(4,d)`；R-006 使用 `(6,4)`；R-005 的 launcher 仍以 `(2,d)` 计算 `ubFormer`，但 Fill Kernel 不读取该字段。输入、输出 Tensor 与 lambda 捕获的标量在提交期间存活；所有 launch 使用同一当前 stream。没有 workspace 参数或切片，`workspace_total=0`。

### 启动图与失败传播

```text
cann_bench::exp / PrivateUse1
  -> exp_npu
    -> calc_exp_tiling_params(N,d,route)
    -> launch_exp_kernel_<dtype>(x,y,N,C,blockDim,ubFormer,s0,s1,s2,route,stream)
      -> LaunchExp<T> -> MakeTiling
        -> R-001/002/003/004/006: exp_arch35_kernel<T,route>(x,y,td)
        -> R-005: exp_fill_one_kernel<T>(y,td)
```

每条 Route 都只有一个 AIV_VECTOR Device 节点，launch 的第二个配置参数为 `nullptr`，没有节点间边。R-001～R-004/R-006 的 entry 将 32B POD 重解释为官方 `EleBaseTilingData32B`，构造 ATVOSS scheduler 后 `Init`、`Process`；R-005 不读取 `x`。C launcher 返回 `void`，`aclCall` 无条件返回 0，源码未检查单次 Kernel launch 返回码。未知 `route` 在 `LaunchExp` 的 `default` 分支落到 R-006，而 Host selector 自身只产生 0～5。`N==0` 会令 `blockFormer==0`，随后计算 `blockDim` 时除零，因此空域不是安全无输出终点。

## Route 与参数设计

### 分核与资源计算

ATVOSS 路线在 Device 构造器中使用 POD 的物理核数 `C` 重建：

```text
blockFormer = ceil_align(ceil(N/C),512)
blockNum    = ceil(N/blockFormer)                    # 与 launcher blockDim 相同
blockTail   = N-(blockNum-1)*blockFormer
fullLoops   = ceil(blockFormer/ubFormer)
tailLoops   = ceil(blockTail/ubFormer)
```

第 `b` 个 block 的 GM 基址为 `b*blockFormer` 元素；除最后 block 外处理 `blockFormer`，最后处理 `blockTail`。每核 tile 循环以 `ubFormer` 为满 tile，末循环取对应 `ubTail`。scheduler 的每个物理 slot 容量为 `blockLen=ubFormer*ElemDag::MaxDtypeBytes` 字节，full/tail tile 共享同一组 slot，以 `i&1` 选择 ping/pong ID。

### Route 选择

下表按实现知识的重要性 P0→P5 排列，不代表 Host 判断顺序。排序综合快速域覆盖、Host 短路、融合价值与安全兜底价值。`Host 顺序`字段保留 selector 短路、随后的 dtype 分发以及 launcher fallback：H0 先把 route 初始化为 R-006；H1 检查 base-one；H2 检查三个原始 `double` 属性有限，并在内部按 identity→scale→shift→affine 短路；H3 严格按 FP32→FP16→BF16 选择 C launcher。Meta 已将 H3 的最后 `else` 封闭为 BF16。D1 的 `switch` 按 R-001→R-002→R-003→R-004→R-005 匹配，`default` 到 R-006。

| 重要性 | Route | 分类 | Route 特征 | 精确适用域与实现前提 | Host 顺序、短路与 fallback |
|---:|---|---|---|---|---|
| P0 | R-002 Scale+Exp | active fast | 折叠后仅保留 `Muls→Exp`；FP16 走 native half，FP32/BF16 走 fused 寄存器 helper | H1 未命中；三个原始属性有限；折叠后 `beta==0.0f && alpha!=1.0f`；三 dtype；950 | H2a identity 失败，H2b 命中 route 1。H3 按 FP32→FP16→BF16 分发；D1 命中 `kScaleExp` 分支；无 Device fallback |
| P1 | R-004 Scale+Shift+Exp | active fast | 折叠为 `alpha*x+beta`，在同一寄存器循环执行 `Muls→Adds→Exp` | H1 未命中；三个原始属性有限；折叠后 `alpha!=1.0f && beta!=0.0f`，也包括 FP32 折叠产生 NaN 的精确比较全失败情形；三 dtype；950 | H2a/H2b/H2c 均失败后 H2d 命中 route 3。H3 dtype 顺序不变；D1 命中 `kScaleShiftExp` 分支；无 Device fallback |
| P2 | R-003 Shift+Exp | active fast | 折叠后仅保留 `Adds→Exp`；Host 把 `beta` 重映射到 scalar slot 0 | H1 未命中；三个原始属性有限；折叠后 `alpha==1.0f && beta!=0.0f`；三 dtype；950 | H2a/H2b 失败后 H2c 命中 route 2 并执行 `scaleValue=shiftValue`。H3 dtype 顺序不变；D1 命中 `kShiftExp` 分支；无 Device fallback |
| P3 | R-005 常量 1 Fill | active override | 原始输入读被消去，按 32B 起点分核直接 Fill 输出 | `base(double)==1.0` 且原始 `scale/shift` 有限；不检查 `x` 数值；三 dtype；950 | H1 是 selector 首个判断，命中后跳过 H2 并选 route 4。H3 dtype 顺序不变；D1 命中 `kOutputOne` 后直接 launch Fill；空核 return，无其它 fallback |
| P4 | R-001 纯 Exp | active fast | 删除全部 affine 节点；FP16 native，FP32/BF16 identity DAG | H1 未命中；三个原始属性有限；折叠后 `alpha==1.0f && beta==0.0f`；三 dtype；950 | H2a 首个精确等值分支命中 route 0。H3 dtype 顺序不变；D1 命中 `kIdentityExp` 分支；无 Device fallback |
| P5 | R-006 通用 DAG 转换体 | conditional safety | 保留官方基线的 `Cast→Muls→Adds→Muls→Exp→Cast` 顺序与三个 scalar | H1 未命中且至少一个原始属性非有限；或 launcher 收到未知 route；三 dtype；950 | H0 初值为 route 5，H1/H2 未改写时保留。H3 dtype 顺序不变；D1 的 `default` 也落此，是唯一 launcher fallback；不会接住“有限 double 窄化后非有限” |

```text
if base(double) == 1.0 && finite(scale(double)) && finite(shift(double)): R-005
else if finite(base(double)) && finite(scale(double)) && finite(shift(double)):
  alpha=float(float(scale)*l); beta=float(float(shift)*l); scalar2=1
  if alpha==1 && beta==0: R-001
  else if beta==0: R-002
  else if alpha==1: scalar0=beta; R-003
  else: R-004
else: scalar0=float(scale); scalar1=float(shift); scalar2=l; R-006
# route 选定后的 dtype 分发：
if dtype==float32: launch_exp_kernel_float
else if dtype==float16: launch_exp_kernel_half
else: launch_exp_kernel_bfloat16  # Meta 已封闭为 BF16
```

### POD/ABI

`ExpTilingData` 为按值传入 Device 的 32B、8B 对齐 POD；转换件只用 `static_assert(sizeof(...)==sizeof(EleBaseTilingData32B))` 检查总大小，再重解释为官方 scheduler POD。下列 offset 由两边相同字段顺序、位宽与自然对齐得到，但源码没有逐字段 `offsetof`/`alignof` 断言；迁移时不能把“仅 size 相等”当成任意重排也安全。

## Kernel 实现

### 公共执行流程

P0→P5 只是下列章节的阅读与复用顺序，Route ID 不变；真实 Host selector、dtype 分发和 launcher fallback 见“Route 选择”。P0/R-002、P1/R-004、P2/R-003、P4/R-001 与 P5/R-006 共用 `ElementwiseSchWithScalar<EleBaseTilingData32B,0,Dag>`：entry 绑定 block 的输入/输出 GM 基址，按 DAG 顺序把当前 tile 搬入 UB、执行每个普通节点、搬出有效 tile。`GetTensor/ReleaseTensor` 根据 `VECIN/VECCALC/VECOUT` 映射到 `PIPE_MTE2/PIPE_V/PIPE_MTE3` 的 Mutex lock/unlock；DAG 的 compile-time buffer ID 允许输入、临时结果和输出在生命周期结束后复用 slot。每个满 tile 与尾 tile 都调用同一 `Run(offset,count,i&1)`。P3/R-005 不进入 scheduler。

所有可达 Route 都只使用 GM、AIV 的 UB/寄存器或 `Fill` primitive：没有 L1、L0A/L0B/L0C、Cube、显式 dynamic UB、workspace 或跨核共享区。scheduler Route 的 `workspace_total=0`、`L1_total=0`、`L0_total=0`；R-005 也没有显式 workspace/L1/L0，`Fill` 内部 pattern/事件属于 primitive 边界，不能从当前源码反推出具体 UB 字节数或同步事件。

| Route | GM 数据流 | UB/寄存器 | L1/L0 | workspace | 同步域 |
|---|---|---|---|---|---|
| R-002 active | x→CopyIn→UB→Muls/Exp Reg→UB→CopyOut→y | 4 slot + float/BF16 promoted 或 half native Reg | 0/0 | 0 | MTE2/V/MTE3 Mutex + lane mask |
| R-004 active | x→CopyIn→UB→Muls/Adds/Exp Reg→UB→CopyOut→y | 4 slot + 同上 | 0/0 | 0 | 同上 |
| R-003 active | x→CopyIn→UB→Adds/Exp Reg→UB→CopyOut→y | 4 slot + 同上 | 0/0 | 0 | 同上 |
| R-005 active | 不读 x；Fill→GM y | kernel-scope `TPipe`；无显式 buffer，primitive 内部不可见 | 0/0 | 0 | `TPipe` 跨越 `Fill` 调用；无源码可见跨核同步 |
| R-001 active | x→CopyIn→UB→Exp Reg→UB→CopyOut→y | 4 slot + dtype 分支 Reg | 0/0 | 0 | MTE2/V/MTE3 Mutex + lane mask |
| R-006 conditional | x→CopyIn→UB→Cast/Muls/Adds/Muls/Exp/Cast→UB→CopyOut→y | 6 个 4B-width slot + float Reg | 0/0 | 0 | MTE2/V/MTE3 Mutex + lane mask |

## 算子特定优化

### Trick T-001：属性恒等专门化删除无效 affine 节点

#### 触发与源码依据

- 适用 Route：官方映射对应 P4/R-001；转换交付件进一步派生 P0/R-002、P1/R-004、P2/R-003 与 P3/R-005。
- 触发条件：官方 Host 以 epsilon 判定 `scale≈1,shift≈0,l≈1`；Direct selector 对折叠后的 float `alpha/beta` 使用精确等值，并把 `base==1` 提到最高优先级。
- Golden 来源：[`math/exp/op_host/arch35/exp_tiling_arch35.cpp:95-103`](../../../../../../../cann-ops-raw/ascendc/ops-math/165d41f02a43a62324b434cb6bda7c533b14da3e/math/exp/op_host/arch35/exp_tiling_arch35.cpp#L95-L103)

**官方源码（固定 Commit 连续逐字摘录）**：

```cpp
bool isScale =
    std::fabs(scale - 1.0f) <= std::numeric_limits<float>::epsilon() * std::max(std::fabs(scale), std::fabs(1.0f));
bool isShift =
    std::fabs(shift - 0.0f) <= std::numeric_limits<float>::epsilon() * std::max(std::fabs(shift), std::fabs(0.0f));
if (isScale && isShift && std::abs(lnBase - 1.0f) < std::numeric_limits<float>::epsilon()) {
    attrWork = static_cast<uint64_t>(TPL_SCALE_IS_ONE_SHIFT_IS_ZERO_LNBASE_IS_ONE);
} else {
    attrWork = static_cast<uint64_t>(TPL_SCALE_NOT_ONE_SHIFT_NOT_ZERO_LNBASE_NOT_ONE);
}
```

#### 机制与设计原因

官方源码证明 Exp 在 950 基线中已用 Host specialization 把纯 `Exp` 与通用 affine DAG 分开。转换 Direct launcher 延续该机制，并先折叠 `l`，再把“只 scale”“两者都有”“只 shift”和 `base==1` 拆开：P0/R-002、P1/R-004、P2/R-003 与 P4/R-001 避免通用 DAG 的无效 Cast/Muls/Adds/Muls 节点，P3/R-005 连输入 GM 都不读。原始属性有限 guard 是语义分流条件，但不是“折叠结果有限”的证明；非有限原始属性保留在 P5/R-006，有限 double 的窄化/折叠溢出仍留在快速域。

#### 迁移边界

- 适用：逐元素 affine 后接指数，属性在 Host 已知且可安全判定。
- 前提：950 Direct Invoke；折叠运算按目标 float 精度执行；保留原始运算顺序的非有限 fallback。
- 失效：H1 未命中且任一原始属性非有限时走 R-006；不得把 epsilon 判定与 Direct 精确等值判定混用，也不得假定有限 double 的 FP32 折叠仍有限。

#### 错误做法

无条件把 `(scale*x+shift)*l` 化为 `(scale*l)*x+(shift*l)` 会改变舍入与非有限值传播。R-006 只保护原始属性非有限的路径；`base==1` 常量路和有限 double 窄化/折叠溢出的边界必须按 Direct 实际 Route 语义处理。

### Trick T-002：窄 dtype 升 FP32 的 masked Exp 寄存器核

#### 触发与源码依据

- 适用 Route：P0/R-002、P1/R-004、P2/R-003 的 BF16 融合分支沿用相同 cast/mask 边界；P4/R-001 的 BF16 分支使用 identity 路径；P5/R-006 的窄 dtype 则在 DAG 外层 Cast 节点完成同类 FP32 promotion。
- 触发条件：`T` 非 `float` 的官方 `ExpCustom` 分支；每 tile 的 `count` 可不是 VL 整数倍。
- Golden 来源：[`math/exp/op_kernel/arch35/exp_dag.h:77-90`](../../../../../../../cann-ops-raw/ascendc/ops-math/165d41f02a43a62324b434cb6bda7c533b14da3e/math/exp/op_kernel/arch35/exp_dag.h#L77-L90)

**官方源码（固定 Commit 连续逐字摘录）**：

```cpp
for (uint16_t loopIdx = 0; loopIdx < loopNum; loopIdx++) {
    mask = MicroAPI::UpdateMask<float, MicroAPI::RegTraitNumOne>(count);
    MicroAPI::DataCopy<T, MicroAPI::LoadDist::DIST_UNPACK_B16>(
        vregInput16, (__ubuf__ T*)(srcAddr + loopIdx * vlSize));
    MicroAPI::Cast<float, T, castTrait0>(vregInput, vregInput16, mask);
    MicroAPI::Exp(vregOutput, vregInput, mask);
    MicroAPI::Cast<T, float, castTrait1>(vregOutput16, vregOutput, mask);
    MicroAPI::DataCopy<T, MicroAPI::StoreDist::DIST_PACK_B32>(
        (__ubuf__ T*)(dstAddr + loopIdx * vlSize), vregOutput16, mask);
}
```

#### 机制与设计原因

VL 固定按 `VECTOR_REG_WIDTH/sizeof(float)` 计算，B16 输入以 `DIST_UNPACK_B16` 装载并升为 float，`Exp` 在 float RegTensor 上执行，最后以 `NO_SAT + CAST_RINT + ZEROING` 降回 B16 并 pack。`UpdateMask(count)` 同时约束 cast、Exp 和 store，避免尾寄存器无效 lane 进入结果。官方固定 Commit 使用 `MicroAPI` 命名；转换件闭合的 identity DAG 使用等价 `AscendC::Reg` 调用，而派生融合 helper 使用 `MicroAPI`。R-006 则由 DAG 外层先 Cast 和执行 float affine，再调用 `ExpCustom<float>`。

#### 迁移边界

- 适用：BF16/FP16 需要 float-promoted Exp 且输出仍为窄 dtype 的逐元素路线。
- 前提：arch35 MicroAPI 的 unpack/pack 与 cast trait 可用；tile count 传入所有 masked primitive。
- 失效：转换件的 FP16 P0/R-002、P1/R-004、P2/R-003 与 P4/R-001 有意选择 native half 路径，不能套用 BF16 的升精度描述。

#### 错误做法

省略 `UpdateMask` 或只 mask `Exp` 而不 mask最终 store，会使尾寄存器的无效 lane 被写回；官方代码用同一 mask 闭合整个窄化链。

### Trick T-003：融合 affine 与 Exp，降低通用 DAG 的 UB slot 上界

#### 触发与源码依据

- 适用 Route：P0/R-002、P1/R-004、P2/R-003。
- 触发条件：属性全部有限，折叠后命中 scale-only、shift-only 或 scale+shift；dtype 分支分别选择 native-half 或 float-promoted register helper。
- Golden 来源：[`math/exp/op_kernel/arch35/exp_dag.h:109-123`](../../../../../../../cann-ops-raw/ascendc/ops-math/165d41f02a43a62324b434cb6bda7c533b14da3e/math/exp/op_kernel/arch35/exp_dag.h#L109-L123)

**官方源码（固定 Commit 连续逐字摘录）**：

```cpp
struct ExpScaleNotOneShiftNotZeroLnbaseNotOne {
    using OpCopyIn0 = Bind<Vec::CopyIn<U>, Placeholder::In0<U>>;
    using OpCopyIn0Cast = Bind<Vec::Cast<T, U, CAST_MODE_NONE>, OpCopyIn0>;
    using OpCopyIn0Cast1 = Bind<Vec::Muls<T>, OpCopyIn0Cast, Placeholder::Var<T, PLACEHOLDER_INDEX_0>>;
    using OpCopyIn0Cast2 = Bind<Vec::Adds<T>, OpCopyIn0Cast1, Placeholder::Var<T, PLACEHOLDER_INDEX_1>>;
    using OpCopyIn0Cast3 = Bind<Vec::Muls<T>, OpCopyIn0Cast2, Placeholder::Var<T, PLACEHOLDER_INDEX_2>>;
    using OpExpResult = Bind<ExpCustom<T>, OpCopyIn0Cast3>;
    using OpResultCast = Bind<Vec::Cast<U, T, CAST_MODE_RINT>, OpExpResult>;
    using OpCopyOut = Bind<Vec::CopyOut<U>, Placeholder::Out0<U>, OpResultCast>;
```

#### 机制与设计原因

官方通用 DAG 把 cast、两个乘法、加法、Exp 和回 cast 表达为独立节点；转换件的有限快速路线先在 Host 折叠 `l`，再在一个 `RunAffineExp` 或 `RunNativeAffineExp` register loop 中按 `Muls→Adds→Exp` 执行必要节点。对应 launcher 把 UB 预算从通用路的 `6*4*ubFormer` 改为 `4*d*ubFormer`，同时不再为已删除节点物化整 tile 中间值。该结论是转换交付件相对官方基线的派生实现事实，不代表官方仓原生包含这些融合 DAG。

#### 迁移边界

- 适用：标量 affine 链可在 Host 安全折叠，且 Device helper 能在同一寄存器域完成剩余运算。
- 前提：保持 `Muls→Adds→Exp` 次序；BF16 用 float promotion，FP16 native 路线需单独做精度审计；`BufferNum/MaxDtypeBytes` 与实际 DAG 一致。
- 失效：H1 未命中且原始属性非有限时走 R-006；需要保留第三次乘法、逐步舍入或其它中间可观察语义时不能把快速 Route 外推为等价模板。

#### 错误做法

仅在 Host 把 `bufferNum` 改小、却不同时删除 DAG 中间节点，会使 scheduler 的 compile-time buffer IDs 与 UB 上界不一致；必须让 Route DAG 与 Tiling 预算成对变化。

- `N==0` 时 `calc_exp_tiling_params` 的 `blockDim` 计算除零；没有官方 Host 的 empty-tensor 失败或安全零 launch 语义。
- `ceil`/`align_up` 通过 `N+C-1`、`value+alignment-1` 等有符号 `int64` 算术实现，源码没有溢出检查；复用前提是 `N>0` 且所有中间量仍在 `int64` 范围内。
- `base<=0` 都被解释成自然指数，任意 `base>0` 都取 log；只在有限属性域内，官方 Host 的意图规则才可概括为 `base>1e-6` 或 epsilon-equivalent `-1` sentinel。官方无 `isfinite`，NaN 可穿过 base 校验，`±Inf` 及非有限 scale/shift 还会触发 relative-epsilon 的特殊比较结果。
- R-005 只由属性触发且不读 `x`；当 `x` 含 NaN/Inf 时，它仍写 1，不能用未专门化表达式的 IEEE 中间值推翻这条部署语义。
- `base/scale/shift` 从 schema 的 double 进入 Host，`scale/shift` 和 `log` 实参再窄化为 float；有限 double 可在窄化、`log` 或折叠后成为 Inf/NaN，属性等值 selector 仍按该 FP32 结果比较，不会回退 R-006。
- R-001～R-004 把 `l` 折入 `alpha/beta`，运算顺序与 R-006 不同；即使所有值有限，也可能存在逐步舍入差异。
- `GetCoreCount` 在解引用平台对象前未判空；`GetUbSize` 才有 253952B fallback。`coreNum` 与 `ubFormer` 的 int32 窄化无范围检查。
- `ubFormer=max(...,alignElements)` 在异常小 UB 查询值下可能使预算反超 U；源码没有资源 fallback。正常 950 查询值下公式闭合。
- R-005 的 `Fill` 内部 UB pattern 与同步实现不在转换源码中；只把 primitive 当作明确边界，不伪造其子区。
- launcher 返回 `void` 且 `aclCall` 固定返回 0，单 Kernel launch 的即时错误传播在固定源码中不可见。
- 本次知识提取未执行编译、真机、数值或性能测试；不据此声明收益比例。
