# Gcd 950 Direct Invoke 算子知识

## 算子速览

| 项目 | 内容 |
|---|---|
| 实际入口 | `cann_bench::gcd(Tensor x1, Tensor x2)`；`PrivateUse1` 实现 `GcdNpu`；按 dtype 与 Route 调用 `launch_gcd_{equal,repeat,axis,scalar,generic}_{int16,int32,int64}` |
| 计算语义 | 对右对齐广播后的每个输出坐标计算两个有符号整数幅值的最大公约数；可表示时结果非负，`gcd(0,0)=0` |
| 输入输出 | `x1/x2` 为同 device、同 dtype、连续 ND Tensor，rank 1～8，dtype 为 `int16/int32/int64`；`y` 为广播 shape、同 dtype |
| 执行类型 | R-001～R-004：单 AIV_VECTOR wrapper 内以 `asc_vf_call` 启动 SIMT VF；R-005：单 AIV_VECTOR Kernel 内的标量 GM 循环；无 Cube/AIC 或 MIX_CV 节点 |
| Kernel 路线 | 五条 Route 均为生产 selector 可达的 `active` 路线。重要性顺序：P0 R-001 等 shape；P1 R-002 连续后缀广播；P2 R-003 单轴值广播；P3 R-004 标量广播；P4 R-005 通用广播安全 fallback。Route ID 保持 Host/launcher 映射 |
| 核心资源 | 部署路线均直接访问 GM；优化路线只用 SIMT 线程寄存器，通用路线用 AIV 标量与 `GlobalTensor::GetValue/SetValue`；AIV UB、TQue/TBuf、dynamic UB、workspace 均为 0 |
| 来源闭包 | `direct_implementation_closed`：转换交付件已闭合 `cann_bench::gcd`→`GcdNpu`→Route/config producer→dtype/Route launcher→entry→全部可达 body；官方固定 Commit 提供 Gcd 语义、950 接线、广播 DAG 与 Stein body，Direct ABI、GM 映射和通用 fallback 明确属于转换实现 |
| 复核范围 | 已完成源码闭包检查；本次知识提取未执行编译、真机、数值或性能测试。 |

## 接口与语义

### 计算语义

把 `x1`、`x2` 的 shape 右对齐到输出 rank `r`，第 `d` 维输出长度为 `o[d]=max(x1[d],x2[d])`；每个输入维必须满足长度相等或一方为 1。对输出坐标 `q`，广播维的输入坐标取 0，其余取 `q[d]`：

```text
a = unsigned_magnitude(x1[index1(q)])
b = unsigned_magnitude(x2[index2(q)])
y[q] = cast_to_input_dtype(gcd(a,b))
```

R-001～R-004 使用二进制 GCD（Stein）：保存 `a|b` 的公共 2 因子，分别去掉尾零，循环对较大奇数做减法。R-005 使用欧几里得取模循环。两者都先以位运算 `(bits ^ signMask) - signMask` 求无符号幅值。若最小有符号值的正幅值不可由同 dtype 表示，最终 cast 保留该 dtype 的位模式；不要把此边界外推为一个可表示的正数。

### 输入、输出与属性

| 参数 | shape/layout | dtype | 约束、默认值与语义 |
|---|---|---|---|
| `x1` | 契约为 rank 1～8、连续 ND | `int16/int32/int64` | 必须与 `x2` 同 device、同 dtype；每维长度必须为正；转换契约要求广播输出元素数 `L<=2^27` |
| `x2` | 契约为 rank 1～8、连续 ND | 同 `x1` | 与 `x1` 右对齐可广播；专用 Route 可利用交换律把 full-shaped 输入放到 `firstPtr` |
| `y` | 右对齐广播 shape，连续 ND | 同 `x1` | 由 `torch::empty(outputShape,x1.options())` 分配；每个元素写一次 |

### 入口与版本

转换交付件通过 `TORCH_LIBRARY_FRAGMENT(cann_bench)` 声明 `gcd`，Meta 路径由 `GcdMeta` 产生输出元数据，`PrivateUse1` 绑定 `GcdNpu`。`GcdNpu` 直接取得当前 NPU stream 并调用 Direct launcher，不是 ACLNN 两段式 workspace/executor 入口。

官方固定 Commit 的 `gcd_apt.cpp::gcd<schMode>` 依赖注册生成的 `DTYPE_X1`、`BroadcastSch<schMode,OpDag>` 和 device tiling 指针。转换实现保留官方 `gcd_dag.h` 的有符号幅值与 Stein 计算关系，但以按值 config、Host shape selector、直接 GM SIMT 映射替换公共广播 scheduler；R-005 的 stride 坐标重建和欧几里得标量 body 是 Direct 闭包所加的兜底，不能归因于官方 entry。

## Host/Launcher 执行流程

### 参数校验与前处理

调用顺序为：安装 `x1.device()` guard→检查两输入 device 相同、均连续、dtype 相同→`BuildBroadcastInfo` 检查输出 rank 1～8、每维正数、右对齐可广播及 `int64` 元素数乘法不溢出→分配 `y`→取得当前 stream→按完整决策树选择 Route→生成对应 config→按 `int16/int32/int64` 分发。`DtypeBytes` 同时拒绝其它 dtype。实现不会隐式执行 `Contiguous` 或 `ViewCopy`。

转换契约的 `L<=2^27` 使 R-001～R-004 的 `uint32_t` 线性地址与映射状态有界；但当前 Plugin 只检查 `int64` 乘法，不显式执行这一上界 guard。若把实现复用于更宽输入域，必须在专用 selector 前增加 `L<=UINT32_MAX`，并分别约束 `blockStart/count/rowLength/axisLength/innerLength` 可窄化；不满足时恢复原始 `x1/x2` 指针并进入 R-005，而不能在 Device 中截断。

`BuildBroadcastInfo` 从末维向前产生连续 stride；当输入维为 1 而输出维不为 1 时，把该维 stride 写为 0，缺失的左侧维也保持 0。专用广播 Route 只在恰有一方 full-shaped 时进入；若 full-shaped 输入原为 `x2`，Host 交换 `firstPtr/secondPtr`，利用 GCD 交换律统一 Device 映射。

### 参数、Workspace 与生命周期

设输出元素数 `L`、dtype 字节 `d`、AIV 核数 `C=max(GetCoreNumAiv(),1)`：

```text
flat:
  B0 = min(C, max(1, ceil(L/4096)))
  A  = max(1, 512/d)                         # 元素
  blockLength = align_up(ceil(L/B0), A)      # 元素/核
  blockNum = ceil(L/blockLength)

rows/axis:
  B0 = min(C, max(1,rowCount))
  rowsPerBlock = ceil(rowCount/B0)           # 行/核
  blockNum = ceil(rowCount/rowsPerBlock)

generic:
  blockNum = min(C,max(1,ceil(L/4096)))
  blockLength = ceil(L/blockNum)
  blockNum = ceil(L/blockLength)
```

`GetTileBytes` 还按 `align_down((UB_hw-32KiB)/6,512)` 生成 `tileElements`，平台查询失败或空间过小时取 24 KiB；但最终五条可达 body 都不读取它，不能据此声称部署路线分配了六槽 UB。`x1/x2/y` 由 Tensor 拥有，config 被 lambda 按值捕获并在同一 stream 提交。独立 workspace、跨节点 GM slice 和 cleanup 均为 0。

### 启动图与失败传播

```text
cann_bench::gcd / PrivateUse1
  -> GcdNpu -> BuildBroadcastInfo -> Route/config producer
  -> OpCommand::RunOpApi("GcdDirect", aclCall)
    -> one launch_gcd_<route>_<dtype>(..., cfg, stream)
      -> one gcd_<route>_<dtype><<<cfg.blockNum,nullptr,stream>>>
        -> R-001..R-004: Run* -> asc_vf_call<SIMT body> -> SyncAll
        -> R-005: RunGeneric -> scalar GM loop
```

每次调用只启动一个 Kernel，无 Kernel 间 edge 或 workspace lifetime。所有 launcher 返回 `void`，`aclCall` 无条件返回 0；源码没有逐 launch 状态检查，参数错误在 launch 前由 `TORCH_CHECK` 阻断，而提交后的 Device 错误依赖外层运行时传播。

## Route 与参数设计

### 分核与资源计算

R-001/R-004 按对齐后的连续元素段分核；R-002 按 `rowLength` 的完整后缀行分核；R-003 把 `(outer,axis)` 折成 `rowCount=outerCount*axisLength` 后按行分核；R-005 按不对齐的连续线性元素段分核。每个 Device body 都以 `GetBlockIdx()` 计算起点并在起点越界时返回，最后一核以 `min` 截断。优化路线随后把该核的元素域交给 SIMT 线程做 `threadIdx.x + k*blockDim.x` 的 grid-stride 循环。

### Route 特征与重要性

P0→P4 只规定本卡的阅读与复用顺序，不参与运行时分派。Route ID 保持不变，真实 Host 判定次序以后续表中的 `Host 顺序`、短路和 fallback 为准。分类口径如下：五条 Route 都有生产 Host producer、launcher 和 Device body，因而均为 `active`；其中 R-005 是 active safety fallback，而不是只在源码中存在的备用 entry。本实现没有 Route 级 `conditional` 路线；INT64 的 32 位 Stein 快路属于 active Route 内的 Device 条件分支。

| 重要性 | Route | 分类 | Route 特征 | 适用域 | 实现前提 |
|---|---|---|---|---|---|
| P0 | R-001 等 shape | active fast | 两输入按相同线性下标直读 GM，以 dtype 特化 SIMT Stein body 处理连续段 | 两输入都是输出 shape | 转换契约保证分核起点与映射参数可被优化 body 的 `uint32_t` 字段表示 |
| P1 | R-002 连续后缀广播 | active fast | full 输入连续读，small 后缀以 `pos % rowLength` 周期复用 | 恰一输入 full，small 为完整连续后缀且形成多行 | Host 必须先把 full 指针归一化到 `firstPtr`；行长与行数须满足专用映射谓词 |
| P2 | R-003 单轴值广播 | active fast | 把 `(outer,axis)` 折成行，以 inner/axis 双状态递推 small 下标 | 恰一输入 full，small 仅一个非 1 轴，且该轴后仍有连续元素 | `axisLength/innerLength/rowCount` 与分核参数须可被优化 body 的 `uint32_t` 映射状态表示 |
| P3 | R-004 标量广播 | active fast | 每个 SIMT 线程只读一次 scalar，然后处理它的连续 GM 元素 | 恰一输入 full，small 只有一个元素 | 等 shape 的单元素输入先被 R-001 短路；full 指针必须在前 |
| P4 | R-005 通用广播 | active safety | 以完整 dims/strides 从线性输出坐标重建两输入偏移，AIV 顺序执行欧几里得 body | 任意其他合法右对齐广播；扩域实现也应承接专用路线的窄化 guard | 保留原始 `x1/x2` 指针与 `int64` stride；没有更下层 Device fallback |

### Route 选择

| 重要性 | Route | Host 顺序 | Key/模板 | 精确选择条件 | 短路/fallback |
|---|---|---|---|---|---|
| P0 | R-001 等 shape | H2：广播 selector 第 1 个谓词 | `GcdRoute::EQUAL` | `x1Full && x2Full` | 命中即跳过单 full 分支；未命中才检查 H3 |
| P1 | R-002 连续后缀广播 | H4：H3 scalar 未命中后的第 1 个专用映射谓词 | `GcdRoute::REPEAT_SUFFIX` | 恰有一方 full；small 非标量；首个非 1 维起直到末维均等于输出；`rowLength==small.numel()>1`、`L%rowLength==0`、`rowCount=L/rowLength>1` | 命中即跳过 R-003；谓词失败进入 H5 |
| P2 | R-003 单轴值广播 | H5：R-002 谓词失败后 | `GcdRoute::AXIS_SCALAR` | small 恰有一个非 1 维且等于输出该维；其后维乘积 `innerLength>1` | 命中选定本 Route；失败保留 R-005 默认值 |
| P3 | R-004 标量广播 | H3：恰一方 full 时先于 H4/H5 | `GcdRoute::SCALAR` | `small.numel()==1` | 命中即短路 R-002/R-003；未命中才进入 H4 |
| P4 | R-005 通用广播 | H1 初始化为默认 Route；H6 在专用选择后收口 | `GcdRoute::GENERIC` | 两方都非 full，或 H2～H5 均未命中 | H6 恢复原始指针并生成 `int64` dims/strides；无进一步 fallback |

H0 先按 device→contiguous→同 dtype校验，再按从末维到首维的顺序生成连续/零 stride；非法广播直接失败。H0 后的 `DtypeBytes` 以 `int16→int32→int64→失败` 校验元素宽度；H7 再以 `int16→int32→int64` 选择 launcher。P0～P3 的 Host 没有 `uint32_t` 索引可表示性 guard，也不会因索引超界转入 P4；P4 始终使用原始 `int64` stride 重建偏移。

```text
if x1Full && x2Full: EQUAL
else if x1Full != x2Full:
  normalize pointer order so firstPtr is full-shaped
  if small.numel == 1: SCALAR
  else if IsRepeatSuffix(...): REPEAT_SUFFIX
  else if IsAxisScalar(...): AXIS_SCALAR
  else: GENERIC
else: GENERIC
```

### 模板/实现执行矩阵

| 重要性 | Route | key/selector | dtype/shape/platform 完整命中条件 | 执行拓扑与 Kernel 节点 | 实际模板/body | 内存与同步特征 | tail/fallback |
|---|---|---|---|---|---|---|---|
| P0 | R-001 等 shape | `EQUAL` | 两输入 shape 均等于输出；950；三种有符号 dtype | 单 AIV wrapper→SIMT VF | `RunEqual<T>`→`GcdGlobalLaunch<T>`→`GcdGlobal`/`GcdGlobalInt64` | 直接 GM；int16/int32/int64 为 2048/1024/512 线程；末尾 `SyncAll` | 最后一核缩短 `currentLength`；无 fallback |
| P1 | R-002 连续后缀 | `REPEAT_SUFFIX` | 单 full 输入 + 完整连续后缀 small | 单 AIV wrapper→SIMT VF | `RunRepeatSuffix<T>`→`GcdMappedGlobalLaunch<T>`→`GcdMappedGlobal{Int64}<...,REPEAT_SUFFIX>` | 直接 GM；1024/1024/512 线程；模递推；`SyncAll` | 行尾自然截断；谓词失败去 R-003 |
| P2 | R-003 单轴值 | `AXIS_SCALAR` | 单 full 输入 + small 仅一个非 1 轴；`innerLength>1` | 单 AIV wrapper→SIMT VF | `RunAxisScalar<T>`→mapped body `<AXIS_SCALAR>` | 直接 GM；1024/1024/512 线程；双状态 carry 递推；`SyncAll` | 最后一行组截断；谓词失败去 R-005 |
| P3 | R-004 标量 | `SCALAR` | 单 full 输入 + small 只有 1 元素 | 单 AIV wrapper→SIMT VF | `RunScalar<T>`→mapped body `<SCALAR>` | 每线程一次读 scalar；1024/1024/512 线程；`SyncAll` | 连续段尾；等 shape `[1]` 已被 R-001 捕获 |
| P4 | R-005 通用广播 | `GENERIC` | 其它合法广播 | 单 AIV Kernel | `RunGeneric<T>`→`GcdScalarDevice<T>` | 无 SIMT/UB；每个 AIV 顺序处理线性段，GM 标量访问 | 坐标循环覆盖 rank 1～8；无进一步 fallback |

### 隐式性能 Guard

| Guard | Host/Tiling 条件 | Device/资源原因 | 影响 Route | 不满足时去向 | 源码符号 |
|---|---|---|---|---|---|
| full-shaped 优先级 | `x1Full && x2Full` 先于 scalar | 等 shape 可直接连续寻址，并避免广播映射 | P0 R-001 | 单 full 分支 |
| 512B 分核对齐 | `blockLength=align_up(ceil(L/B0),512/d)` | 让 R-001/R-004 核起点按 512B 对齐 | P0 R-001 / P3 R-004 | N/A |
| 最小核粒度 | `ceil(L/4096)` | 小张量避免使用超过元素段需要的 AIV 核 | P0 R-001 / P4 R-005 | 至少 1 核 |
| 单 full 限制 | `x1Full != x2Full` | R-002～R-004 的 Device body固定 `src1[pos]`，只映射 `src2` | P1 R-002 / P2 R-003 / P3 R-004 | P4 R-005 |
| SIMT 线程数 | equal 为 2048/1024/512，mapped 为 1024/1024/512 | dtype 模板固定并行度；INT64 使用更小 launch bound | P0 R-001～P3 R-004 | 编译期选择，无运行时 fallback |
| 32 位索引窄化 | 优化 body 把 `blockStart/base/count/map*` 转为 `uint32_t` | SIMT 地址和循环状态均为 32 位 | P0 R-001～P3 R-004 | 转换契约以 `L<=2^27` 保证；源码无动态 fallback，扩域时须新增 Host guard 并转 R-005 |
| rank 上限 | `1<=rank<=8` | `GcdGenericConfig` 固定三个长度为 8 的数组 | 全部，尤其 P4 R-005 | Host `TORCH_CHECK` 失败 |
| UB 查询非语义 guard | `GetTileBytes()` 查询 UB 并产生 `tileElements` | 字段在所有可达 body 中显式 `(void)` 或未传给 generic | 全部 | 查询失败用 24KiB；不改变 Route |

### POD/ABI

这些结构是 Host C++ 直接调用 ABI，不是官方 `BroadcastSch` 的 tiling buffer。按常规 8B 对齐，数组元素连续；`blockNum` 只由 Host launcher 消费，`tileElements` 在部署 Device body inactive。

| 结构 | 字段 | 类型/位宽 | ABI 布局 | 单位 | Host/launcher producer | Device consumer | 边界 |
|---|---|---|---|---|---|---|---|
| `GcdFlatConfig` | `totalLength` | int64/64 | sizeof 32, align 8, off 0 | 元素 | `calc_gcd_flat_config:L` | `RunEqual/RunScalar` 结束边界 | 必须可窄化到优化 body 的 uint32 参数 |
| 同上 | `blockLength` | int64/64 | off 8 | 元素/核 | 对齐公式 | `GetBlockIdx()*blockLength` | 512B 对齐 |
| 同上 | `tileElements` | int64/64 | off 16 | 元素 | `GetTileBytes()/d` | inactive：body `(void)` | 不代表实际 UB 分配 |
| 同上 | `blockNum` | int64/64 | off 24 | AIV 核 | `ceil(L/blockLength)` | `launch_gcd_equal/scalar_*` | Device 不接收 |
| `GcdRowsConfig` | `rowCount` | int64/64 | sizeof 40, align 8, off 0 | 后缀行 | `L/rowLength` | `RunRepeatSuffix` | `>1` |
| 同上 | `rowLength` | int64/64 | off 8 | 元素/行 | `IsRepeatSuffix` 末维乘积 | base/count/map0 | 等于 small.numel |
| 同上 | `rowsPerBlock` | int64/64 | off 16 | 行/核 | `ceil(rowCount/B0)` | rowBegin/rowEnd | 正数 |
| 同上 | `tileElements` | int64/64 | off 24 | 元素 | `GetTileBytes()/d` | inactive | 同上 |
| 同上 | `blockNum` | int64/64 | off 32 | AIV 核 | `ceil(rowCount/rowsPerBlock)` | repeat launcher | Device 不接收 |
| `GcdAxisConfig` | `outerCount` | int64/64 | sizeof 56, align 8, off 0 | 外层组 | `IsAxisScalar` 前轴乘积 | inactive：launcher 不传 | 仅用于 producer 推导 rowCount |

## Kernel 实现

### 公共执行流程

三个 dtype 由宏生成相同的五个 entry/launcher 家族。entry 均为 `__global__ __aicore__ __vector__`。R-001～R-004 的 AIV wrapper 只负责按核截断工作域、选择编译期 SIMT 模板并等待 `SyncAll`；实际元素计算直接在 SIMT VF 中从 GM 读、在寄存器完成幅值与 GCD、再写 GM。R-005 不调用 SIMT，而在 AIV 上以线性循环和 rank-stride 坐标重建完成通用广播。源码中 `CopyIn/CopyOut/CopyInBroadcast*/ProcessLocalTile/GcdLocal` 等 UB helper 没有被任何部署 `Run*` 调用，属于不可达遗留，不进入 Route 资源账。

下列章节按 P0→P4 的重要性顺序展开，不改变 R-ID；真实 Host 选择次序仍为 R-001→R-004→R-002→R-003→R-005。每节的伪码都对应一个 active Route，不包含前述 dormant UB helper。

```text
base = blockIdx * blockLength
if base >= totalLength: return
count = min(blockLength,totalLength-base)
SIMT for i=threadIdx; i<count; i+=threads:
  pos=base+i; a=abs_bits(x1[pos]); b=abs_bits(x2[pos])
  if dtype is int16/int32:
    if a==0 or b==0 or a==b: write shortcut result; continue
    y[pos]=cast(stein_unsigned(a,b)); continue
  if a==0 or b==0: write shortcut result; continue
  if (a|b)<=UINT32_MAX: y[pos]=cast(stein_u32(a,b))
  else: y[pos]=cast(stein_u64(a,b))
SyncAll()
```

## 算子特定优化

### Trick T-001：无除法的有符号二进制 GCD SIMT body

#### 触发与源码依据

- 适用 Route：P0 R-001、P1 R-002、P2 R-003、P3 R-004；INT16/INT32 走对应 unsigned 模板，INT64 走双 32 位 word 的 `ffs` 版本。
- 触发条件：专用广播谓词之一命中，并由 dtype router 选择 SIMT 模板。
- 官方源码锚点：[`math/gcd/op_kernel/arch35/gcd_dag.h:120-152`](../../../../../../../cann-ops-raw/ascendc/ops-math/165d41f02a43a62324b434cb6bda7c533b14da3e/math/gcd/op_kernel/arch35/gcd_dag.h#L120-L152)

**官方源码（固定 Commit 连续逐字摘录）**：

```cpp
        T2 a = static_cast<T2>(src1[index]);
        T2 b = static_cast<T2>(src2[index]);
        if constexpr (!IsSameType<T1, T2>::value) {
            T2 mask;
            mask = static_cast<T2>(src1[index] >> attr);
            a = (a ^ mask) - mask;

            mask = static_cast<T2>(src2[index] >> attr);
            b = (b ^ mask) - mask;
        }

        if (a == 0) {
            dst[index] = b;
            continue;
        }
        if (b == 0) {
            dst[index] = a;
            continue;
        }

        uint8_t shift = __builtin_ffs(a | b) - 1;
        a >>= __builtin_ffs(a) - 1;
        b >>= __builtin_ffs(b) - 1;
        while (b != 0) {
            b >>= __builtin_ffs(b) - 1;
            if (a > b) {
                T2 temp = a;
                a = b;
                b = temp;
            }
            b = b - a;
        }
        dst[index] = a << shift;
```

#### 机制与设计原因

`attr` 由 dtype 模板固定为符号位位置（INT16 为 15，INT32 为 31），算术右移得到全 0/全 1 mask，再用二补码位式求无符号幅值；这覆盖负数和最小有符号值的位模式。`ffs(a|b)-1` 保存公共 2 因子，循环只做尾零剥离、比较、交换与减法，避免通用 Route 每步的 `%`。转换实现将官方 UB 指针换成 direct-GM `pos` 访问，并为 mapped Route 加广播索引递推；幅值与 Stein 核心顺序保持相同。INT64 在两个幅值均不超过 `0xffffffff` 时用等价 `uint32` Stein 路径，否则继续完整 64 位版本。

#### 迁移边界

- 适用：有符号整数逐元素 GCD，输入地址可由等 shape、后缀、单轴或 scalar 映射直接生成。
- 前提：950/Ascend 950 SIMT VF 可用；dtype router 必须把符号位 `attr`、unsigned 中间类型和 launch bound 配对；所有优化地址字段须可表示为 uint32。
- 失效：其它合法广播必须使用 R-005 的完整 stride 坐标重建；不能把 direct-GM 适配误写成官方 `BroadcastSch` 原样实现。
- 复核边界：本次知识提取未执行编译、真机、数值或性能测试。

## 限制与失败边界

- Direct 接口只接受 `int16/int32/int64`、连续、同 device、同 dtype、rank 1～8 且每维为正的可广播输入；官方源码还声明 `int8/uint8`，但转换入口没有暴露这两种 dtype。
- 转换 Host 实际只检查 `max(x1.dim(),x2.dim())` 为 1～8；因此当另一输入 rank 合法时，单个 rank-0 Tensor 可能穿过实现校验，但它超出固定的 rank 1～8 输入契约，不能据此扩大正式接口。
- 转换契约以 `L<=2^27` 覆盖 R-001～R-004 的 `uint32_t` 地址前提，但 Host 仅检查输出元素数的 `int64` 乘法溢出，没有显式检查该契约上界，也没有超界时的动态回退。扩大输入域时必须增加可表示性 guard，并让失败项进入 R-005 的 int64 stride 路线或另一条 64 位索引实现。
- `calc_gcd_axis_config` 的 `outerCount*axisLength` 没有单独的乘法溢出检查；当前 rowCount 来自已检查的输出维乘积关系，但迁移公式时不可脱离这一前提。
- 所有 launcher 返回 `void`，`aclCall` 固定返回 0；源码没有细粒度 launch 失败传播或 cleanup。
- `GetTileBytes/tileElements` 和 UB helper 存在于转换源码但在最终可达 body 中 inactive；不得据此构造虚假的 Queue、双缓冲或 NDDMA 路线。
- 官方固定 Commit 的 950 DAG 在 UB 上执行 `CopyInBrc→GcdNode→CopyOut`；本文部署实现只保留算法转换关系，不声称 Direct GM Route 与官方 scheduler/ABI 字节相同。
- 已完成静态源码闭包；本次知识提取未执行编译、真机、数值或性能测试。
