# NMS 950 Direct Invoke 算子知识

## 算子速览

| 项目 | 内容 |
|---|---|
| 实际入口 | `cann_bench::nms` → `nms_npu` → `launch_nms_rank_chunk_float` / `launch_nms_scatter_ranks_float` / `launch_nms_reorder_float` / `launch_nms_mask_float` / `launch_nms_greedy_float`；Direct Invoke |
| 计算语义 | 对独立 `boxes[N,4]` 与 `scores[N]` 按 `scores` 降序做 greedy NMS，使用 `intersection/(area_i+area_j-intersection+1e-6)`，返回保留框的原始 INT64 索引 |
| 输入输出 | `boxes` 为 contiguous FP32 `[N,4]`、坐标顺序 `[x1,y1,x2,y2]`；`scores` 为 contiguous FP32 `[N]`；输出为动态长度 INT64 `[K]` |
| 执行类型 | rank-chunk 为 AIV 外壳内的 SIMT+UB；rank-scatter、reorder、pairwise-mask 为 SIMT；greedy 为 AIV Vector/MicroAPI；所有可达 entry 均为 `KERNEL_TYPE_AIV_ONLY`，无 Cube/AIC/MIX_CV |
| Kernel 路线 | P0 / R-001（active）：`ceil(N/2048)` 个 rank-chunk → scatter → reorder/area → 20 核 pairwise byte mask → 单核 greedy；没有 conditional Route。源码另保留未接生产 Host 的排序 wrapper、入口与 body，均为 dormant |
| 核心资源 | GM Tensor workspace；rank-chunk 单个 TBuf=`align_up(chunkLength*4,32)` B；greedy 的 depth-1 row Queue 与 alive TBuf 各 `align_up(N,256)` B；其余 SIMT 节点无 dynamic UB |
| 来源闭包 | `direct_implementation_closed`：转换交付件闭合 Torch schema、Host workspace/launcher、唯一 active Route 的全部 entry/body、逐阶段同步、动态输出与 dormant 排除证据；官方固定源码仅支撑相关 NMS 接口边界与“并行关系矩阵→有序传播”结构，不把派生 Direct 符号表述为官方实现 |
| 证据边界 | 本卡做静态源码闭包与生产可达性归类；它不把源码存在、构建接线或固定来源外推为运行正确性、输入域完备性或性能结论。 |

## 接口与语义

### 计算语义

令输入框 `b_i=[x1_i,y1_i,x2_i,y2_i]`，面积 `a_i=(x2_i-x1_i)(y2_i-y1_i)`。生产 Host 不检查坐标合法性；R-001 的可复用前提要求调用侧已保证 `x1<=x2`、`y1<=y2`。对无 NaN、两两不等的 `scores`，严格大于计数恰好产生降序排列 `p_0...p_{N-1}`，实现随后生成：

```text
inter(i,j) = max(0,min(x2_i,x2_j)-max(x1_i,x1_j))
           * max(0,min(y2_i,y2_j)-max(y1_i,y1_j))
iou(i,j)   = inter(i,j) / (a_i + a_j - inter(i,j) + 1e-6)
suppress(i,j) = !(iou(i,j) <= iou_threshold)
```

随后按 `i=0..N-1` 顺序扫描；若位置 `i` 仍 alive，则输出原始索引 `p_i`，并令所有 `suppress(i,j)==1` 的 `j` 失活。任一坐标为 NaN 时该 pair 直接抑制；非 NaN 坐标计算出的 IoU 为 NaN 时，`iou<=threshold` 仍为 false，因而也抑制。该语义不是官方 `NMSWithMask` 的原样调用：官方 950 接口接收 `[N,5] [y1,x1,y2,x2,score]`、保持输入顺序并输出 full-N boxes/INT32 indices/UINT8 mask；官方比较为 `intersection > threshold*union`，没有 `+1e-6`。

### 输入、输出与属性

| 参数 | shape/layout | dtype | 约束、默认值与语义 |
|---|---|---|---|
| `boxes` | `[N,4]`，contiguous ND | FP32 | `[x1,y1,x2,y2]`；与 `scores` 同设备；转换契约要求合法框 |
| `scores` | `[N]`，contiguous ND | FP32 | 长度等于 `N`；R-001 要求无 NaN 且两两不等（`+0/-0` 也属于并列）；`+/-Inf` 只有在仍保持唯一全序时才不破坏 rank permutation |
| `iou_threshold` | Host 标量 | double 输入，launch 前窄化为 FP32 | Host 只按 double 检查开区间 `(0,1)`；窄化后可能舍入到 FP32 的 `0` 或 `1`，Device 不复查；不同于官方 950 `NMSWithMask` 的闭区间 `[0,1]` |
| `output` | 初始 `[N]`，完成后 resize 为 `[K]` | INT64 | Device 已写原始索引；Host 只回读 `keepCount` 并修改 Tensor 元数据，`0<=K<=N` |

### 入口与版本

转换交付注册 `cann_bench::nms(Tensor boxes, Tensor scores, float iou_threshold) -> Tensor`，绑定 Meta 与 `PrivateUse1`，不是 ACLNN 两段式接口。目标为 CANN 9.1.0、950/Ascend 950。固定提交中的 950 `NMSWithMask` 公开支持 Ascend 950，并注册 `ascend950`、`arch35` tiling 与 key 10000；它只提供相关实现结构来源。`NonMaxSuppressionV6` 虽有独立 boxes/scores、降序 greedy 的接口语义，但固定仓 README 明确没有开放 AscendC kernel，且公开文档明确不支持 Ascend 950；它只能用于 ABI/语义差异核对，不能作为 950 Device body。A2 参考 `NMSWithMask` 为单核 UB、最多 2048 个框，也只能作为“独立 boxes/scores + 顺序 greedy”参考。

### 来源与转换关系

- **官方原生事实**：Frontmatter 的固定 Commit 文件证明 `NMSWithMask` 的 950 接口、key 10000 tiling、AIV 多核 pair-mask 后有序传播，以及官方交叉乘法比较；`NonMaxSuppressionV6` 和 experimental `NMSWithMask` 只提供接口/语义差异边界。
- **Direct Invoke 适配**：Torch schema、Meta/PrivateUse1、current-stream 获取、Torch Tensor 临时内存、逐值 C launcher ABI、逐 stage Host 同步、D2H count 与动态 resize 都是转换适配，不是上述官方算子的原生 Host 链。
- **Device 派生补充路线**：rank-count 排序、UINT32 rank/order、SoA 重排、20 核 full-byte suppression matrix、字面 FP32 epsilon/division 和 INT64 动态索引输出是为目标语义新增的 R-001；D-001～D-003 也是转换源码保留实现。固定官方来源不单独证明这些选择的等价性、资源安全或性能。

## Host/Launcher 执行流程

### 参数校验与前处理

`nms_meta` 依次检查 `boxes` 为二维且末维 4、`scores` 为一维且长度等于 `N`、两个输入均为 FP32、阈值在 `(0,1)`，并以输入设备/options 分配最大长度 `N` 的 INT64 输出。`nms_npu` 再设置 DeviceGuard，检查同设备与 contiguous；没有隐式 `Contiguous/ViewCopy`，也不检查 `N>0`、框合法性、score 的 NaN/并列或整数/内存上界。`N` 直接窄化为 `uint32_t`，阈值在 launch 点直接窄化为 FP32。

### 参数、Workspace 与生命周期

定义 `A=align_up(N,32)`，`P` 为从 UINT32 常量 1 反复左移得到的不小于 `N` 的最小 2 次幂：

```text
orderWorkspace = P * sizeof(int32)                 = 4P B
sortedCoords   = 4A * sizeof(float)                = 16A B
sortedAreas    = A * sizeof(float)                 = 4A B
maskWorkspace  = N*A * sizeof(uint8)               = N*A B
countWorkspace = 8 * sizeof(int32)                 = 32 B
output capacity                                           = 8N B
temporary_tensor_total = 4P + 20A + N*A + 32 B
```

`sortedAreas` 在 rank-chunk 阶段先把 FP32 Tensor 的相同 4-byte 槽解释为每个原始 index 的 UINT32 rank；scatter 完成并同步后，reorder 才覆盖同一物理 Tensor 为排序后 FP32 area。`orderWorkspace` 以 `P` 分配，但 active 节点只读写前 `N` 项。Host 还计算 UINT32 `sortTmpBytes=15A+512`，但没有把它传给 R-001 的任一 launcher；它只是 dormant `KernelScoreSort` 路线的遗留 producer，不计入 active Device 资源。所有临时 Tensor 均由 Torch Tensor 所有权覆盖整个 `RunOpApi` lambda、逐节点同步、D2H 与最终 resize；没有把 Host 临时地址异步悬挂到函数外。

### 启动图与失败传播

```text
nms_npu
  -> for chunkStart=0; chunkStart<N; chunkStart+=2048
       K-001 nms_rank_chunk_kernel<<<1>>>
       aclrtSynchronizeStream
  -> K-002 nms_scatter_ranks_kernel<<<1>>>
     aclrtSynchronizeStream
  -> K-003 nms_reorder_kernel<<<1>>>
     aclrtSynchronizeStream
  -> K-004 nms_mask_kernel<<<20>>>
     aclrtSynchronizeStream
  -> K-005 nms_greedy_kernel<<<1>>>
     aclrtSynchronizeStream
  -> D2H countWorkspace[0] (4 B)
     aclrtSynchronizeStream
  -> validate 0<=keepCount<=N
  -> output.resize_({keepCount})
```

所有节点使用当前 NPU stream；每个节点后都做 Host stream 同步，因此 producer 完成后 consumer 才提交。任一同步错误由 `TORCH_CHECK` 立即阻断后续节点。launcher 与 kernel entry 返回 `void`，异步 Device 错误只由紧随其后的 stream synchronize 转成 Host 失败。D2H 只复制 keep count，框、`scores`、IoU/mask 和输出索引都不回 Host 计算。`N=0` 时只跳过 rank-chunk 循环，scatter、reorder、20-block mask 与 greedy 仍会提交；由于 greedy 会申请两个零字节 local buffer，源码没有建立可复用的空输入安全分支。

| 边 | 介质与范围 | producer → consumer | ordering | owner/lifetime |
|---|---|---|---|---|
| E-001 | `sortedAreas[0:N]`，UINT32 rank 视图 | 所有 K-001 → K-002 | 每 chunk 后 Host stream sync，最后一 chunk 后再提交 scatter | Torch Tensor；scatter 完成后可覆盖 |
| E-002 | `orderWorkspace[0:N]`，UINT32 | K-002 → K-003/K-005 | scatter 后 stream sync | Torch Tensor；greedy 完成后释放 |
| E-003 | `sortedCoords[0:4A]` SoA FP32；`sortedAreas[0:N]` FP32 | K-003 → K-004 | reorder 后 stream sync | Torch Tensor；mask 完成后不再读 |
| E-004 | `maskWorkspace[0:N*A]` row-major UINT8 | K-004 → K-005 | mask 后 stream sync | Torch Tensor；greedy 完成后释放 |
| E-005 | `countWorkspace[0]` INT32 | K-005 → Host D2H | greedy sync；D2H async 后再次 sync | Torch Tensor；resize 后释放 |

## Route 与参数设计

### 分核与资源计算

活跃路线不查询硬件核数，也不生产传统 Tiling POD。rank chunk 大小固定 2048，chunk 数为 `ceil(N/2048)`；K-001/K-002/K-003 均启动一个 AIV block、SIMT `blockDim.x=2048`。K-004 固定启动 20 个 AIV block，每块 2048 SIMT lane：core `c` 处理 reference 行 `c,c+20,...`，lane `t` 处理 destination `t,t+2048,...`。K-005 固定单核顺序遍历排序位置。`A=align_up(N,32)` 只用于 SoA/mask GM 行跨度，`B=align_up(N,256)` 用于 greedy Vector buffer。

### Route 选择

P 等级综合合法域覆盖、生产可达性、性能结构价值与安全终点价值，只组织阅读，不参与 Host 判定。固定 Host 没有 key、tiling key 或 runtime capability selector：校验成功只会进入 R-001；源码中其它排序实现都没有从 `nms_npu` 出发的调用边。合法输入谓词本身不等于 `conditional`，因此本卡有一条 active Route、零条 conditional Route。

| 重要性 | 状态 | Route/family | 覆盖与价值 | selector、短路与 fallback |
|---:|---|---|---|---|
| P0 | active | R-001 rank-count + byte-mask greedy | 唯一生产图；rank-chunk 计数、scatter、SoA 重排、20 核 pairwise byte mask 与单核 greedy 闭合完整语义 | `nms_meta/nms_npu` 校验成功即无条件进入；任一 Host 校验、同步、D2H 或 count 检查失败即终止，无其它 Device/CPU/ACLNN Route |
| P1 | dormant | D-001 `KernelScoreSort` tile/merge wrapper | `launch_nms_direct_float → launch_nms_sort_float → sort_tiles(+merge) → reorder → mask → greedy` 是源码中最完整的替代排序图 | `nms_npu` 从不调用 `launch_nms_direct_float/launch_nms_sort_float`；不能作为 R-001 的自动退路 |
| P2 | dormant | D-002 rank 聚合 wrapper | `launch_nms_global_sort_float` 可连续提交 rank chunks 与 scatter | Host 不调用该 wrapper，而是逐 chunk 调 stage launcher 并同步；两种失败传播与生命周期不同 |
| P3 | dormant source | D-003 孤立排序 entry/body | tiled-512 merge、global bitonic、serial heap、identity、20-core rank 等候选算法仍在 translation unit 中 | 没有完整 Host selector/launcher/后继图，不能仅凭 global entry 存在构造生产 Route |

```text
nms_npu:
  require boxes:[N,4]/FP32, scores:[N]/FP32, same device, contiguous
  require double(iou_threshold) in (0,1)
  allocate output[N] and GM temporaries
  for start in range(0,N,2048):
      launch rank_chunk(start,min(2048,N-start)); synchronize-or-fail
  launch scatter; synchronize-or-fail
  launch reorder; synchronize-or-fail
  launch mask; synchronize-or-fail
  launch greedy; synchronize-or-fail
  D2H count; synchronize-or-fail; range-check; resize
  # no selector retry and no edge to D-001/D-002/D-003
```

### dormant 源码与重新启用条件

| family/符号 | 生产链不可达证明 | 重新启用必须闭合的条件 |
|---|---|---|
| D-001 composite sort：`launch_nms_direct_float`、`launch_nms_sort_float`、`launch_nms_sort_tiles_float`、`launch_nms_sort_merge_float`、`nms_sort_kernel/KernelScoreSort`、`nms_merge_sort_kernel/MergeScoreSortSimt` | `nms_npu` 只引用五个 stage launcher；全源码没有调用 `launch_nms_direct_float` 或 `launch_nms_sort_float` 的 Host 边。`launch_nms_sort_one_tile_float` 也没有 caller | 新增互斥 Host selector 与明确优先级；把 `sortedAreas` 作为 merge 的 UINT32 auxiliary 保活到 reorder 前；令 `A_t=align_up(tileLength,32)`，为每个最多 1024 项 tile 证明 `KernelScoreSort` 的三个 `4A_t` Queue 加 `15A_t+512` TBuf 容量；定义并列/NaN score 顺序；补齐 current-stream 同步、错误传播和后继节点生命周期 |
| D-002 rank wrapper：`launch_nms_global_sort_float` | 只在 header/Device translation unit 声明和定义；`nms_npu` 不调用。它内部批量提交 chunk 与 scatter，没有生产 Host 当前的逐 chunk同步点 | selector 必须显式选择 wrapper，传入不与未完成消费者冲突的 rank/order GM，并在 reorder 前建立完成与失败可见性；还需证明去掉逐 chunk Host 同步不会改变所需生命周期 |
| D-003 tiled local family：`nms_tiled_sort_kernel/TiledScoreSortSimt`、`nms_adjust_tile_order_kernel/AdjustTileOrderSimt` | 两个 global entry 均没有 launcher 调用；512 项 local tile 与现存 1024-width merge/索引修正也未形成完整可达组合 | 先设计一致的 tile 宽度、local/global index 表示与 merge 起始宽度，再增加 launcher、Host selector、GM/UB 账和后继同步；不能把两个孤立 entry 直接拼接 |
| D-003 standalone family：`nms_global_bitonic_sort_kernel/GlobalBitonicSortSimt`、`nms_serial_heap_sort_kernel/SerialHeapSortSimt`、`nms_identity_order_kernel/IdentityOrderSimt`、`nms_rank_sort_kernel/RankSortSimt` | 四个 global entry 均没有任何 `<<<...>>>` 调用点；其中 `RankSortSimt` 还把 `coreCount=20` 写死在 body 参数，却没有 20-block launcher | 分别补 launcher/grid、Host 谓词和与 reorder 的 order ABI；bitonic 需证明 power-of-two/sentinel 与 score 域，identity 需证明输入已降序，heap/rank 需定义 tie/NaN 规则，20-core rank 还需消除 `order[rank]` 写冲突并建立跨核完成边 |

Dormant family 不参与 active 的 POD、UB、workspace 或同步账，也不是出错重放路径。只有同时接通 Host producer、selector、launcher、entry/body、资源和失败出边后，才可重新归类为 active/conditional Route。

### 模板/实现执行矩阵

| Route | key/selector | dtype/shape/platform 完整命中条件 | 执行拓扑与 Kernel 节点 | 实际模板/body | 内存与同步特征 | tail/fallback |
|---|---|---|---|---|---|---|
| P0 · R-001 | active；无 key/serialized tiling/能力分支 | FP32 boxes `[N,4]`、FP32 scores `[N]`、950 Direct 构建、同设备 contiguous、double 阈值 `(0,1)`；安全复用还要求后表 guard | `ceil(N/2048)`×K-001 → K-002 → K-003 → K-004 → K-005 | `RankChunkSimt`、`ScatterRanksSimt`、`ReorderSimt`、`PairwiseSuppressSimt`、`KernelGreedy::Process/ApplyRow` | GM Tensor 边；逐 stage Host stream sync；K-001 与 K-005 使用 UB | chunk、SIMT grid-stride、reference stride 与 MicroAPI mask 覆盖尾部；任一失败终止，无 fallback |

### 关键安全与资源 Guard

## Kernel 实现

### 公共执行流程

全部活跃 entry 都设置 `KERNEL_TASK_TYPE_DEFAULT(KERNEL_TYPE_AIV_ONLY)`。K-001 用 AIV 的 `TPipe/TBuf/DataCopyPad` 搬入一个 score chunk，再从同一 AIV block 内调用 2048-lane SIMT；K-002～K-004 直接从 AIV entry 调 SIMT；K-005 使用 AIV Queue、Vector Duplicate、MicroAPI mask/select 与标量 greedy。节点之间只以 GM Tensor 交接，不传 opaque Device workspace 或 Tiling buffer。

##### 源码等价伪码

```text
# 伪码；保持 active 源码顺序；首个 chunk 在每个 index 的 lane 内初始化 rank
for start in range(0,N,2048):
    L = min(2048,N-start)
    scoreLocal[0:L] = scores[start:start+L]
    wait MTE2 -> Vector/SIMT visibility
    parallel tid in [0,2048):
        for i=tid; i<N; i+=2048:
            rank = 0 if start==0 else ranks[i]
            for off=0; off<L; ++off:
                rank += (scoreLocal[off] > scores[i])
            ranks[i] = rank

parallel tid in [0,2048):
    for i=tid; i<N; i+=2048: order[ranks[i]] = i

parallel tid in [0,2048):
    for pos=tid; pos<N; pos+=2048:
        i=order[pos]
        coords[0*A+pos]=boxes[4*i+0]; coords[1*A+pos]=boxes[4*i+1]
        coords[2*A+pos]=boxes[4*i+2]; coords[3*A+pos]=boxes[4*i+3]
        areas[pos]=(x2-x1)*(y2-y1)

parallel core in [0,20), tid in [0,2048):
    for ref=core; ref<N; ref+=20:
        for dst=tid; dst<N; dst+=2048:
            if any coordinate is NaN: remove=true
            else:
                intersection=clamped_width*clamped_height
                iou=intersection/(areas[ref]+areas[dst]-intersection+1e-6)
                remove=!(iou<=threshold)
            mask[ref*A+dst]=uint8(remove)

alive[0:B]=1; keepCount=0
for pos in [0,N):
    wait previous Vector store -> scalar load
    if alive[pos]==0: continue
    output[keepCount++]=int64(order[pos])
    row[0:N]=mask[pos*A:pos*A+N]
    loops = uint16(ceil(N/256))
    remaining = N
    for vec in range(loops):
        active = UpdateMask(remaining)  # 参数按引用传入；每轮 POST_UPDATE 扣除至多 256
        alive[vec] = select(0, alive[vec], row[vec]==1, active)
        # 最后一轮 active 只覆盖 remaining 个真实字节
    Vector store/load barrier; wait Vector -> scalar
count[0]=int32(keepCount)
```

## 算子特定优化

### Trick T-001：并行关系生成与有序 greedy 解耦

#### 触发与源码依据

- 适用 Route：P0 / R-001。
- 触发条件：所有合法 `N`；先完成 pairwise suppression 介质，再按 `scores` 顺序传播。
- 官方结构锚点：[`image/nms_with_mask/op_kernel/arch35/nms_with_mask_regbase_multiprocess.h:72-83`](../../../../../../../cann-ops-raw/ascendc/ops-cv/bb717d075d129fd1fc7b96b2886824a1d153ed2f/image/nms_with_mask/op_kernel/arch35/nms_with_mask_regbase_multiprocess.h#L72-L83)

**官方源码（固定 Commit 连续逐字摘录）**：

```cpp
__aicore__ inline void NMSWithMaskRegbaseMultiProcess<T>::Process()
{
    if (blockIdx_ >= usedCoreNum_) {
        return;
    }
    PreProcess();
    // reset tque
    PipeBarrier<PIPE_ALL>();
    SyncAll();
    ReInit();
    PostProcess();
};
```

#### 机制与设计原因

greedy 选择存在严格的顺序依赖，不适合直接把 `position` 并行化；pairwise IoU 则彼此独立。官方 950 body 先由多核 `PreProcess` 计算上三角 packed mask，再 `SyncAll` 后 `PostProcess` 传播。转换路线保留“关系生成→全局可见→有序传播”的结构，但派生为 20 核 full byte matrix 与单核 greedy：K-004 每个 `(ref,dst)` 由唯一 SIMT lane 写入，K-005 只做 byte mask 的 Vector select，从而不在 greedy 内重复计算 IoU。full byte matrix、固定 20 核和 Host stage sync 均是转换选择，不是官方原实现。

#### 迁移边界

- 适用：pairwise predicate 可并行、最终选择必须保持全序的 NMS/过滤任务。
- 前提：可承担 `N*A` B 的 GM mask；producer 与 consumer 之间有明确 stream/event/barrier；排序顺序已闭合。
- 失效：mask GM 不可承受时需改用官方式 packed/triangular mask或分块流式 greedy，并重新证明同步与索引语义。
- 证据边界：该迁移结论来自固定官方结构与 Direct 数据流的静态对应，不据此外推吞吐或设备运行结论。

#### 错误做法

若省略 K-004→K-005 的完成同步，greedy 可能读取未完成的 row；官方源码以 `PipeBarrier + SyncAll` 明确证明这一边不能仅靠源码书写顺序替代。

### Trick T-002：为目标语义保留字面 FP32 除法与 epsilon

#### 触发与源码依据

- 适用 Route：P0 / R-001 K-004。
- 触发条件：所有非 NaN 坐标 pair；转换目标要求 `intersection/(union+1e-6)` 后再做 `<=threshold`。
- 官方算术对照锚点：[`image/nms_with_mask/op_kernel/arch35/nms_with_mask_regbase_multiprocess.h:480-483`](../../../../../../../cann-ops-raw/ascendc/ops-cv/bb717d075d129fd1fc7b96b2886824a1d153ed2f/image/nms_with_mask/op_kernel/arch35/nms_with_mask_regbase_multiprocess.h#L480-L483)

**官方源码（固定 Commit 连续逐字摘录）**：

```cpp
MicroAPI::Mul(intersection, minX2, minY2, preg);
MicroAPI::Sub(sumArea, sumArea, intersection, preg); // 视sumArea为并集大小
MicroAPI::Muls(sumArea, sumArea, iouThreshold_, preg);
MicroAPI::Compare<float, CMPMODE::GT>(pregIou, intersection, sumArea, preg);
```

#### 机制与设计原因

官方 950 `NMSWithMask` 用 `intersection > threshold*union` 避免除法；这与转换目标并不完全同构，因为目标分母额外加 `1e-6`，且 FP32 乘法交叉变换会改变边界舍入。转换 K-004 因此派生地保留 `denominator=union+1e-6`、`iou=intersection/denominator`、`remove=!(iou<=threshold)` 的字面顺序，并单独处理坐标 NaN。该选择服务数值语义，不声称比官方公式更快。

#### 迁移边界

- 适用：参考语义明确规定 epsilon、除法顺序和 NaN 比较方向的 NMS。
- 前提：FP32 输入/中间值；阈值先按 Direct ABI 窄化为 FP32；框面积定义一致。
- 失效：若调用契约就是官方 `intersection > threshold*union`，应保持官方交叉乘法；两者不能无证明互换。
- 证据边界：该结论约束运算次序与比较方向，不单独证明未声明输入域上的等价性或性能。

#### 错误做法

直接把目标比较改写为官方交叉乘法，会丢失 `+1e-6` 并改变少量 FP32 阈值边界；固定官方源码本身正是该非同构边界的可验证反例。

## 限制与失败边界

- 转换目标与官方 `NMSWithMask`、`NonMaxSuppressionV6` 均不完全同构；不能用官方算子名替代对独立输入、坐标顺序、score sort、epsilon、NaN、INT64 动态输出的实现证明。
- rank-count 依赖 `scores` 无 NaN、无并列且严格大于关系形成全序；NaN、相等值或 `+0/-0` 会使多个 index 得到同一 rank，`order[rank]` 发生写冲突并留下未定义槽。固定路线没有稳定 tie-break fallback。
- `N` 被窄化为 UINT32，keep count 又写 INT32；`P` 左移、`N+31`、`N+255`、`N*A`、`A*{2,3,15}` 与各指针偏移均缺少显式溢出 guard。复用时应把 `N<=INT32_MAX`、`ceil(N/256)<=UINT16_MAX` 与所有乘加可表示性作为前置条件。
- Host 校验 double 阈值 `(0,1)`，比官方 950 `NMSWithMask` 的 `[0,1]` 更窄；launch 前 FP32 窄化可把极近端点的值舍入成 0 或 1。空 `N=0` 未被拒绝，且仍提交 scatter/reorder/mask/greedy，零字节 local buffer 没有专门安全分支。
- K-004 物化 `N*A` B full byte mask，空间为 O(N²)；K-001 rank count 计算为 O(N²)，K-005 最坏也逐保留框读取 N 字节。本文不声称性能收益。
- K-005 依赖 `MicroAPI::UpdateMask(uint32_t&)` 的按引用 POST_UPDATE：每轮从 `remaining` 扣除一个 UINT8 vector width，最后一轮据余数裁尾。把 `remaining` 改成按值副本、常量或不具 POST_UPDATE 的 mask helper 会破坏尾块语义；B-byte 对齐仍是 Queue/TBuf 分配前提。
- Host 每个 stage 都同步，使异步错误在对应边界转为 Host 失败，但也阻止跨 stage 异步重叠；不得删除同步而不补充等价 stream/event 与所有权证明。
- 固定官方源码只证明相关算法结构、950 支持与差异边界；Direct selector、workspace Tensor 复用、rank-count、full byte mask、动态 resize 与 Torch 生命周期均为转换交付事实。
- D-001～D-003 都没有从 `nms_npu` 出发的生产边；R-001 失败不会转到这些实现，也不会转到 CPU、ACLNN 或官方 `NMSWithMask`。
- `direct_implementation_closed` 只表示静态源码链闭合，不证明转换载荷在全部输入域可运行或具备未声明性质。
- 本卡只闭合静态生产调用图；运行正确性、容量上限与性能不从静态源码自动推出。
