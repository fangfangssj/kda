# GQA 950 Direct Invoke 算子知识

## 算子速览

| 项目 | 内容 |
|---|---|
| 实际入口 | Python `cann_bench.gqa` → dispatcher `cann_bench::gqa` → `gqa_npu` →三类 Host plan→显式 C launcher。 |
| 语义 | 对每只 KV head 的 `G=Nq/Nkv` 个 query heads 计算 `softmax(scale·QK^T+causal)V`；causal 是右下对齐三角。 |
| 合法域 | Q/K/V 为同设备、同 FP16/BF16 的 rank-4 BSND；`B,Sq,Skv,Nq,Nkv>0`，K/V shape 相同，Q/K 的 B、D 相同，`Nq%Nkv=0`；`D` 为 `[64,512]` 内 64 的倍数。任意 stride 输入在 Host 稠密化。 |
| Route | 18 条可达 Route：16 active（14 common FIA + 2 generic AIV）、2 conditional dedicated FlashAttn；没有生产链可达的 dormant Route。 |
| 节点图 | common causal：AIV mask→MIX_CV；common non-causal/dedicated：单 MIX_CV；generic：每个 row chunk 依次启动 score→softmax→output 三个 AIV-only 节点。 |
| 内存 | common/dedicated 有效 GM workspace 为 0；common causal 另有 uint8 mask。generic 复用不超过 64 MiB 的 FP32 score workspace。非连续输入另有 dense Q/K/V 临时张量，输出始终新分配为 dense。 |
| 精度 | QK、softmax 状态与 PV 累加均为 FP32；输入 dtype 用于 Q/K/V、common/dedicated 的 P，以及最终输出。 |
| 来源闭包 | `direct_implementation_closed_with_external_runtime_contract`：接口、校验、selector、三类 plan/POD、launch 图、Device body、核/任务映射、内存、同步、mask、tail、精度和 fallback 闭合；异步临时 storage 生命期明确依赖 stream-aware completion-owner 契约。 |

## 来源与转换关系

固定提交的官方源码提供 FIA common GQA 的 D128 原生 Host 路由（c1/c3 MIX_CV）、可复用的 c18 config/Device body，以及专用 FlashAttn c2 GQA 的 SectionStreamK、Cube/Vector body 与 online softmax。Direct 交付把 registry/metadata 路线转换为 PrivateUse1 schema、current-stream launcher、按值 tiling、显式 dtype/config symbol，并补充共享 causal-mask producer。

官方 GQA Host 不接受 `qkHeadDim!=128`；canonical Direct Host 将 D256 显式映射到 c18，因而 c18 组件有官方来源，但 D256 GQA 的可达激活是 Direct 派生适配，不是 official 原生 GQA Host route。官方源码也没有提供本任务的 Python schema、任意 stride 适配、D64/D192/D320～D512 通路或 `Sq>Skv` 的全掩行语义。`ValidateGqa`、`.contiguous()`、dense output 与 generic 三节点 AIV 路线属于 Direct 派生补充，不能称为官方原生实现。固定 HTTP 来源证明官方骨架与模板事实，不单独证明这些 Direct 适配的语义等价性。

## 接口、校验与数学

令 `Q:[B,Sq,Nq,D]`，`K,V:[B,Skv,Nkv,D]`，`G=Nq/Nkv`，`hkv=floor(hq/G)`：

```text
scale = float32(1/sqrt(D))  if scaleValue <= 0
      = float32(scaleValue) otherwise
score[b,hq,i,j] = scale * dot_fp32(Q[b,i,hq,:], K[b,j,hkv,:])
causal 时仅保留 j <= i + Skv - Sq
P = softmax_fp32(score, axis=j)
Y[b,i,hq,:] = cast_input_dtype(sum_fp32(P * V[b,:,hkv,:]))
```

`scaleValue` 没有 finite 检查；NaN 不满足 `<=0`，因此以 NaN 显式进入 FP32 计算，正负无穷也不会在 Host 被拒绝。

| 检查 | Host 行为 | Device 前提 |
|---|---|---|
| rank/dtype/device | 三输入均 rank 4、dtype 完全相同且仅 FP16/BF16、device 完全相同 | 不存在“非 FP16 即 BF16”的越界分派 |
| shape | K/V shape 相同；Q/K 的 B、D 相同；B/Sq/Skv/Nq/Nkv 正数；`Nq%Nkv=0` | `G` 与所有 BSND offset 可定义 |
| D | `64<=D<=512 && D%64==0` | common 仅 D128/D256，其余由 generic 承接 |
| 上界 | `B<=256,Sq<=4096,Skv<=8192,Nq,Nkv<=256` | generic workspace 公式与 direct ABI 有界 |
| 乘积 | 用 `__int128` 检查 int64；`B*Sq`、`B*Skv` 另须可表为 uint32 | common POD 不静默窄化；generic int64 索引不溢出 |
| layout | Q/K/V 可为任意 stride；各自调用 `.contiguous()` | Device 总是读取 dense BSND；dense 输入可原样复用存储 |
| output | `torch::empty(query.sizes(), query.options())` | shape/dtype/device 与 Q 相同，但不承诺继承 Q 的 stride |

`gqa_meta` 与 `gqa_npu` 共用 `ValidateGqa`。NPU 路径先设 query device guard，再分配输出和稠密输入。输入拷贝、临时张量分配或 plan 构造失败均发生在 direct launch lambda 之前。

## Host selector、POD 与 launch

### 真实 selector 顺序

```text
H0 ValidateGqa; output=empty(shape); denseQ/K/V=contiguous()
H1 useGeneric = D not in {128,256} OR (causal AND Sq>Skv)
H2 flashCandidate = !useGeneric AND !causal AND D==128
                    AND Sq==Skv AND Sq>=256
H3 candidate ? make_flash_plan() : zero FlashPlan
   useFlash = flashCandidate AND flashPlan.supported
H4 !useGeneric ? make_common_plan() : zero CommonPlan
H5 useGeneric ? make_generic_plan() : zero GenericPlan
H6 allocate generic FP32 scores OR common causal uint8 mask OR neither
H7 lambda: generic early-return; dedicated early-return;
           otherwise optional mask then dtype/config/mask common dispatch
```

H3 的最终门是 `SectionStreamK::Compute` 成功、`sectionNum==1`、FA/FD 结果均存在、FA `usedCoreNum>0` 且 FD `usedVecNum==0`。任一条件失败只取消 dedicated，H4 已生成的 common plan随即接管。candidate 不含 batch 白名单。

### 三类 Host plan

| plan | Host producer | 核心字段/公式 | 消费方式 |
|---|---|---|---|
| `GenericGqaLaunchPlan` | `make_generic_gqa_launch_plan` | `totalRows=B*Sq*Nq`；`workspaceRows=min(totalRows,floor(64MiB/(Skv*4)))`；`blockDim=reportedAIV`，查询失败为 1；FP32 scale | struct 不整体过 ABI；字段展开为三类 launcher 的 int64/uint32/float 标量 |
| `GqaLaunchPlan` | `make_gqa_launch_plan` | `GqaDirectTiling`、MIX `blockDim`、mask 几何、`compressedMask`、config 1/3/18 | tiling 按值传入 common MIX；mask 字段传入 AIV producer |
| `FlashGqaLaunchPlan` | `make_flash_gqa_launch_plan` | `FlashGqaDirectTiling`、FA `blockDim`、`supported` | supported 只在 Host 消费；tiling 按值传入 dedicated MIX |

common plan 只在非 generic 域构造，真实映射是：D128 且 `Sq<=64 && Skv>128`→c1；其它 D128→c3；D256→c18。M/S2/D tile 分别是 c1=`64/256/128`、c3=`128/128/128`、c18=`64/256/256`。

固定结构按 LP64 自然对齐的 ABI 账如下；源码未提供配套 `static_assert`，移植时须在目标编译器复核。

| ABI 对象 | size/align | 关键 offset/步长 | 传递边界 |
|---|---|---|---|
| `NoQuantTilingArch35` | 272 B / 8 | base/mask/PSE/prefix/PA/padding/quant/workspace/S1-outer/empty 参数覆盖 0～271 | 嵌入 common Direct POD |
| `GqaDirectTiling` | 1424 B / 8 | `faMetadata[core]` 从 `272+core*32` 开始，每核 8×uint32 | 整体按值传入 14 个 common symbols |
| `GqaLaunchPlan` | 1456 B / 8 | `blockDim` 从 1424 开始；其后 mask geometry、bool 与 uint16 config | Host-only；只拆出 tiling与 launcher 标量 |
| `FlashAttnNoQuantTilingArch35` | 144 B / 8 | base/mask/PA/workspace/S1-outer 覆盖 0～143 | 嵌入 dedicated Direct POD |
| `FlashGqaDirectTiling` | 2448 B / 8 | `faMetadata[core]` 从 `144+core*64` 开始，每核 16×uint32 | 整体按值传入 2 个 dedicated symbols |
| `FlashGqaLaunchPlan` | 2456 B / 8 | `blockDim` at 2448，`supported` at 2452 | Host-only |
| `GenericGqaLaunchPlan` | 24 B / 8 | two int64 后接 uint32 blockDim 与 float scale | Host-only；C launcher 接收展开后的 shape/plan 标量 |

### common POD 的 active/inactive 边界

`GqaDirectTiling={NoQuantTilingArch35 baseTiling; uint32 faMetadata[36][8];}`。聚合零初始化后，Host 只激活下列关系：

| POD 子结构 | active producer→consumer | inactive/边界 |
|---|---|---|
| `FiaBaseParams` | B、`B*Sq`、`B*Skv`、Nkv、G、Sq、Skv、D、DV=D、FP32 scale、continuous、coreNum、BSH output → scheduler/offset/Vec | Rope/actual-seq/LSE 为 0；BSH 与 dense BSND 仅在连续字节序上等价 |
| K/V stride groups | 全零 | 非连续路径不读；Host 已稠密化 |
| `FiaAttenMaskParams` | causal 为 right-down、`preTokens=INT_MAX,nextTokens=0`、单张 mask 和物理 row stride | non-causal default；row-invalid 关闭 |
| PSE/prefix/PA/left-padding/post-quant | 全零 | 不得从官方大结构外推能力 |
| workspace params | accumOut/logSumExp 均 0 | FD 和 GM C2 workspace 不可达 |
| S1-outer params | metadata 成功时 `enable=false,totalSize=0`；否则 `enable=true,totalSize=totalTasks` | metadata 请求 FD 时退 S1-outer |
| `faMetadata[core][8]` | enable、BN2/M/S2 start/end、first-FD index → scheduler | S1-outer 时忽略；未用 core 为零 |

`totalTasks=B*Nkv*ceil(Sq*G/Mbase)`，初始 `blockDim=clamp(totalTasks,1,availableAIC)`。仅 D128 且 `residentBn*Skv*(D+D)*sizeof(input)*2<L2` 时运行 `split_core_v2`；结果必须 `fdNum==0 && usedCoreNum>0` 才切 metadata cursor，否则走 S1-outer 蛇形调度。`residentBn=min(B*Nkv,availableAIC)`，末尾乘 2 是双份驻留预算。

### dedicated POD

`FlashGqaDirectTiling={FlashAttnNoQuantTilingArch35 baseTiling; uint32 faMetadata[36][16];}`：base 写入 B、扁平 token 数、Nkv、G、Sq=Skv、D=DV=128、FP32 scale、fixed-length/continuous、coreNum 与 BSND output；mask、PA、LSE、FD workspace 和 output pre-clear 均关闭。active core 的 metadata 只写 BN2/M/S2 start/end 与 first-FD index，其余槽为零。

SectionStreamK 使用 M128/S2 128、平台 AIC/AIV 上限、96 MiB L2 参数和 `fdOn=true`。cost model 的 query/kv dtype 固定写作 FP16，BF16 Device body仍由独立模板 symbol 具体化；不能把 cost-model dtype 当成 Device IO dtype。

### mask、workspace 与生命周期

| Route 族 | Host 临时存储 | Device consumer | 生命周期/同步 |
|---|---|---|---|
| generic | dense Q/K/V；FP32 `[workspaceRows,Skv]` scores | 三个 AIV 节点 | 每个 chunk 的 score→softmax→output→下一 chunk 按 current stream 顺序；owner 依赖外部 completion 契约 |
| common causal full | dense Q/K/V；uint8 `[Sq,align32(Skv)]` | common Vec1 | mask producer 先入同一 stream；dense/mask owner 依赖外部 completion 契约 |
| common causal compressed | dense Q/K/V；uint8 `[256,256]` | compressed mask copy | producer/consumer 同时切 compressed 几何；owner 依赖外部 completion 契约 |
| common non-causal | dense Q/K/V | MIX | mask null；模板删除 mask 链；dense owner 依赖外部 completion 契约 |
| dedicated | dense Q/K/V | dedicated MIX | 无 mask，FA cursor 按值携带；dense owner 依赖外部 completion 契约 |

common/dedicated 的官方 ABI 都收到 output 指针作为非空 workspace 占位；当前 `bmm2WriteToUb=true`、`splitD=false`、FD=false，没有 Device 路径消费该 extent，有效 workspace 为 0 B。generic scores 是真实 workspace，不能混同。

launcher 全为 `void`，lambda 提交节点后无条件返回 0，不同步读取异步 Device 状态。所有节点依赖 current stream；跨 stream 使用输出须由上层同步。

canonical 在 lambda 中只传 dense Q/K/V、mask 与 scores 的裸 GM 地址；这些局部 Tensor owner 没有被一个存活到 Device completion 的对象捕获。因而同 stream 只闭合节点先后关系，不自动闭合存储生命周期；本实现明确依赖外部 **stream-aware completion-owner 契约**：allocator/runtime 必须将这些 storage 记录到 current stream，并延迟复用或释放到所有已提交 consumer 完成。可闭环的 owner 机制包括：① allocator `record_stream`/事件驱动 deferred free；② completion event 持有 Tensor owner，由 host callback 或完成队列在事件后释放；③ 持久异步 closure 捕获 owner 直到 completion；④ 在 owner 析构前显式 stream synchronize。仅让提交 launch 的短命 lambda `[=]` 捕获 owner，若 lambda 在 enqueue 后立即析构，仍不足以闭环。输出 Tensor 由返回值保持，但跨 stream/Host 读仍须上层同步。

## Device 执行族

### common FIA MIX_CV

```text
for assigned (b,nkv,M_tile,S2_tile), PRELOAD_N=2:
  AIC: dense Q/K GM->L1->L0A/L0B->QK Mmad(FP32 L0C)
       ->Fixpipe->two AIV halves of cross-core score UB
  AIV0/1: wait score; scale; optional full/compressed mask;
           FP32 online max/sum/exp; cast P to input dtype;
           write own M half to triple-buffered P L1; signal AIC
  AIC two tasks later: wait P; dense V GM->L1; P*V Mmad(FP32 L0C)
       ->Fixpipe->two AIV halves of cross-core C2 UB
  AIV0/1: wait C2; rescale old accumulation; accumulate;
           final S2 tile divides by sum, casts, writes valid M*D
```

MIX entry 标记 `KERNEL_TYPE_MIX_AIC_1_2`。逻辑 `blockDim=N` 对应 N 个 AIC 与 2N 个 AIV；AIV 以 `GetBlockIdx()/GetSubBlockNum()` 找配对 AIC，以 `GetSubBlockIdx()` 分 M tile 的 ceil/floor 两半。

| 层级 | c1 | c3 | c18 | producer→consumer/同步 |
|---|---:|---:|---:|---|
| P L1 triple | 98,304 B | 98,304 B | 98,304 B | AIV MTE3→AIC PV，forward flag，slot `%3` |
| Q/K/V L1 | 32,768+131,072+131,072 B | 65,536×3 B | 65,536+131,072+131,072 B | GM→L1→L0；Q 可跨 S2 驻留 |
| L1 total | 393,216 B | 294,912 B | 425,984 B | 512 KiB 预算内 |
| L0A/L0B/L0C | 64/64/256 KiB | 同 | 同 | Mmad FP32 L0C→Fixpipe |
| score/C2 cross-UB | 65,536+32,768 B | 65,536+65,536 B | 65,536+65,536 B | AIC↔AIV bidirectional DB，slot `%2` |
| AIV private UB | nonmask 57,088；causal 73,472 B | nonmask 73,472；causal 89,856 B | nonmask 73,472；causal 89,856 B | mask queues、stage2、三槽 max/sum/exp |

score/C2 用双向 cross-core flag：AIV 初始化反向“可覆盖”flag，AIC wait 后生产并 set 正向 flag，AIV wait/消费后再 set 反向 flag。P L1 用 forward-only flag。sync mode 为 4，flag id 在 0～10 循环，AIV1 加 16；L1/L0/UB 内另以 MTE1/MTE2/M/FIX/V/MTE3 hard event 排序。

tail 由实际 `actM`、`actS2` 参与地址、mask、softmax和 CopyOut；S2 搬运按输入 dtype 的 16 元素粒度补齐，补齐区不进入有效归一化。D 编译期固定 128 或 256，无 D tail。全量 P 不落 GM，online max/sum 和 output state 跨 S2 tile 保持 FP32。

### dedicated FlashAttn MIX_CV

dedicated c2 仍是 1:2 MIX_CV：M128/S2 128/D128、FP32 QK/PV/online state、P 为输入 dtype、score/C2 双缓冲、P 三缓冲。差异是 one-section cursor、专用 POD/Cube/Vec，以及四槽 `RunInfo` ring（`loop&3`）；preload 仍为 2。本 Direct 合法 c2 实例满足 `BaseApi::IsDn(...)`，因而 `useDn=true`：Cube 以 DN score layout 向 cross-core score UB 交付，Vector 等待同一正向 flag 后由 `ProcessVec1Dn` 执行 DN copy/scale/online-softmax，消费完再回送反向可覆盖 flag。C2 仍按原 Vec2 链消费，P 仍以 forward flag 交给 Cube。

L1/L0/cross-UB 与 c3 相同。DN 路径的 private Vec UB 为 `2*8,192 + 32,768 + 2*33,024 + 6,400 = 121,600 B`；`useDn=true` 时不分配 512 B `commonTBuf`。cross-UB 为 131,072 B，总 UB 为 252,672 B。`needInitOutput=false`；FD 非零时 Host 不进入该族。

### generic AIV 三节点

```text
for rowBegin in range(0,totalRows,workspaceRows):
  rowCount=min(workspaceRows,totalRows-rowBegin)
  score<<<AIV>>>(denseQ,denseK,scores,rowBegin,rowCount):
    each score=(row,j); hkv=(globalRow%Nq)/G
    causal masked -> -FLT_MAX; else dot_fp32(Q,K)*scale
  softmax<<<AIV>>>(scores,rowBegin,rowCount):
    validCount=clamp(qPos+Skv-Sq+1,0,Skv) if causal else Skv
    if validCount==0: zero whole row
    else max/exp/sum/divide FP32; zero masked suffix
  output<<<AIV>>>(V,scores,Y,rowBegin,rowCount):
    each (row,d) computes sum_j fmaf(score_j,V_jd) FP32; cast once
```

三个 entry 都是 `KERNEL_TYPE_AIV_ONLY`，每个 AIV block 以 `asc_vf_call` 启动 1024 个 SIMT threads。`GetGenericGqaBlockRange` 对 score 元素、row 或 output 元素做 ceil block 分片，每线程按 `blockDim.x` 步进。没有显式 L1/L0/UB 或 AIC 任务；Q/K/V/output 与 FP32 scores 直接在 GM 访问，局部 max/sum/dot/result 为标量状态。

tail 包括最后 block count、最后 row chunk、任意合法 D 与 Skv 循环尾部，均由 int64 上界判断收口。`Sq>Skv` 的早期 causal 行可全掩；softmax 将该行 P 置零。当对应 V 元素均为 finite 时，output 中 `fmaf(0,V,result)` 精确保持零；Host 不检查 V 的有限性，NaN/Inf 可通过 `0*V` 传播为 NaN，故非有限 V 不在“全掩输出精确零”承诺内。这一 signed 路径避免 common uint32 diagonal offset 下溢。

## 每条 Route 的关键关系与伪码

以下严格按上表的综合优先级顺序展开；真实执行顺序仍由 Host selector 决定。

### Route R-016（P0，conditional）：BF16 dedicated c2

关系：`BF16 + flashCandidate + SectionStreamK(one section,FA>0,FD=0)` → BF16 c2 MIX；`flashPlan.supported=false` → BF16 common c3。candidate 已要求 `Sq==Skv && Sq>=256`，不可能命中 c1。

```text
if candidate && supported: launch flash_bf16_c2(tiledCursor)
else: launch common_bf16(config=3)
```

数据流、资源和同步取 dedicated 族；M/S2 tail 由 cursor 的 start/end 与实际 tile 长度共同约束，workspace 为 0。

### Route R-002（P0，active）：FP16 common c1 no-mask

关系：D128 short-Q/long-KV 选择 M64/S2 256，no-mask 模板删除 mask producer/consumer。

```text
if fp16 && D==128 && !causal && Sq<=64 && Skv>128:
    launch common<half,c1,false,false>
```

Q 跨 S2 tile 驻留；M tail≤64、S2 tail≤256，P/输出为 FP16，QK/PV/online state 为 FP32。

### Route R-001（P0，active）：FP16 common c1 full causal

关系：Host 先生成 `Sq*align32(Skv)` mask，`diagonalOffset=Skv-Sq`，再启动 c1 MIX。

```text
mask[i,j] = (j > i + Skv - Sq)
launch common<half,c1,HAS_MASK=true,COMPRESSED=false>
```

mask→MIX 依同 stream；MIX 内 score/C2 双向 DB、P 正向三缓冲，FP32 state 跨 S2 tail 保留。

### Route R-005（P0，active）：FP16 common c3 full causal

关系：D128 causal、非 c1且 Sq<256；full mask 由 c3 Vec1 逐 tile 读取。

```text
if fp16 && D==128 && causal && Sq<=Skv && !c1 && Sq<256:
    make_full_mask(); launch common<half,c3,true,false>
```

L1 294,912 B、causal private UB 89,856 B；M/S2 tail 与 mask valid region 同时收口。

### Route R-007（P0，active）：FP16 common c3 no-mask

关系：D128 non-causal 非 c1，且 dedicated 未通过或不候选；M128/S2 128，无 mask 临时区。

```text
if !useFlash && fp16 && D==128 && !causal && !c1:
    launch common<half,c3,false,false>
```

L1 294,912 B、cross-UB 131,072 B；M/S2 tail 只写有效 FP16 输出。

### Route R-008（P0，active）：BF16 common c3 full causal

关系：与 R-005 同 mask/tile，P 在 online softmax 后 cast 为 BF16 再进入 PV。

```text
make_full_mask(); launch common<bfloat16,c3,true,false>
```

输出只在最后 S2 tile 经 FP32 divide 后转 BF16。

### Route R-004（P0，active）：BF16 common c1 no-mask

关系：与 R-002 同 tile、L1/L0/UB 和 flag 协议，P 和输出落 BF16。

```text
launch common<bfloat16,c1,HAS_MASK=false>  # M64,S2=256,D128
```

没有 mask 或 GM workspace；tail 与 R-002 一致。

### Route R-006（P1，active）：FP16 common c3 compressed causal

关系：Host 生成 canonical 256² triangle；consumer 以 compressed offset 取当前 M/S2 子窗。

```text
if fp16 && D==128 && causal && Sq>=256 && Skv>=Sq:
    make_mask(256,256); launch common<half,c3,true,COMPRESSED=true>
```

mask 固定 65,536 B；producer 几何、POD stride 和 consumer template 必须成组切换。

### Route R-009（P1，active）：BF16 common c3 compressed causal

关系：与 R-006 共享 mask/offset 协议，数值主链为 BF16 IO/FP32 state。

```text
make_mask(256,256); launch common<bfloat16,c3,true,true>
```

M/S2 tail 仍用实际长度，canonical mask 的 padding 不进入 softmax。

### Route R-010（P1，active）：BF16 common c3 no-mask

关系：与 R-007 同实现族；dedicated gate miss 是其显式入边之一。

```text
if !useFlash && bf16 && D==128 && !causal && !c1:
    launch common<bfloat16,c3,false,false>
```

BF16 只出现在 IO/P 边界，FP32 state 和同步协议不变。

### Route R-011（P1，active）：FP16 common c18 full causal

关系：D256 固定 M64/S2 256，full right-down mask；K/V L1 各 131,072 B 单缓冲。

```text
if fp16 && D==256 && causal && Sq<=Skv:
    make_full_mask(); launch common<half,c18,true,false>
```

D 无 tail；M/S2 tail 有效，workspace 为 0，`Sq>Skv` 转 R-017。

### Route R-012（P1，active）：FP16 common c18 no-mask

关系：D256 non-causal 直接进入 c18 no-mask，P/输出 FP16，累加 FP32。

```text
if fp16 && D==256 && !causal: launch common<half,c18,false,false>
```

L1 425,984 B，score/C2 cross-UB 131,072 B；没有 mask 临时区。

### Route R-013（P1，active）：BF16 common c18 full causal

关系：与 R-011 同资源和 mask；`Sq>Skv` 不进入 common，而提前转 R-018。

```text
if bf16 && D==256 && causal && Sq<=Skv:
    make_full_mask(); launch common<bfloat16,c18,true,false>
```

P 与输出为 BF16，FP32 max/sum/exp/PV state 到末块才 cast。

### Route R-003（P2，active）：BF16 common c1 full causal

关系：mask 几何、c1 tile 和 cross-core protocol 同 R-001，仅 IO/P dtype 为 BF16。

```text
make_full_mask(); launch common<bfloat16,c1,true,false>
```

`Sq<=Skv` 已由 generic selector 的反条件保证；full mask row stride 是 `align32(Skv)` bytes。

### Route R-014（P2，active）：BF16 common c18 no-mask

关系：D256 non-causal 的 BF16 symbol；没有 Device 内二次 selector。

```text
if bf16 && D==256 && !causal: launch common<bfloat16,c18,false,false>
```

M/S2 tail、L1/L0/UB 和双向/正向 flag 与 R-012 相同。

### Route R-015（P2，conditional）：FP16 dedicated c2

关系与 R-016 相同，仅 IO/P cast 类型为 FP16；selector 不含 batch 限制。

```text
if fp16 && !causal && D==128 && Sq==Skv && Sq>=256 && supported:
    launch flash_fp16_c2_nomask
```

gate miss 的出边是 common c3（candidate 的 Sq 已不可能命中 c1）；Device 不自行重新选择调度。

### Route R-017（P2，active）：FP16 generic safety route

关系：D 不是 128/256，或 causal `Sq>Skv` 时在所有 official plans 之前短路；复用 FP32 score workspace。

```text
for rowChunk:
  launch score_fp16 -> softmax_fp16 -> output_fp16 on current stream
```

每个节点用 AIV-only SIMT；GM→标量 FP32→GM，无 L1/L0/Cube。chunk/block/D/Skv tail 由 int64 loop 边界闭合；全掩行的 P 为零，仅当对应 V 为 finite 时承诺输出精确零。

### Route R-018（P2，active）：BF16 generic safety route

关系：selector、workspace、三节点和同步与 R-017 相同；score/output 节点的 GM load/store 类型改为 BF16。

```text
for rowChunk:
  launch score_bf16 -> softmax_bf16 -> output_bf16 on current stream
```

dot、exp、sum、PV 均 FP32；只在最终 output store 转 BF16。

## 可复用优化与迁移边界

### T-001：Host 能力门隔离 specialization 与完整合法域

先以 generic predicate 拦截 D 非 128/256 和 `Sq>Skv`，再尝试 dedicated，最后落 common。

```text
generic safety predicate > dedicated capability predicate > common static key
```

三层顺序不可交换：先构造 common 再判断 generic 会产生非法 mask offset；只按 shape 进入 dedicated 会绕过 FD/section 完整性门。

### T-002：dense boundary 把 stride 复杂度挡在 Device 外

Host 对 Q/K/V 独立调用 `.contiguous()`，Device 所有 BSND offset 共享稠密公式；dense 输入不复制，非 dense 输入付一次框架拷贝。输出新分配为 dense，不保留输入 strides。

迁移时须同时保留临时 Tensor 的 stream-aware completion-owner 契约、current-stream allocator 语义与输出 stride 契约；仅保留裸 GM 地址不能代替 owner。

### T-003：preload=2 的 Cube/Vector 软件流水

common 的三槽 task/P ring 与 dedicated 的四槽 RunInfo ring把当前 QK/Vec1 与两任务前的 PV/Vec2 重叠；score/C2 双槽，P 三槽。

```text
task[t]: QK -> Vec1
task[t-2]: PV -> Vec2
P slot=t%3; score/C2 slot=t%2
```

改变 preload、AIC:AIV 比、P 槽数或 flag 周期时必须整体重算。

### T-004：BMM2→UB 与 FP32 online update 消除 common GM workspace

PV 的 FP32 L0C 结果经 Fixpipe 到 cross-core UB，AIV 直接执行 online update，最后一块才除总和并 cast。每个 S2 tile 单独归一化再累加会改变 softmax。

若改为 `bmm2WriteToUb=false`、启用 FD 或 D-split，必须新增 accumOut/logSumExp workspace、owner、offset、归并节点与异常生命周期；output 占位不能当可写 workspace。

### T-005：full/compressed mask 与 signed generic causal 互补

common 的 full/compressed mask 只覆盖 `Sq<=Skv`；generic 用 int64 表达 `qPos+Skv-Sq`，允许负边界并显式处理全掩行。compressed 必须成对切换 producer 几何和 consumer offset。

任意用户 mask、左上 causal、band/tree/prefix 语义均不在本卡。

### T-006：64 MiB row-chunk workspace 形成确定性安全兜底

generic 不扩展 K/V heads，只按 `hkv=hq/G` 索引；workspace 随 `workspaceRows*Skv*4` 有界，并在 stream 序列中跨 chunk 复用。代价是 QK、softmax、PV 都通过 GM 和标量 SIMT 循环，定位是合法域闭合而非 Cube 路线替代品。

## 失败边界

- 只接受 FP16/BF16、D 为 64 的倍数且位于 `[64,512]`；其它输入在 Host 拒绝，不存在隐式 dtype/D fallback。
- B/S/head 上界和关键乘积先验证；不能删掉 `__int128` 检查后依赖 Device int64/uint32 回绕。
- common causal 仅在 `Sq<=Skv` 可达；`Sq>Skv` 必须保持 generic signed 几何和全掩行 P 置零。只有对应 V 为 finite 时才承诺 output 精确零，NaN/Inf 可经 `0*V` 传播。
- dedicated 仅接收 D128、non-causal、square、`Sq>=256`，并通过 one-section/no-FD gate；gate miss 回 common。
- generic workspace 分配失败在节点提交前传播；common causal mask 分配失败也在 mask launch 前传播。
- `scaleValue` 的 NaN/Inf 未拒绝；需要有限数语义时应在 Host 新增校验，不能依赖 `<=0` 默认分支。
- PSE、RoPE、PA、prefix、actual-seq、量化、dropout、LSE、FD 和任意 attention mask 都没有 Direct producer/完整节点图。
- launcher 不检查异步错误；同 stream 保证本调用内部顺序，不替代跨 stream 或 Host 读取前的同步。

## 实现复用检查

| 检查项 | 必须一起迁移的关系 | 常见破坏方式 |
|---|---|---|
| selector | generic 短路→dedicated gate→common key | 恢复 batch 白名单、漏掉 `Sq>=256`、让 `Sq>Skv` 进入 uint32 mask |
| stride | Validate→contiguous Q/K/V→dense output | 声称保留 input stride，或让某一输入绕过稠密化 |
| common POD | base/mask/workspace/S1-outer/metadata producer与同版 consumer | 只复制 active 字段而未零初始化 inactive storage |
| dedicated POD | one-section FA cursor、coreNum、no-FD/no-mask/no-preclear | 只检查 shape，不检查 SectionStreamK 最终结果 |
| common memory | L1 P triple、score/C2 UB double、preload=2、flag cycle | P 双缓冲或不同步改 task ring |
| generic memory | `workspaceRows` 公式、三节点 stream 顺序、chunk overwrite | score 未被 output 消费即覆写，或按 Nq 展开 K/V |
| precision | FP32 QK/max/sum/exp/PV，末端 cast；全掩行 P 零，finite V 时 output 精确零 | 每 S2 tile 独立归一化、半精度累加、`0/0` 全掩行、忽略非有限 V 传播 |
| tail/mask | M/S2/chunk/element tail；full/compressed/signed causal 各闭合 | producer/consumer mask 几何混搭，padding 进入 softmax |
