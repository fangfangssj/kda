# GRU 950 Direct Invoke 算子知识

## 算子速览

| 项目 | 内容 |
|---|---|
| 入口 | `cann_bench::gru` → Meta `gru_meta` / PrivateUse1 `gru_npu` → `OpCommand::RunOpApi("GruDirect", directCall)` → `launch_gru_*`。 |
| 语义 | reset/update/new 三门、reset-after 形式；按 layer→direction→timestep 递推，产出完整序列 `y` 与末状态 `hn`。 |
| dtype/layout | FP16、BF16、FP32；所有 Tensor 必须同设备、同 dtype、contiguous ND。 |
| Route | 七条可达叶子：Wide Strict、Raw Strict、Accurate FP16、Persistent Cooperative、Persistent Serial、Staged FP32-internal Vector、Staged normal FP16 Vector。 |
| 核任务 | Wide/Raw/Accurate/Persistent 为 AIV wrapper 内 SIMT；Staged 路线用 AIC Cube GEMM 与 AIV Vector；pack/cast/transpose/gather 是 AIV。 |
| 内存层级 | Host Tensor 负责 GM 与生命周期；Cube 使用 L1/L0A/L0B/L0C；Vector 使用动态 UB；SIMT recurrence 使用静态 UB state/partial 数组。无 workspace 形参、atomic、NDDMA 或跨卡通信。 |
| 来源性质 | `direct_implementation_closed`。Direct Host、selector、POD、launcher 和 Device body来自固定单版本转换源码；固定 HTTP 来源只支撑 GRU 属性、950 MatMul/Cube 范式和构建映射，不把转换代码称作官方原生 GRU。 |

## 来源与转换关系

固定官方 `gru_onnx_plugin.cpp` 只给出 `CommonGRU` 属性映射，`experimental/rnn/CMakeLists.txt` 只给出 RNN 构建边界；固定提交中没有与本卡同构的 GRU Direct Host/Tiling/Device 链。`block_mmad.h`、arch35 `batch_mat_mul_v3.cpp` 和 Ascend 950 binary 配置只证明相关 950 Cube/MatMul 编程范式。

以下事实属于 Direct 转换实现，而非上述文件的逐字实现：

- PyTorch schema、Meta、PrivateUse1 注册、current-stream callback 与 Tensor capture；
- Host selector 的阈值、七条 Route、所有 workspace 公式和 `GemmExTilingData` 生产；
- `GruWide` 双 FP32 展开、Kahan、persistent cooperative reduction、Cube→Vector 分图及其同步；
- `gru_launch.h` 的 C ABI 和 `register_direct_launch_op` 接线。

转换源码闭包由 `source/gru/CMakeLists.txt`、`op_plugin/gru_plugin.cpp`、`op_kernel/gru_launch.h`、`gru_tiling_data.h` 与 `gru_kernel.cpp` 组成。`gru.txt` 是这四段可编译载荷的字符串封装；知识消费应以解包后的源码符号为准。本文不把固定 HTTP 相关映射外推为 Direct 路线的语义、精度或性能证明。

## 接口与门控状态

### Schema、输入与输出

```text
gru(x, weight_ih[], weight_hh[], inputSize, hiddenSize, numLayers,
    bias=True, batchFirst=False, dropout=0.0, bidirectional=False,
    bias_ih=None, bias_hh=None, h0=None) -> (y, hn)
```

令 `S=sequence`、`B=batch`、`I=inputSize`、`H=hiddenSize`、`D=1/2`、`L=numLayers`、`G=3H`、`R=SB`、`Q=RG`、`Qh=BG`、`O=R·D·H`。

| 对象 | shape/layout | 约束与语义 |
|---|---|---|
| `x` | `[S,B,I]` 或 batch-first `[B,S,I]` | rank 3，末维必须等于 `I`。 |
| `weight_ih[lD+d]` | 至少 `[G,I_l]`，`I_0=I`,`I_l=DH` | 允许多余行/列；Raw/Wide 读取逻辑行和物理 row stride，Cube 路线要求有效前缀紧凑。 |
| `weight_hh[lD+d]` | 至少 `[G,H]` | 同上。 |
| `bias_ih/bias_hh` | 各项至少 `[G]` | 只有 `bias=true` 且两表都提供时消费；任一缺省时两套 bias 都按零。 |
| `h0` | `[LD,B,H]` | 可缺省，缺省时 state 为零。 |
| `y` | `[S,B,DH]` 或 `[B,S,DH]` | direction 只改变递推顺序；写回仍使用逻辑 timestep。 |
| `hn` | `[LD,B,H]` | 每个 layer/direction 的最终递推状态。 |

### 数学顺序

权重按 `r,z,n` 三段解释；实现刻意保持 `h=n+z*(h_prev-n)` 的求值顺序：

```text
i_r,i_z,i_n = x_t W_ih^T
h_r,h_z,h_n = h_(t-1) W_hh^T
r = sigmoid(i_r+h_r+b_ir+b_hr)
z = sigmoid(i_z+h_z+b_iz+b_hz)
n = tanh(i_n+b_in+r*(h_n+b_hn))
h = n+z*(h_prev-n)
```

反向 direction 的 `timestep=S-1-step`，但 `y` offset 仍按该逻辑 `timestep`。多层时上一层的 `D·H` 输出成为下一层输入。Wide Route 在中间层另存 hi/lo，不把中间状态先压回公开 dtype。

`dropout` 只校验 `[0,1]`，Device 图没有 dropout 节点；因此这里只闭合推理态门控语义，不能复用为训练态非零 dropout 实现。

## Host、selector 与生命周期

### Host 校验和边界

`CheckInputs` 在任何分配或 launch 前检查：

- Tensor 已定义、同设备、同 dtype、strided contiguous；dtype 仅 FP16/BF16/FP32；
- `I,H,L,S,B>0`，`S≤1024,B≤256,I≤1024,H≤1024,L≤8`；`G`、`R`、workspace 元素积及 direct 参数收窄无溢出；
- 权重/bias 列表至少 `LD` 项，多余项忽略；每个逻辑前缀 shape 足够；
- `h0` 必须精确为 `[LD,B,H]`；`dropout∈[0,1]`。

非法 shape/dtype/layout 在 Host `TORCH_CHECK` 失败，不存在 Device 内 shape fallback。

### selector 定义

令 `exactW` 表示每个有效权重恰为 `[G,I_l]` 和 `[G,H]`，`E=64·1024·1024` 个 gate 元素：

```text
strictPersistent = dtype∈{FP32,BF16} && H<=128 && exactW && Q<=E
fp16Persistent   = dtype==FP16 && H<=128 && exactW && Q<=E

wideHalfRecovery = dtype∈{FP16,BF16} &&
                   ((L>1 && (D>1 || H>=128)) || (dtype==FP16 && H==256))
wideRoute = H<=256 && Q<=E/2 &&
            ((dtype==FP32 && H>32) ||
             (dtype==FP16 && H==127) || wideHalfRecovery)

strictRoute = H<=1024 &&
  (wideRoute ||
   (!strictPersistent && dtype∈{FP32,BF16}) ||
   !exactW || S>200 || B>32 || I>512 || H>256 || L>3)

accurateRoute = !strictRoute && dtype==FP16 && S*H>=32768 &&
                L==1 && D==1 && H<=256
fp32Internal  = !strictRoute && dtype==FP16 && S*H>=32768 && !accurateRoute
persistentRoute = !strictRoute && (H<=32 || strictPersistent || fp16Persistent)
fp32Gates = wideRoute || fp32Internal || persistentRoute || accurateRoute
streamed = !accurateRoute && !persistentRoute && Q*gateBytes>256MiB
```

### Route 判定顺序与重要性排序

Route ID 表示可达叶子；P0～P6 是知识复用价值顺序，不改变源码短路顺序。

| 优先级 | Route | 完整叶子条件 | 关键价值 |
|---:|---|---|---|
| P0 | R-001 Wide Strict | `wideRoute`；必有 `strictRoute` | hi/lo 跨 timestep、跨层保持，闭合最复杂的门控状态与 GM 交接。 |
| P1 | R-002 Raw Strict | `strictRoute && !wideRoute` | 读取原始 stride，覆盖 padding、宽/长/大 batch 和非 Wide 的 FP32/BF16。 |
| P2 | R-004 Persistent Cooperative | `!strict && !accurate && persistent && H>=16` | Cube 输入投影后由单 block 持有整段 recurrence，多 lane 分摊 H×H dot。 |
| P3 | R-003 Accurate FP16 | `accurateRoute` | 输入与循环 dot 都保持固定 k 顺序 Kahan FP32。 |
| P4 | R-007 Staged normal FP16 Vector | `!strict&&!accurate&&!persistent&&!fp32Internal` | 常规 Cube input/recurrent + Vector cell 主干。 |
| P5 | R-006 Staged FP32-internal Vector | `!strict&&!accurate&&!persistent&&fp32Internal` | FP16 ABI 下 gate/state/循环权重保持 FP32。 |
| P6 | R-005 Persistent Serial | `!strict && !accurate && persistent && H<16` | 小 H 由单 lane/hidden 串行 dot；FP32 特化启用 Kahan recurrence。 |

源码 callback 的真实短路顺序为：

```text
for layer:
  select layerInput/layerOutput and wide ping-pong slices
  for direction:
    optionally launch input-weight pack
    if strict:
      wide ? launch_wide_strict : launch_strict
      continue
    if accurate: cast/transpose/accurate-input/accurate-recurrence; continue
    if !streamed: launch full input Cube GEMM
    optionally pack recurrent weight
    if persistent: transpose recurrent weight; launch persistent; continue
    optionally cast recurrent weight to FP32
    init state
    for step: optional gather/input GEMM; recurrent GEMM; cell
```

注意 input-weight pack 位于 strict 短路之前：若 `!exactW` 触发 Strict，Host 仍会执行 pack，但 Strict/Wide 实际传 `wiSource` 和物理 stride，pack 结果不参与该 Route。recurrent pack 位于 Strict 之后，所以 Strict 不启动它。

### 不可达分支证明

源码保留 streamed 和 staged SIMT launcher，但当前 Host 合同下不形成额外 Route：

- `!strictRoute` 蕴含 `S≤200,B≤32,I≤512,H≤256,L≤3,exactW`，且非 Strict 的 FP32/BF16 会被 persistent 截获；剩余 staged dtype 为 FP16。
- 因而 `Q≤200·32·3·256=4,915,200`，即便 `gateBytes=4` 也小于 256 MiB，`streamedInputGates` 恒假。
- staged cell 的 SIMT 条件是 `dtype!=FP16 || H>256`；上述非 Strict staged 域同时否定两项，故恒走 Vector。

`launch_gru_gather_timestep`、`GruCellSimt` 和 BF16/FP32 Vector entry 是构建内保留能力，不得写成当前 selector 的可达 Route。alpha/beta post-process 同样没有 GRU 调用边。

## POD、Tiling 与 launch ABI

### `GemmExTilingData`

唯一按值传入 Cube entry 的命名 POD 为 `GemmExTilingData`，21 个 32-bit 字段，自然布局 `alignof=4,sizeof=84`：

| offset | 字段 | Host producer | Device consumer / 状态 |
|---:|---|---|---|
| 0/4/8 | `m,n,k` | `CalcGruGemmTiling` | core extent、M/N/K loops。 |
| 12/16/20 | `lda,ldb,ldc` | 固定为 `k,k,n` | GM offset 与 Fixpipe dst stride。 |
| 24/28/32 | `usedCoreNum,mBlocks,nBlocks` | AIC core 搜索 | block guard 与 block→M/N 映射。 |
| 36/40 | `singleCoreM,singleCoreN` | base 对齐后 clamp | 每核有效矩形。 |
| 44/48/52/56 | `baseM,baseN,baseK,c0Size` | dtype 选择 | Device entry 实际由模板常量控制；字段仅保留记录。 |
| 60/64 | `isTransA,isTransB` | `0,1` | A/B load 方向；B 物理存 `[N,K]`。 |
| 68/72/76 | `alpha,beta,hasBeta` | `1,0,0` | GRU Cube body不读；仅 dormant alpha/beta 路线消费。 |
| 80 | `outputFp32` | `0` | entry 由 launcher 的 dtype case 选择，字段不参与选择。 |

`gru_tiling_data.h` 声明同名 POD，但当前 `gru_kernel.cpp` 自含一份定义，plugin 只 include `gru_launch.h`；该 header 不在编译依赖链上。修改字段时必须同步两份定义并重新核 ABI，不能把 header 的注释值当作运行时生产者。

其它 entry 直接传 GM 指针、`uint32_t` 与 C++ `bool`，没有共享 tiling GM：

- `weightIhStride/weightHhStride` 只供 Raw/Wide 读取原始逻辑前缀；
- `inputWide/outputWide` 只供 Wide 的层间 hi/lo 交接；
- `compactInputGates` 在当前可达 staged Route 固定 false；
- `writeHn` 只在逐步 staged 的最后一次 launch 为 true。

### Cube 分核与 tile

`launch_gru_gemm` 生成 `M×N = [M,K]·[N,K]^T`：

| dtype / output | template tile `(BM,BK,BN,C0)` | Fixpipe |
|---|---|---|
| FP16→FP16 | `(128,16,128,16)` | `F322F16` |
| BF16→BF16 | `(128,16,128,16)` | `F322BF16` |
| FP16/BF16→FP32 | `(128,16,128,16)` | `NoQuant` |
| FP32→FP32 | `(32,8,16,8)` | `NoQuant` |

Host 枚举 `mb=1..min(ceil(M/BM),AIC)`，取 `nb=min(ceil(N/BN),AIC/mb)` 并最大化 `mb·nb`。每核 `singleCoreM/N` 向 base 对齐后 clamp 到实际维度。Device 再令同时驻留的 C0 tile 数不超过 `256KiB/(BM·BN·4)`，较大维先二分。

### blockDim、stream 与错误边界

| 节点 | blockDim / threads |
|---|---|
| Cube GEMM | `usedCoreNum` AIC；模板 entry。 |
| Wide input / Accurate input | `min(AIV cores,R)` blocks，256 threads。 |
| Wide/Raw/Accurate recurrence | `B` blocks；32/64/128/256 或固定 256 threads。 |
| Persistent | `B` blocks；serial 32～128，cooperative `lanes·H≤256`。 |
| init/cell Vector | `B` blocks；一 block 对应一个 batch row。 |
| pack/transpose | `ceil(elements/256)` blocks；cast 为 `ceil(elements/4096)`。 |

所有 launch 使用 `getCurrentNPUStream().stream(false)`。Tensor、权重表、输出与全部 workspace 被 callback capture 保活；跨 kernel GM 可见性依赖同一 stream 的提交顺序。launcher 返回 `void`，callback 固定返回 0，没有逐 launch 状态、event 或 Host 同步；异步错误由 runtime/framework 处理。

## Workspace、内存层级与复用

### Host workspace 公式

令 `e=sizeof(dtype)`，`Nbuf=0(L=1),1(L=2),2(L≥3)`，`Imax=max(I,DH)`：

| Tensor | 元素数 / dtype | 路线与 offset |
|---|---|---|
| `gateWorkspace` Wide | `2Q` FP32 | hi `[0,Q)`，lo `[Q,2Q)`；无 hidden-gate slice。 |
| `gateWorkspace` Raw Strict | 1 个输入 dtype元素 | 占位，不消费。 |
| `gateWorkspace` Accurate/Persistent | `Q+Qh` FP32 | input gate `[0,Q)`；hidden slice已分配但两 Route 不消费。 |
| `gateWorkspace` staged | `Q+Qh`，gate dtype | input `[0,Q)`，hidden `[Q,Q+Qh)`。 |
| `stateWorkspace` Strict | 1 个输入 dtype元素 | 占位。 |
| `stateWorkspace` 非 Strict | Host 固定分配 `B·H`，dtype 为 `fp32Internal?FP32:input dtype` | Accurate/Persistent 因 `fp32Internal=false` 实际分配 `B·H·e` 字节但 body 不消费；只有 staged 的 init/cell 原地消费并按方向复用。 |
| `layerWorkspace` | `max(1,Nbuf·O)` 输入 dtype | 非最终层 ping-pong；Wide 中间层分配但其普通值不被下一层消费。 |
| `wideLayerWorkspace` | Wide 为 `2·max(1,Nbuf)·O` FP32，否则 1 FP32 | 每个 ping-pong buffer含 hi/lo 两个 `O` slice。 |
| `recurrentWeightWorkspace` | 需 FP32循环权重时 `G·H` FP32，否则 1 | Accurate/Persistent/FP32-internal。 |
| input/recurrent pack | 需要时 `G·Imax·e` / `G·H·e` | 每 layer/direction 顺序复用；否则 Tensor 别名 `x`。 |
| timestep input | streamed 时 `B·Imax·e`，否则别名 `x` | 当前 selector 下不消费。 |
| accurate | Accurate 时 `(R·I+G·I)` FP32，否则 1 | FP32 `x` slice + 转置 input-weight slice；Accurate 仅 L1。 |

Wide 中 `wideLayerBuffers=max(1,Nbuf)`，因此单层也分配 `2O` FP32，虽 `inputWide=false,outputWide=false` 时该层间区不被 Device 读写。多层 Wide 按 layer 奇偶复用 hi/lo buffer；同一 layer 的两个 direction 写 `D·H` 的不重叠 slice。

### Cube 本地内存

```text
GM A/B ND
  -> L1 A1@0 / B1@16KiB
  -> L0A/L0B
  -> Mmad FP32 L0C
  -> Fixpipe row-major GM gate
```

- L1 地址空间 32 KiB，A1/B1 各用半区 view；FP16/BF16 活跃 tile 各 4096 B，FP32 A/B 分别 1024/512 B。
- L0A/L0B 与 tile 相同量级；L0C 总驻留由 256 KiB guard 控制。
- `DataCopy(Nd2Nz)`、`LoadData`、Mmad block 写出前后使用 `PipeBarrier<PIPE_ALL>`。
- M/N/K tail 分别用 `actualM/N`、`tailM/NAlign` 与末 `curK`；Fixpipe 只写 `curM×curN`。

### 跨 kernel 复用边

| 边 | producer → consumer | 安全条件 |
|---|---|---|
| Wide input gates | wide-input hi/lo → wide recurrence | 同 stream；每方向完整生产后消费，之后可覆盖。 |
| Wide layer state | layer `l` hi/lo → layer `l+1` wide-input | `outputWide/inputWide` 成对，ping-pong slice在下一层完成前不复用。 |
| Persistent gate | input Cube FP32 → persistent | Cube 完成后启动；persistent 内部独占整段 S。 |
| staged hidden gate | recurrent Cube → cell → 下一 timestep覆盖 | 同 stream 严格串行。 |
| staged state | init/cell → next recurrent Cube | 同 stream；一方向完成后才供下一方向复用。 |
| Accurate transformed buffers | cast/transpose → Kahan input/recurrence | producer 完整结束后消费。 |

## Route R-001（P0）：Wide Strict

### 选择、调用链与伪码

条件为 `wideRoute`。该条件先令 `strictRoute=true`，所以 callback 第一分支直接调用：

```text
launch_gru_wide_strict
  -> gru_wide_input_kernel / GruWideInputSimt<T>
  -> gru_wide_strict_kernel / GruWideStrictSimt<T>
```

```text
for layer,direction:
  parallel for row, hidden-group:
    inputGateWide[r,g] = sum_wide_k(layerInputWide_or_T * weight_ih)
  one block per batch:
    previousWide = h0 or 0
    for step in direction order:
      recurrentWide = grouped_sum_wide_k(previousWide * weight_hh)
      r = wide_sigmoid(inputR + recurrentR + biases)
      z = wide_sigmoid(inputZ + recurrentZ + biases)
      n = wide_tanh(inputN + r*(recurrentN+b_hn) + b_in)
      nextWide = n + z*(previousWide-n)
      if intermediate layer: store hi/lo
      else: store hi+lo to public dtype y
      sync; swap state hi/lo
    store hi+lo to hn
```

### 数值、资源、同步与尾块

`GruWide{hi,lo}` 用 TwoSum、FMA residual、normalize 构成约 48-bit mantissa；乘、加、减、除均保留双分量。`exp` 将输入 clamp 到 `[-40,40]`，以 split-ln2 做 range reduction、12 阶 Horner 后用 `ldexpf` 缩放；sigmoid 由 wide exp/div 组合。`GruWideTanh` 先检查 `hi+lo`：近似值 `>=20` 或 `<=-20` 时直接饱和为 `+1/-1`，只有其余区间才进入 wide exp/div。

输入投影 `H≤64/128/256` 分别用 4/2/1 lanes per hidden，recurrence 相同；partial hi/lo 是各 `3×256` float。输入投影每处理一行有两次 `asc_syncthreads`：partial 写完后一次、owner 合并并写 gate 后一次；recurrence 每 step 有三次：partial 写完后、owner 形成 next 后、owner 写输出后各一次，第三次完成后才交换 state。state 为四个 `256`-float 静态 UB 数组；每 block 的显式 wide UB 约为 state 4096 B + partial 6144 B，不计编译器标量。

`H≤256` 保证 state 数组和 hidden owner；非 32 对齐 H 由 `active/owner` guard 与 group 映射覆盖。row 由 `firstRow+=rowStride` 覆盖，direction/output offset 使用逻辑 timestep。输入权重和循环权重直接按物理 stride 读，padding 不改变逻辑 K 范围。

边界：Wide 只在 `Q≤32M elements` 且 H≤256；不满足则由 R-002 Raw Strict 或非 Strict 路线承接。没有 Device 内降级；wide exp 的 clamp 与 tanh 的 `±20` 饱和是函数定义边界，不是 Route fallback。

## Route R-002（P1）：Raw Strict

### 选择、调用链与伪码

条件为 `strictRoute&&!wideRoute`：

```text
gru_npu -> launch_gru_strict -> gru_strict_kernel
        -> GruStrictSimt<half|bfloat16_t|float>
```

```text
one block per batch:
  previous[H] = h0 or 0 in FP32 UB
  for step:
    for hidden lane (stride 256):
      i_r,i_z,i_n = Kahan over logical inputSize using weightIhStride
      h_r,h_z,h_n = Kahan over H using weightHhStride and previous
      next = GRU_gate_equations_in_FP32
    sync
    store every timestep to public dtype y
    sync; swap previous/next
  store hn
```

### 内存、同步、精度与 fallback

每 block 静态 UB 为两个 `1024`-float state 数组，共 8192 B；H 以线程 `hiddenIndex+=256` 关闭宽尾。所有六个 dot 各有 Kahan correction，bias 与激活为 FP32，`y/hn` 每步按 FP16/BF16 RN 或 FP32 写回。多层 Raw Strict 下一层读取普通 `layerWorkspace`，所以中间层在公开 dtype 边界舍入；它不具有 Wide 的跨层 hi/lo 保持。

每步先 `asc_syncthreads` 等待所有 next，再写 y；第二次同步后交换 state，避免部分 lane 读取新旧混合状态。物理 padding 只改变 stride，不改变逻辑 K。H≤1024 由 Host 与静态数组共同约束；更大 H 在 Host 失败。此 Route 是 Wide 条件不成立时的严格原始布局终点，没有后继 Device fallback。

## Route R-003（P3）：Accurate FP16

### 选择、调用链与伪码

叶子条件是 `accurateRoute`，并在任何 Cube input launch 前短路：

```text
cast layerInput FP16->FP32
transpose/promote weight_ih [3H,I] -> [I,3H]
transpose/promote weight_hh [3H,H] -> [H,3H]
GruAccurateInputFp16Simt
GruAccurateFp16Simt
```

```text
parallel rows: each hidden lane Kahan-sums three input dots
one block per batch:
  keep two 256-float FP32 state arrays
  for t=0..S-1:
    Kahan-sum three recurrent dots in fixed k order
    update FP32 state; sync; write y half-rn; swap
  write hn half-rn
```

该 Route 只允许 `L=1,D=1,H≤256`，因此 Accurate recurrence 固定正向，不需要 direction 参数。`!strictRoute` 同时蕴含 `exactW`，源码中的 recurrent-pack 防御分支在此叶子恒假。输入 gate 为 `Q` FP32；hidden gate slice虽被分配但不消费。UB state 2048 B，thread guard 处理 H tail。跨节点依赖同 stream，recurrence 每 timestep 用 `asc_syncthreads`。若 long-FP16 但 L/D 不满足，selector 转到 Wide、Persistent 或 R-006，而不是在 Accurate 内回退。

## Route R-004（P2）：Persistent Cooperative

### 选择、调用链与伪码

叶子条件是 `!strict&&!accurate&&persistent&&H>=16`：

```text
input Cube GEMM [R,I_l]·[3H,I_l]^T -> FP32 inputGates
transpose/promote weight_hh -> FP32 [H,3H]
gru_persistent_kernel -> GruPersistentCoopSimt<T>
```

```text
one block per batch, lanes = H<=32 ? 8 : H<=64 ? 4 : 2
previous[H] = h0 or 0
for step:
  each (hidden,lane) sums k=lane; k<H; k+=lanes for r/z/n
  write three partial arrays; sync
  lane0 reduces lanes in fixed order, forms gates and next[hidden]
  sync; lane0 writes y; swap state
lane0 writes hn
```

FP16/BF16 可达 H 主要为 `[16,128]`（受 Wide 排除项约束）；FP32 只在 `[16,32]` 可达，因为 FP32 H>32 先命中 Wide。`!strictRoute` 保证 `exactW`，所以两个 pack 分支在此叶子均恒假。input gate、转置 recurrent weight 与 recurrence state 都为 FP32，bias/输出保持输入 dtype。

静态 UB 为两块 `128`-float state（1024 B）加三块 `256`-float partial（3072 B），合计约 4096 B。每 step 有 partial producer→owner reduce 与 next producer→下一步 read 两个 block barrier。`lanes·H≤256`，非整除的 k tail 由 strided loop自然覆盖。该 Route 内没有 staged recurrent Cube；H×H dot 在一个持久 block 内完成。

## Route R-005（P6）：Persistent Serial

叶子条件是 `!strict&&!accurate&&persistent&&H<16`，图与 R-004 相同，但 body 为 `GruPersistentSimt`：

```text
one thread owns one hidden output
for step:
  serial k=0..H-1 recurrent r/z/n dot
  FP32 gate/state update
  sync; write y; swap state
write hn
```

FP16/BF16 实例为普通 FP32 accumulation；FP32 实例为 `GruPersistentSimt<float,float,true>`，三个循环 dot 各使用 Kahan correction。UB 只有两块 `128`-float state，约 1024 B；threads 取 32，`hiddenIndex<H` 关闭尾 lane。fallback 只发生在 Host selector：H 达 16 转 R-004，Wide/Strict 条件优先时转 R-001/R-002。

## Route R-006（P5）：Staged FP32-internal Vector

### 选择、调用链与伪码

叶子条件为 `!strict&&!accurate&&!persistent&&fp32Internal`。在当前合同中它只能是 FP16、H≤256、materialized gate：

```text
input Cube FP16×FP16 -> FP32 gates (once)
cast recurrent weight FP16->FP32
init h0 FP16 -> FP32 state
for step:
  recurrent Cube FP32×FP32 -> FP32 hidden gates
  GruCellImpl<half,float,float>
```

```text
state = fp32(h0 or 0)
for timestep in direction order:
  hiddenGates = state * fp32(weight_hh)^T
  Vector UB loads FP32 gates/state and FP16 biases
  next = GRU equations in FP32
  store FP32 state; store FP16 y; final step stores FP16 hn
```

GM gate=`(Q+Qh)·4`，state=`B·H·4`，recurrent weight=`G·H·4`。Vector UB 为两块 `align32(H·2)` raw bias/output、两块 `align32(H·4)` gate/state raw 与五块 `align32(H·4)` FP32 工作区。`LoadAsFloat/StoreFromFloat` 每次 copy/cast 后使用 `PipeBarrier<PIPE_ALL>`；跨 Cube/cell 由 stream 顺序保护。

H tail 由 `DataCopyPad` 的实际 `count=H` 和 Vector count关闭，Cube tail按公共规则。`y/hn` 是唯一每步降回 FP16 的公开边；state 不降精度。若形状触发 Strict/Persistent/Accurate，Host 在更早分支切走；无 Device fallback。

## Route R-007（P4）：Staged normal FP16 Vector

叶子条件为 `!strict&&!accurate&&!persistent&&!fp32Internal`。同样由不可达证明知 dtype=FP16、H≤256、完整 gate 物化：

```text
input Cube FP16 -> FP16 gates (once)
init FP16 state
for step:
  recurrent Cube FP16 -> FP16 hidden gates
  GruCellImpl<half,half,half>
```

cell 把 gate/state/bias load 到 FP32 UB 完成激活与门控，但每步把 state、y 写回 FP16，因此下一 timestep 的 recurrent Cube 读取已舍入状态。GM gate=`(Q+Qh)·2`，state=`B·H·2`；Vector UB 为三块 FP16 raw、一个 FP16 state raw、五块 FP32 工作区，所有大小按 32 B 对齐。

input gate 对所有 `R` 行只算一次；hidden gate `Qh` slice 每步覆盖。方向和层按 Host 循环串行，共享 gate/state/pack workspace。M/N/K、H 和 batch tail分别由 Cube actual extent、Vector count和 `blockDim=B` 闭合。

## 同步、尾块与失败闭包

| 范围 | 同步机制 | 尾块/边界 | 失败或 fallback |
|---|---|---|---|
| Host graph | 同 current stream launch ordering | layer/direction/step 串行，workspace按阶段复用 | `TORCH_CHECK` 只负责输入；launcher无逐节点返回值。 |
| Cube | `PipeBarrier<PIPE_ALL>` | `actualM/N`、align16 tail、末 `curK`、L0C block guard | entry dtype case由 launcher唯一确定；default case不应从合法 Host 到达。 |
| Vector | copy/cast/store barrier | `count=H`，DataCopyPad关闭非32B尾 | H>256 staged 不可达；否则 selector先转 Strict。 |
| SIMT state | `asc_syncthreads` | active/owner/thread-stride guards | 静态 state 上限由 Host H合同和 Route H guard共同保证。 |
| Wide math | deterministic group merge | row stride、hidden group、direction slice | exp clamp；tanh 在近似值 `>=20/<=-20` 时饱和为 `±1`；无内部降精度 Route。 |

不存在跨 block state 共享、atomic 或 device-side global barrier。每个 batch block独占对应 state；direction 通过输出最后一维 slice隔离，layer/direction之间靠 Host stream 顺序而非 Device 同步原语。

## 迁移与修改检查清单

- 改 selector 时同时重证 Route 可达性、streamed/SIMT 不可达证明、workspace dtype/offset 与静态 UB 上限。
- 改 `GemmExTilingData` 时同步 kernel 内定义和 header 镜像，重新核 84 B ABI、entry 按值参数与 Host producer。
- 改 gate 顺序、state 更新式或激活近似时，同时修改 Wide、Raw、Accurate、Persistent 和 Staged 五个 body 族；它们不是自动共享同一 helper。
- 改多层 Wide 时保持 `inputWide/outputWide` 成对、hi/lo ping-pong和 direction slice；普通 `layerWorkspace` 不是其数值状态来源。
- 改异步调度时必须为所有 GM producer/consumer 添加等价依赖；当前正确性依赖单 stream，不可直接拆到多 stream。
- 不把 dormant launcher当作 fallback；不把相关官方 MatMul映射称为官方 GRU；不宣称 dropout、非连续 layout、H>1024 或未注册 dtype 受支持。
