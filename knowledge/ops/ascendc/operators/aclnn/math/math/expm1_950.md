# Expm1 950 ACLNN 算子知识

## 算子速览

| 项目 | 内容 |
|---|---|
| 实际入口 | `aclnnExpm1GetWorkspaceSize` + `aclnnExpm1`，公开两段式 ACLNN，无版本后缀；本卡不包含 `aclnnInplaceExpm1`。 |
| 计算语义 | 对每个元素计算 `out_i = exp(self_i) - 1`；小输入由专门的 range reduction 与多项式路径避免直接相减的精度损失。 |
| 输入输出 | `self` 与 `out` shape 相同、公开格式 ND；950 ACLNN 输入为 `BOOL/INT64/FLOAT16/BFLOAT16/FLOAT`，核心 `Expm1` 节点只接收同 dtype 的 `FLOAT16/BFLOAT16/FLOAT`，其它输入先转 `FLOAT`，结果再转到可兼容的浮点 `out` dtype。非连续输入/输出由 executor 的 `Contiguous/ViewCopy` 边界处理。 |
| 执行类型 | 单个 Host 可见核心 Kernel 节点；entry 明确为 `KERNEL_TYPE_AIV_ONLY`，GM↔UB 与 DAG 调度在 AIV 上完成，逐 tile 的核心数学由 `asc_vf_call` 启动 1024-thread SIMT VF，故为非 Cube Hybrid（AIV 调度/搬运 + SIMT 计算）。 |
| Kernel 路线 | R-001：FP32 内核存储/计算（key 7）；R-002：FP16/BF16 存储、FP32 计算（key 3/5）。 |
| 核心资源 | GM 输入输出、一个 `TBuf<VECCALC>` tensor pool、MTE2/MTE3 ping-pong 子区、LEVEL_2 临时子区、SIMT 标量寄存器；核心 Tiling 请求 16 MiB workspace，但 `expm1` entry 不解引用 workspace。 |
| 来源闭包 | `source_closed`：公开 ACLNN→executor 图→`l0op::Expm1`→950 Host/Tiling→`EleBaseTilingDataV2`→key 3/5/7→AIV-only entry→ATVOSS DAG/同步/搬运→SIMT VF body→ascend950 构建接线已闭合；通用 `Contiguous/Cast/ViewCopy/CommonOpExecutorRun` 作为框架边界。 |
| 验证状态 | 已完成源码闭包检查；本次知识提取未执行编译、真机、数值或性能测试。 |

## 接口与语义

### 计算语义

令输入逻辑元素数为 `N = product(self.shape)`，对 `0 <= i < N`：

```text
out_i = expm1(self_i) = exp(self_i) - 1
```

核心 Device 运算统一在 FP32 中进行。对 `|x| > 2` 直接采用 `expm1f(x)`；对 `|x| <= 2`，先把 `x` 约化为 `r = x - k*ln(2)`，在 `r` 上计算五阶系数组合的 `r + r^2*P(r)`，再与 `2^k` 合成。`x == 0` 时选择 `x+x`，保留零的符号；约化指数过大/过小时分别钳到 `+inf` 或 `-1`。FP16/BF16 输入先升为 FP32，最终以 `RoundMode::CAST_RINT` 降回外部存储 dtype。

### 输入、输出与属性

| 参数 | shape/layout | dtype | 约束、默认值与语义 |
|---|---|---|---|
| `self` | 与 `out` shape 相同；公开 ND；允许非连续 | 950：`BOOL/INT64/FLOAT16/BFLOAT16/FLOAT` | 非空输入先 `Contiguous`；`BOOL/INT64` 转为 `FLOAT` 后进入核心节点。源码先判空指针、同 shape、输入支持表与结果到 `out` 的可转换性。 |
| `out` | 与 `self` shape 相同；公开 ND；允许非连续 | 公开文档列 `FLOAT16/BFLOAT16/FLOAT/FLOAT64` | 核心节点产物经过 `l0op::Cast(..., out->GetDataType())`，再 `ViewCopy` 到用户 tensor。头文件注释未列 `FLOAT64`，但公开接口文档列出；以公开文档和实际通用 Cast 检查为准，并在限制中保留该源码差异。 |
| `workspaceSize` | 标量输出 | `uint64_t*` | 空 tensor 路径写 0；非空路径由 executor 汇总各节点 workspace，核心 Expm1 Tiling 固定请求 16 MiB。 |
| `executor` | Host 对象 | `aclOpExecutor**` | 第一段接口创建并移交；包含前处理、核心节点、后处理的执行序列。 |
| `workspace` | Device 地址 | 字节区 | 第二段接口传给 `CommonOpExecutorRun`；大小必须使用第一段返回值。 |
| `stream` | ACL runtime stream | `aclrtStream` | 第二段在该 stream 上执行 executor；节点失败按 executor 框架终止后续节点。 |

### 入口与版本

公开版本族只有无后缀 `aclnnExpm1GetWorkspaceSize/aclnnExpm1`，固定仓没有更高版本号入口。第一段在 `aclnnExpm1Common` 中组装：`Contiguous`→条件输入 `Cast`→`l0op::Expm1`→输出 `Cast`→`ViewCopy`；第二段直接调用 `CommonOpExecutorRun`。`l0op::Expm1` 在 950 的 `IsRegBase()` 分支允许 FP16/BF16/FP32，并以 `ADD_TO_LAUNCHER_LIST_AICORE(Expm1, ...)` 添加核心节点。本卡明确排除同文件中的原地入口。

## Host/Launcher 执行流程

### 参数校验与前处理

1. `CREATE_EXECUTOR()` 失败返回 `ACLNN_ERR_INNER_CREATE_EXECUTOR`。
2. `CheckParamsExpm1` 依次检查 `self/out` 非空、view shape 相同、`self` 位于 950 支持表并且计算结果可 Cast 到 `out`；失败分别返回空指针或参数非法。
3. `self->IsEmpty()` 时直接令 `workspaceSize=0`、移交空执行器并成功返回；不会到达核心 Tiling 对零维的拒绝路径。
4. storage format 非 ND 仅记录 warning；之后无条件调用框架 `l0op::Contiguous`，具体是别名返回还是产生搬运节点由框架决定。
5. `self` 为 `INT64/BOOL` 时插入输入 `Cast(..., DT_FLOAT)`；已有浮点输入保持原 dtype。
6. `l0op::Expm1` 校验核心 dtype，按输入 view shape/dtype 分配连续临时输出，并添加 `Expm1` AICore launcher 节点。
7. 核心结果再 Cast 到用户 `out` dtype，最后 `ViewCopy` 写入可能非连续的 `out`；任一返回空指针即中止组图。

### 参数、Workspace 与生命周期

核心 `Expm1Tiling::SetTilingData` 把 `currentWorkspace[0]` 固定写成 `16,777,216 B`。该核心 entry 的 `workspace` 形参未被读取，因此这 16 MiB 是算子框架/Ascend API 保留协议，不是 body 中可见的切片。ACLNN 第一段返回的是整个 executor 的 `GetWorkspaceSize()`，还可能包含 `Contiguous/Cast/ViewCopy` 的临时 tensor；其汇总对齐与各框架节点切片在固定算子仓不可见，不得用 16 MiB 直接替代 ACLNN 总 workspace。

executor 拥有组图产生的临时 tensor 与 launch 描述，用户拥有 `self/out` 和第二段传入的 workspace。第二段执行期间所有对象必须保持有效；stream 上的框架顺序保证前一节点产物在后一节点消费前可见。第一段任何检查/建图失败不会返回可执行的完整图；第二段 `CommonOpExecutorRun` 的失败状态直接向调用者传播。

### 启动图与失败传播

```text
aclnnExpm1GetWorkspaceSize
  -> Contiguous(self)                         # 框架边界；可能消除
  -> [self 非浮点] Cast(selfContiguous, FP32) # 框架边界；条件节点
  -> l0op::Expm1
       -> ADD_TO_LAUNCHER_LIST_AICORE(Expm1)
       -> Tiling4Expm1 / Expm1Tiling::RunTiling
       -> expm1<schMode=1,dType>(x,y,workspace,tiling)  # 唯一核心 Device 节点 K0
  -> Cast(expm1Result, out.dtype)              # 框架边界；可能消除
  -> ViewCopy(outCasted, out)                  # 框架边界；可能消除
aclnnExpm1(workspace, size, executor, stream)
  -> CommonOpExecutorRun(..., stream)
```

| 节点/边 | Host 添加/入口 | block/grid/POD | 输入→输出或交接介质 | ordering、owner/lifetime 与失败 |
|---|---|---|---|---|
| 前处理边界 | `aclnnExpm1Common` 的 `Contiguous` 与条件 `Cast` | 框架决定 | 用户 `self`→连续浮点临时 tensor | executor 持有临时 tensor；空指针返回会阻断 K0。具体 kernel/workspace 固定仓不可见。 |
| K0 `Expm1` | `Expm1AiCore`→`ADD_TO_LAUNCHER_LIST_AICORE` | `blockDim=tiling.blockNum`；`EleBaseTilingDataV2`；key 3/5/7 | 连续 `x` GM→连续 `y` GM；workspace 形参存在但 body 不使用 | 与前后节点在同 executor/stream 有序；Tiling 或 launch 失败阻断后处理。临时 `y` 由 executor 持有到后处理完成。 |
| 后处理边界 | `l0op::Cast`→`l0op::ViewCopy` | 框架决定 | K0 连续结果→目标 dtype 连续临时→用户 `out` view | executor/stream 顺序；失败返回空指针或第二段运行错误。具体 kernel/workspace 固定仓不可见。 |

## Route 与参数设计

### 分核与资源计算

记 `n=product(storageShape)`，平台 AIV 数为 `C`，平台 UB 字节数为 `U`。ATVOSS 的共同推导如下，所有长度均为元素数，只有显式标注的量是字节：

```text
extra = ASCEND_API_BUFFER + DCACHE_SIZE = 122880 + 32768 = 155648 B
minBits = 32 (FP32 route) 或 16 (FP16/BF16 route)
maxBits = 32                         # DAG 的中间计算均可能是 FP32
B = OpDag::BufferNum = 4 (FP32) 或 6 (FP16/BF16)

coreNum = min(C, ceil(n * minBits / 32768))
blockFormer = align_up(ceil(n / coreNum), 512)
blockNum = ceil(n / blockFormer)
blockTail = n - (blockNum - 1) * blockFormer

alignFactor = 256 * 8 / minBits      # FP32 为 64 元素；16-bit 为 128 元素
ubFormer = align_down(floor((U-extra)*8/(B*maxBits)), alignFactor)
loopFormer = ceil(blockFormer / ubFormer)
loopTail = ceil(blockTail / ubFormer)
tailFormer = blockFormer - (loopFormer-1)*ubFormer
tailTail = blockTail - (loopTail-1)*ubFormer
```

`coreNum==0`、`U<extra` 或对齐后 `ubFormer==0` 均失败；当 `U==extra` 时也会因 `ubFormer==0` 失败，因此成功路线实际要求 `U>extra` 且留存空间足以形成一个对齐 tile。Host 下发 `blockDim=blockNum`，而 POD 中也保留候选 `coreNum`；Device 实际只启动 `blockNum` 个 AIV block。每个 block 的 GM 基址为 `blockFormer * blockIdx * sizeof(UType)`，block 内用 `ubFormer` 做整 tile，最后一次用相应 `tail*`。Host 另设置 `localMemorySize = uint32_t(U-32768)`，固定源码没有显式检查 `U>=32768` 或 uint32 窄化。

### Route 选择

| 顺序 | Route | Key/模板 | 精确选择条件与优先级 | 不适用去向 |
|---:|---|---|---|---|
| 1 | R-001 FP32 存储/计算 | key 7；`expm1<1,TPL_FP32>`；`Expm1DAG<float>` | 核心节点输入/输出 dtype 均为 `DT_FLOAT`。ACLNN 的 `FLOAT` 输入以及先转 FP32 的 `INT64/BOOL` 均落到此路线。 | 非 FP32 转 R-002；其它 dtype 在 `CalcInputDtype/IsAiCoreSupport` 失败。 |
| 2 | R-002 16-bit 存储、FP32 计算 | key 3：`expm1<1,TPL_FP16>`；key 5：`expm1<1,TPL_BF16>` | 核心节点输入/输出分别同为 `DT_FLOAT16` 或 `DT_BF16`；950 `IsRegBase()` 允许 BF16。两 key 的 DAG、分核、内存与 SIMT body 相同，仅外部存储/cast 类型不同。 | 无其它 Kernel fallback；非法 dtype/shape/资源返回 `GRAPH_FAILED`。 |

```text
if input dtype not in {FP16, BF16, FP32}: GRAPH_FAILED
if output dtype != input dtype: GRAPH_FAILED
if input storage shape != output storage shape: GRAPH_FAILED
DoTiling<Expm1DAG<dtype>>; failure -> GRAPH_FAILED
scheMode = 1
if dtype == FP16: dType=1 -> key = 1 + (1<<1) = 3 -> R-002
else if dtype == BF16: dType=2 -> key = 1 + (2<<1) = 5 -> R-002
else: dType=3 -> key = 1 + (3<<1) = 7 -> R-001
```

### 隐藏性能 Guard

| Guard | Host/Tiling 条件 | Device/资源原因 | 影响 Route | 不满足时去向 | 源码符号 |
|---|---|---|---|---|---|

| local memory 窄化 | `SetLocalMemorySize(uint32_t(U-32768))` | 为 SIMT/Vector runtime 下发 DCache 之外的本地内存上限 | 全部 | 固定源码无下溢/超过 uint32 的显式 guard | `Expm1Tiling::SetTilingData` |

### POD/ABI

`EleBaseTilingDataV2` 是 `EleBaseTilingData` 的别名。按字段声明与标准对齐，其 ABI 为 `sizeof=80 B`、`alignof=8 B`；Host 用 `GetTilingData<EleBaseTilingDataV2>()` 写入，Device 用 `REGISTER_TILING_DEFAULT/GET_TILING_DATA_WITH_STRUCT` 以同一结构解析。

## Kernel 实现

### 公共执行流程

核心 launch 只有 K0。entry 解析 `EleBaseTilingDataV2`，声明 `KERNEL_TYPE_AIV_ONLY`，创建一个 `TPipe`，按编译期 `dType` 构造相应 `ElementwiseSch<schMode,Expm1DAG<U>::OpDag>`。scheduler 把当前 AIV block 的 GM 基址绑定到 `x/y`，一次性初始化 `TBuf<VECCALC>` tensor pool，然后对每个 tile 依 DAG 顺序执行 CopyIn、必要的 U→FP32 Cast、SIMT `Expm1Custom<float>`、必要的 FP32→U Cast、CopyOut。

`asc_vf_call` 是 K0 内部、逐 tile 的同步 VF 计算调用，不是第二个 Host kernel，也不形成 workspace 边。Host 的 `blockDim` 是 AIV block 数；SIMT 仅使用 `threadIdx.x/blockDim.x` 在当前 tile 的 UB 地址上做步长 1024 的循环，无 atomic、barrier、warp cooperative group 或显式 shared 数组。

##### 源码等价伪码

```text
# 伪码；一个 AIV block
coreBase = blockFormer * blockIdx
loopNum = (blockIdx == blockNum-1) ? loopTail : loopFormer
lastLen = (blockIdx == blockNum-1) ? tailTail : tailFormer
tileOffset = 0
for tile in [0, loopNum):
    len = (tile == loopNum-1) ? lastLen : ubFormer
    pp = tile & 1
    src = tensorPool[mte2Slot(pp)]
    dst = tensorPool[mte3Slot(pp)]
    lock MTE2(src); DataCopyPad(src, x + coreBase + tileOffset, 1 block, len*4 B); unlock MTE2(src)
    lock V(src); lock V(dst)
    asc_vf_call 1024 threads:
        for i = threadIdx.x; i < len; i += blockDim.x:
            f0 = expm1f(src[i])
            k0 = roundf(src[i] * INV_LN2)
            k = (abs(src[i]) < 0.41) ? 0 : k0
            r = fma(-k, LN2_HI, src[i]); r = fma(-k, LN2_LO, r)
            q = r + r*r*poly5(r)
            e = exp2f(k == 128 ? 127 : k)
            z = fma(q, e, e-1)
            if k == 128: z += z
            if adjusted_k > 128: z = +inf
            if adjusted_k < -25: z = -1
            if src[i] == 0: z = src[i] + src[i]
            dst[i] = (abs(src[i]) > 2) ? f0 : z
    unlock V(inputs/outputs)
    lock MTE3(dst); DataCopyPad(y + coreBase + tileOffset, dst, 1 block, len*4 B); unlock MTE3(dst)
    tileOffset += ubFormer
```

- 触发条件：每个 FP32 lane；最终 `fabsf(x)>2` 选 `expm1f`，否则选约化/多项式结果；内部还按 `|x|<0.41`、指数 128、指数上下界和零值分支修正。
- Golden 来源：[`math/expm1/op_kernel/arch35/expm1_dag.h:54-65`](../../../../../../../cann-ops-raw/ascendc/ops-math/165d41f02a43a62324b434cb6bda7c533b14da3e/math/expm1/op_kernel/arch35/expm1_dag.h#L54-L65)

**官方源码（固定 Commit 连续逐字摘录）**：

```cpp
for (int64_t i = threadIdx.x; i < totalNum; i += blockDim.x) {
    float f1 = x[i];
    float f0 = expm1f(f1);
    float f2 = f1 * INV_LN2_APPROX;
    float f3 = roundf(f2);
    float f4 = fabsf(f1);
    bool p1 = f4 < LN2_HALF_APPROX;
    float f5 = p1 ? 0.0f : f3;
    float f6 = -f5;
    float f7 = LN2_APPROX;
    float f8 = fmaf(f6, f7, f1);
    float f9 = ONE_MINUS_LN2_APPROX;
```

#### 机制与设计原因

当 x 很小时，直接 `exp(x)-1` 会损失有效位。实现用 `k≈round(x/ln2)` 与两段 ln2 常量产生较小余项 r，再以 FMA 链计算 `r+r²P(r)` 并和 `2^k` 合成，减少减 1 的抵消；`|x|<0.41` 强制 k=0，零值用 `x+x` 保留符号。`|x|>2` 则复用硬件/库 `expm1f`，避免把多项式外推到未设计区间。所有常量与分支均为源码固定值，没有 Host 属性。

#### 迁移边界

- 适用：需要 FP32 中间精度的逐元素 `expm1`，且可在 SIMT lane 中使用 `roundf/fmaf/exp2f/expm1f`。
- 前提：必须完整保留阈值、ln2 高低段、系数顺序、指数 128 特判、上下界与 signed-zero 分支。
- 失效：若平台没有同语义的 SIMT 数学函数或目标 dtype 不是本实现三种浮点存储，需另建实现，不能只替换一条 API。
- 未验证：本次知识提取未执行编译、真机、数值或性能测试。

#### 错误做法

固定仓未提供可验证反例；但源码明确没有把 `exp(x)-1` 当作本路线的等价替代，迁移时不得删除上述小值分支后仍宣称相同精度语义。

### Trick T-002：16-bit 外存与 FP32 SIMT 计算的融合 DAG

#### 触发与源码依据

- 适用 Route：R-002。
- 触发条件：核心 dtype 为 FP16 或 BF16。
- Golden 来源：[`math/expm1/op_kernel/arch35/expm1_dag.h:110-120`](../../../../../../../cann-ops-raw/ascendc/ops-math/165d41f02a43a62324b434cb6bda7c533b14da3e/math/expm1/op_kernel/arch35/expm1_dag.h#L110-L120)

**官方源码（固定 Commit 连续逐字摘录）**：

```cpp
template <typename U, typename T = float>
struct Expm1DAG {
    using OpCopyIn0 = Bind<Vec::CopyIn<U>, Placeholder::In0<U>>;
    using OpCopyIn0Cast = Bind<Vec::Cast<T, U, CAST_MODE_NONE>, OpCopyIn0>;
    using OpResult1 = Bind<Expm1Custom<T>, OpCopyIn0Cast>;
    using OpResultCast = Bind<Vec::Cast<U, T, CAST_MODE_RINT>, OpResult1>;
    using OpCopyOut = Bind<Vec::CopyOut<U>, Placeholder::Out0<U>, OpResultCast>;

    using Outputs = Elems<OpCopyOut>;
    using MemCfg = MemOptCfg<MemLevel::LEVEL_2>;
    using OpDag = DAGSch<Outputs, void, MemCfg>;
```

#### 机制与设计原因

GM 仍只搬运 2 B/元素的 FP16/BF16，但数学函数固定在 FP32 中执行；输出在 CopyOut 前才以 RINT 降精度。Cast、SIMT 运算和 CopyOut 位于同一个 AIV kernel/tile 中，没有把 FP32 中间结果物化到 GM。LEVEL_2 planner 为两段 FP32 中间值分配两个临时 slot，并对输入/输出 DMA 使用 ping-pong，从源码上同时证明精度顺序与 GM 搬运量。

#### 迁移边界

- 适用：外部存储为 16-bit、核心非线性函数需要 FP32 的逐元素链。
- 前提：UB 必须容纳 `6*ubFormer*4 B`，且 Host 必须按 MaxDtypeBytes=4 而不是外存字节数估算。
- 失效：若删除任一 Cast、改变 RINT 或按 2 B 估算所有 slot，会破坏精度或 UB 安全；FP32 route 应采用其 CastNoOp 消除后的 4-slot 图。
- 未验证：本次知识提取未执行编译、真机、数值或性能测试。

#### 错误做法

### Trick T-003：DAG 存活期驱动的 LEVEL_2 slot 复用

#### 触发与源码依据

- 适用 Route：R-001、R-002。
- 触发条件：`Expm1DAG` 固定选择 `MemLevel::LEVEL_2`，scheduler 按编译期 buffer id 与 tile parity 取 slot。
- Golden 来源：[`pkg_inc/op_common/atvoss/elewise/elewise_sch.h:47-51`](https://gitcode.com/cann/opbase/blob/d574f5571391390f8b619c6a134b65c819842318/pkg_inc/op_common/atvoss/elewise/elewise_sch.h#L47-L51)

**官方源码（固定 Commit 连续逐字摘录）**：

```cpp
RUN_LOG("BufferNum: %d, Mte2Num: %d, Mte3Num: %d, BufLevel: %d",
        ElemDag::BufferNum, ElemDag::Mte2Num,
        ElemDag::Mte3Num, ElemDag::BufLevel);
pipePtr->InitBuffer(buf, tilingData->ubFormer * ElemDag::MaxDtypeBytes * ElemDag::BufferNum);
tensorPool = buf.Get<uint8_t>();
blockLen = tilingData->ubFormer * ElemDag::MaxDtypeBytes;
```

#### 机制与设计原因

Host 与 Device 都使用 `OpDag::BufferNum*MaxDtypeBytes`：Host 由它反推最大 tile，Device 用完全相同的乘积初始化单一 tensor pool。FP32 的同 dtype Cast 在 DAG 解析时消除，形成 4-slot 图；16-bit 路线需要两个同时存活的 FP32 临时值，形成 6-slot 图。每个节点通过编译期 buffer id 与 `i&1` parity 选物理子区，Mutex 在 MTE2、V、MTE3 三条 pipe 间保护复用，因此无需为每个语义节点永久分配独立 UB。

#### 迁移边界

- 适用：可静态构图并能证明最后消费者的逐元素融合链。
- 前提：Host 的 `BufferNum/MaxDtypeBytes` 必须与 Device 同一 DAG 实例；增删节点后必须重新计算存活期和 tile 上界。
- 失效：改变 DAG、dtype 或同步关系却沿用旧 `ubFormer` 会导致 slot 重叠或 UB 越界，应重新走 planner。
- 未验证：本次知识提取未执行编译、真机、数值或性能测试。

## 限制与失败边界

- 只覆盖非原地 `aclnnExpm1`；`aclnnInplaceExpm1` 是不同逻辑语义，不得据此卡合并实现。
- A3/A2 虽有公开支持声明，但固定 `ops-math@165d41f02a43a62324b434cb6bda7c533b14da3e` 的 CMake、OpDef 与 binary config 只接 `ascend950`；其 Host/Tiling/Kernel 源码不可见，因此本卡不得外推到 A2/A3，也不生成 `expm1.md`。
- ACLNN 文档列出 `out=FLOAT64`，`aclnn_expm1.h` 的注释仅列 FP16/BF16/FP32；实现依赖通用 Cast 可转换性。该差异不改变核心 950 Expm1 只接收 FP16/BF16/FP32 的事实，复用接口检查时应以公开文档与实际 `CheckDtypeValid` 为准。
- executor 的 `Contiguous/Cast/ViewCopy` 具体 kernel、临时 tensor 切片、对齐和 workspace 汇总算法属于固定仓不可见的框架边界；调用者必须使用第一段返回的总 workspace，不能只申请核心 16 MiB。
- `dim0` 的多维乘法、`blockFormer` 的若干加法、`ubFormer/coreNum` 的 int64→int32 写入和 `SetLocalMemorySize` 的 uint32 窄化都没有算子级显式溢出检查。
- 核心 Tiling 拒绝零 shape dim，但公开 ACLNN 在更早处把空 tensor 作为成功的零 workspace 路径；绕过 ACLNN 调核心 Host/Tiling 时不能假设相同空域行为。
- `schMode=0` 和 dtype 声明表中的模板实例只是编译期声明；当前 Host 的 `GetScheMode()` 恒为 1，正式 Route 只有 key 3/5/7。
- `SetLocalMemorySize(U-32768)` 与逐 tile `asc_vf_call` 之间的 runtime 地址传递、120 KiB `ASCEND_API_BUFFER` 的内部具体消费和每线程寄存器字节数在固定源码中不可见。
- 未执行编译、单元测试、真机、数值或性能测试；源码只证明机制，不证明性能百分比或误差上界。
