# All 950 ACLNN 算子知识

## 算子速览

| 项目 | 内容 |
|---|---|
| 实际入口 | `aclnnAllGetWorkspaceSize` / `aclnnAll`，公开两段式 ACLNN，无版本后缀 |
| 计算语义 | 对 `dim` 指定的轴做逻辑与：输出元素为对应输入集合中所有 `x != 0` 的与；空归约集合的单位元为 `true` |
| 输入输出 | `self` 为 ND、rank 不超过 8、支持非连续；950 API dtype 为 BOOL、UINT8、INT8/16/32/64、FLOAT16/FLOAT/BFLOAT16/DOUBLE；`out` 为 BOOL 或 UINT8 |
| 执行类型 | 空输入为单个 Fill `AIV_VECTOR` 节点或无 Device 节点；非空路线含可选 Cast `AIV_VECTOR`、单个 ReduceAll AIV Kernel（搬入可用 NDDMA）和可选 Cast `AIV_VECTOR`；分组归约是同一 AIV Kernel 内的 workspace 两阶段，不含 Cube/AIC/MIX_CV |
| Kernel 路线 | R-001 空输入真值 Fill；R-002 单阶段 MoveAlign；R-003 单阶段 NDDMA；R-004 分组 MoveAlign；R-005 分组 NDDMA |

| 来源闭包 | `source_closed`：公开 ACLNN→参数归一化→可选 Cast/Fill→ReduceAll Host/Tiling/POD→AIV/NDDMA entry/body→可选 Cast→ViewCopy/executor 已闭合；Contiguous、ViewCopy、executor 与 primitive 内部是明确框架边界 |
| 验证状态 | 已完成源码闭包检查；本次知识提取未执行编译、真机、数值或性能测试。 |

## 接口与语义

### 计算语义

设规范化后的归约轴集合为 `D`，对每个输出坐标 `o`：

```text
out[o] = AND { self[i] != 0 | i 在非归约轴上对应 o，归约轴属于 D }
```

`dim=[]` 不表示“不归约”：L2 用 `getAllDims` 生成 `[0, ..., rank-1]`，即归约全部维度。负轴先按 `dim + rank` 解释，重复轴在 L2 被拒绝。`keepdim=true` 时每个归约轴保留为长度 1，否则删除这些轴。输入为空时 API 不启动 ReduceAll：若输出非空，用标量 1 经 Fill 生成真值，再 `ViewCopy`；若输出也为空，Fill 直接返回空中间 Tensor，不启动 Device。

非空 950 上，FLOAT/FLOAT16/BFLOAT16 保持原 dtype 进入 ReduceAll，DAG 先把每个元素显式正规化为 0/1；其余数值 dtype 先由 Cast 转成 BOOL。ReduceAll 最终写 BOOL；`out=UINT8` 时再做 BOOL→UINT8，`out=BOOL` 时 L0 Cast 直接返回原 Tensor。

### 输入、输出与属性

| 参数 | shape/layout | dtype | 约束、默认值与语义 |
|---|---|---|---|
| `self` | ND；rank `<=8`；允许非连续 | BOOL、UINT8、INT8、INT16、INT32、INT64、FLOAT、FLOAT16、BFLOAT16、DOUBLE | 必填；950 支持 BF16；非空时先 `Contiguous` |
| `dim` | Host `aclIntArray` | 元素为 `int64_t` | 必填；每项属于 `[-rank, rank-1]`，标量按 rank 1 校验；不得重复；空数组展开成全部轴 |
| `keepdim` | Host scalar | bool | 归约轴是否保留为长度 1 |
| `out` | ND；shape 必须等于 L2 推导 shape；允许非连续 | BOOL 或 UINT8 | 必填；最终由 `ViewCopy` 写入调用者 view |
| `workspaceSize` | 标量输出 | `uint64_t*` | executor 全图 workspace，不等于单个 ReduceAll 用户 workspace；第一段写入 |
| `executor` | Host 对象 | `aclOpExecutor**` | 第一段拥有中间 Tensor/launch 列表，第二段消费；创建或子节点失败均不发布 executor |
| `workspace` / `stream` | Device 地址 / runtime stream | `void*` / `aclrtStream` | 第二段把第一段给出的 workspace 与同一 executor 交给 `CommonOpExecutorRun` |

### 入口与版本

固定仓公开入口只有无版本后缀的 `aclnnAllGetWorkspaceSize` / `aclnnAll`。公开文档同时声称 A2、A3 与 950 支持；但本固定源码中的 ReduceAll AICore OpDef 只 `AddConfig("ascend950")`，算子 CMake 只设置 `SUPPORT_COMPUTE_UNIT "ascend950"`，binary JSON 也仅位于 `config/ascend950`。因此本卡仅覆盖源码闭合的 950 最新公开入口；A2/A3 固定源码缺少 ACLNN→Device 的可验证构建接线，未生成无后缀卡。

## Host/Launcher 执行流程

### 参数校验与前处理

`aclnnAllGetWorkspaceSize` 的顺序不可交换：

1. `CheckNotNull` 校验 `self/dim/out`；`CheckDtypeValid` 根据 950/RegBase 选择包含 BF16 的输入列表，并限制 `out` 为 BOOL/UINT8；`CheckFormat` 拒绝私有 storage format。
2. `CheckDim` 对标量按 rank 1 处理，校验范围并用 64 位 bitset 拒绝规范化后重复的轴；`CheckShape` 用同一轴 mask 从后向前置 1 或删除轴，并与 `out->GetViewShape()` 精确比较。
3. 创建 executor；`dim->Size()==0` 时生成全部轴数组。
4. `self->IsEmpty()` 时构造值 1、输出 shape Tensor 和 Fill 节点；Fill 输出为空则无 Device；随后 `ViewCopy`，写 workspaceSize 并返回。
5. 非空时 `Contiguous(self)`。950 的 `DAV_3510` 对 FLOAT/FLOAT16/BFLOAT16 不做前置 Cast；其他 dtype 调用 `Cast(..., DT_BOOL)`，BOOL→BOOL 在 L0 立即返回原 Tensor。
6. `l0op::ReduceAll` 把轴数组转成 INT64 Tensor，按 950 分支分配 BOOL 输出，运行 infer-shape 后用 `ADD_TO_LAUNCHER_LIST_AICORE(ReduceAll, ...)` 添加主节点。
7. 调用 `Cast(allResult, out.dtype)`：BOOL→BOOL 无节点；BOOL→UINT8 命中 950 `CastThrough<uint8_t>`。最后 `ViewCopy` 提交到可能非连续的 `out`。

### 参数、Workspace 与生命周期

executor 拥有 `selfContiguous`、可选 BOOL 输入、axes Tensor、ReduceAll BOOL 输出、可选 UINT8 输出以及空输入 Fill 中间 Tensor；它们从第一段成功返回后存活到第二段执行结束。所有节点由 `CommonOpExecutorRun` 在调用者 `stream` 上按 launcher 列表顺序执行，前一节点失败会阻断后续节点。

ReduceAll Tiling 的 workspace 为：

```text
reduce_user_ws = groupR > 1
    ? vectorCoreNum * align(outSize * maxInputBytes, cacheLineSize)
    : 0
reduce_workspace = 16 MiB system reserve + reduce_user_ws
```

entry 先 `SetSysWorkspace(workspace)`，再以 `GetUserWorkspace(workspace)` 取得用户区；任一指针为空立即返回。分组第一阶段把每个 group/core 的部分结果写用户区，第二阶段在 `SyncAll()` 后从该区归约到输出。单阶段路线不消费用户区，但固定 16 MiB 系统 reserve 仍由 Tiling 上报。Cast、Fill 和 ViewCopy 的 workspace 也由 executor 汇总，故 ACLNN `workspaceSize` 不能用上式单独替代。

### 启动图与失败传播

| ACLNN 条件 | 节点顺序 | 输入→输出 | ordering / owner / failure |
|---|---|---|---|
| `self.IsEmpty && out.IsEmpty` | 无自有 Device 节点；框架 ViewCopy 对空 Tensor 处理 | 空中间 Tensor→`out` | executor 持有对象；第一段构图失败直接返回错误 |
| `self.IsEmpty && !out.IsEmpty` | Fill AIV→ViewCopy | 标量真值+shape→连续真值 Tensor→`out` | 同一 executor/stream；Fill 失败阻断 ViewCopy |
| 非空、输入非 BOOL/FP16/FP32/BF16 | CastDstBool AIV→ReduceAll AIV/NDDMA→可选 CastThrough→ViewCopy | 原 dtype→BOOL→BOOL→BOOL/UINT8→`out` | 中间 Tensor 归 executor；严格 launcher 顺序 |
| 非空、输入 BOOL/FP16/FP32/BF16 | ReduceAll AIV/NDDMA→可选 CastThrough→ViewCopy | BOOL/浮点→BOOL→BOOL/UINT8→`out` | 同上；浮点正规化在 ReduceAll DAG 内完成 |

ReduceAll 自身只有一个 Device launch。R-004/R-005 的“两个阶段”是同一 launch 中所有 AIV core 先写 user workspace、`SyncAll`、再读 workspace，不是两个 Kernel。entry 的 `g_coreType == AIC` 分支立即返回；selector 中 group 条目的 `ASCENDC_TPL_MIX_AIV_1_0` 没有可达 AIC 计算体，故执行族仍为 VV/AIV。

## Route 与参数设计

### 分核与资源计算

通用 Reduce Tiling 先把标量 shape 变为 `{1}`，在真实 shape 前补一个 A 轴 1；删除连续且长度 1 的轴，在非连续断点后补 1，再合并相邻同类 A/R 轴。A 表示保留轴，R 表示归约轴。ACLNN 已先 Contiguous，因此最终 `isContiguous=true`；合并结果映射到 AR、ARA、ARAR、扩展到 8/9 维的交替模式。

资源计算按以下依赖顺序执行：

```text
UB_avail = ubSize - 16 KiB cache - reservedSize
preInputBuffers = 2 * preInput；若 reduceOpPos==1 再乘 2
preRestBuffers = preTempCalc + 2 * preOutput + reservedNode
postBuffers = postInput + postTempCalc + postOutput + 1(result)

basicBlock/resultBlock
  -> cacheLine 切分轴与 step
  -> ubFactorA（非纯 A 最大 512 B 的 A 内域，并保持约 95% 分核率）
  -> ubFactorR（填满 basicBlock，并兼顾约 95% 分核率）
  -> factorA/R total 与 per-core
  -> groupR = ceil(factorRTotalCnt / factorRCntPerCore)
  -> realCore = ceil(A_total/A_per_core) * ceil(R_total/R_per_core)
```

`basicBlock` 向下对齐 `vRegSize`，小于一个 vReg 直接失败；`resultBlock` 在非 A 模式被限制到 `[512 B, 16 KiB]` 且按 cache line 对齐。`groupR>1` 设置 schedule mode 1。`useNddma` 在尾轴 stride 非 1、有效切分超过普通 DMA 的维度能力等条件下置 1；若尾轴足够长或转置后的 A/R 乘积超过 UB block 元素数则保持普通 MoveAlign。

### Route 选择

| 顺序 | Route | Key/模板 | 精确选择条件与优先级 | 不适用去向 |
|---:|---|---|---|---|
| 1 | R-001 空输入真值 Fill | Fill key `101` | API `self->IsEmpty()`；`out` 非空时启动 Fill，`out` 空时无 Device | 非空进入 ReduceAll |
| 2 | R-002 单阶段 MoveAlign | Reduce tuple，normal selector | `groupR==1 && useNddma==0`；tuple 属 AR/ARA/ARAR/ARARARAR/ARARARARA normal 集合 | `useNddma==1`→R-003；`groupR>1`→R-004/5 |
| 3 | R-003 单阶段 NDDMA | 同 normal selector | `groupR==1 && useNddma==1` | 无额外 fallback；Tiling/entry guard 失败则整节点失败 |
| 4 | R-004 分组 MoveAlign | group selector | `groupR>1 && useNddma==0`；`loopRCount>0` | `useNddma==1`→R-005 |
| 5 | R-005 分组 NDDMA | group selector | `groupR>1 && useNddma==1`；第一阶段 NDDMA，第二阶段强制 `groupTiling.useNddma=0` | 无额外 fallback |

```text
if self.IsEmpty():
    if out.IsEmpty(): R-001(no device)
    else:             R-001(Fill key 101)
else:
    TransformShape -> pattern tuple
    if groupR == 1:
        if useNddma == 0: R-002
        else:             R-003
    else:
        if useNddma == 0: R-004
        else:             R-005
```

### 模板/实现执行矩阵

| Route | key/selector | dtype/shape/platform 完整命中条件 | 执行拓扑与 Kernel 节点 | 实际模板/body | 内存与同步特征 | tail/fallback |
|---|---|---|---|---|---|---|
| R-001 | Fill `101` | 950；API 空输入；输出非空 | 单 Fill AIV；输出空则零节点 | `ElementwiseSch<0, FillDag<int8_t>::OpDag>`，`Duplicate`→`CopyOut` | Fill baseTiling UB；同 stream 后接 ViewCopy | 输出 numel 为 0 时 L0 Fill 直接返回 |
| R-002 | normal tuples | 950；连续输入；`groupR=1,useNddma=0` | 可选 Cast→单 ReduceAll AIV→可选 Cast | `ReduceSch<true,PatternID,LoopARCount,LoopInnerARCount,OpDag>::ProcessNormal` | `DataCopyPad`/loop mode；UB cache 二分归约；无 user workspace 交接 | mask/pad 值 1，GM CopyOut 只写有效长度 |
| R-003 | normal tuples | 同 R-002，但 `useNddma=1` | 同 R-002 | 同一 `ReduceSchAux`，`CopyInAux` 转到 `CopyInWithNddma` | 3/4/5 维 `MultiCopy` 或退化 `DataCopyPad`，随后同一 UB 归约 | NDDMA loopSize/stride 来自 `SliceView`；无额外 fallback |
| R-004 | group tuples | 950；`groupR>1,useNddma=0` | 单 ReduceAll AIV 内 stage-1→SyncAll→stage-2 | `ProcessGroup`：两个 `ReduceSchAux` | stage-1 写 userWS；全核 barrier；stage-2 普通 DMA 读 userWS | 无有效 R 范围的 core 早退；workspace 需完整分配 |
| R-005 | group tuples | 同 R-004，但 `useNddma=1` | 同 R-004 | stage-1 `CopyInWithNddma`；stage-2 `useNddma=0` | NDDMA→workspace→SyncAll→MoveAlign | 同 R-004 |

normal selector 覆盖：AR `(PatternID=11, LoopARCount=10, LoopInnerARCount=0..1)`；ARA `(20,10/20,0..1)`；ARAR `(31,10/20,0..2)`；ARARARAR `(71,10/20/30/40,0..4)`；ARARARARA `(80,10/20/30/40/50,0..4)`。group selector使用相同 patternID，但 `LoopARCount` 为对应宏列出的 A/R 组合（如 AR 的 12，ARA 的 12/23）；Host tuple 是唯一可达来源。

### 隐藏性能 Guard

| Guard | Host/Tiling 条件 | Device/资源原因 | 影响 Route | 不满足时去向 | 源码符号 |

## Kernel 实现

### 公共执行流程

非空主路线的 entry 参数顺序为 `x, axes, y, workspace, tiling`；axes 只参与 Host Tiling，Device body 不读。entry 拒绝 AIC 和空 workspace，解析 `ReduceOpTilingData` 后按 `DTYPE_X` 实例化：FP32 用 `ReduceAllDagFloat<float,int32_t>`，FP16/BF16 用 `ReduceAllDagFloat<T,int16_t>`，BOOL binary 以 `uint8_t` 存储并用 `ReduceAllDag<uint8_t,half>`。三类 DAG 均为 `CopyIn→0/1 正规化/升型→ReduceAllOp→转 uint8→CopyOut`。

`ReduceAllOp` 继承 `ReduceMinOp`：二维 inner pattern 为 AR 时调用 `ReduceMin<T, Pattern::Reduce::AR, true>`，RA 时调用 RA 版本；二分尾部用 `Min(src0,src1)` 合并，cache 继续做 min。所有有效值都被正规化为 0/1，故 min 等价逻辑与；padding 返回 1，不污染尾块。

Cast 前置节点的 `CastDstBool` 使用双缓冲输入/输出 Queue、mask TBuf 和全零 TBuf：`CompareScalar(x,0,EQ)` 后 `Select(mask ? 0 : 1)`。后置 BOOL→UINT8 命中 `CastThrough`，只按有效长度搬运同为 1 字节的值。空输入 Fill key 101 对标量 1 做 `Duplicate`，再 CopyOut。

## 算子特定优化

### Trick T-001：浮点输入在归约 DAG 内正规化为 0/1

#### 触发与源码依据

- 适用 Route：R-002～R-005，950 FLOAT/FLOAT16/BFLOAT16 输入。
- 触发条件：API 不做前置 BOOL Cast；`DoTiling` 选择 `ReduceAllDagFloat<T,PromteT>`。
- Golden 来源：[`math/reduce_all/op_kernel/arch35/reduce_all_dag.h:33-60`](../../../../../../../cann-ops-raw/ascendc/ops-math/165d41f02a43a62324b434cb6bda7c533b14da3e/math/reduce_all/op_kernel/arch35/reduce_all_dag.h#L33-L60)

**官方源码（固定 Commit 连续逐字摘录）**：

```cpp
template <typename T, typename R>
struct CastZeroOne : public Vec::ElemwiseUnaryOP<T, R> {
    __aicore__ inline CastZeroOne(const LocalTensor<T>& dst, const LocalTensor<R>& src, const uint32_t& count)
    {
        constexpr uint32_t VECTOR_LENGTH = GetVRegSize();
        constexpr uint32_t VL_LENGTH = VECTOR_LENGTH / sizeof(T);
        ...
        MicroAPI::Compares<R, CMPMODE::NE>(cmpMask, srcReg, 0.0f, InMask);
        MicroAPI::Duplicate(dstReg, 0);
        MicroAPI::Duplicate(dstReg, 1, cmpMask);
        MicroAPI::DataCopy<T, MicroAPI::PostLiteral::POST_MODE_UPDATE>(dstAddr, dstReg, VL_LENGTH, OutMask);
    }
};
```

#### 机制与设计原因

API 在 950 对三种浮点 dtype 不物化独立 BOOL Tensor。CopyIn 后 `CastZeroOne` 以 vReg 宽度循环：`UpdateMask` 给最后一轮生成输入/输出 mask，`Compares<NE>` 生成非零 mask，两个 Duplicate 组成 0/1，再写 promote buffer。随后 `ReduceMin` 即逻辑与。这样省掉独立 Cast Kernel 及其 GM 中间 Tensor，同时保留 `x!=0` 语义。

#### 迁移边界

- 适用：输出只依赖输入是否为零、后续归约可在 0/1 域表达的 950 AIV 归约。
- 前提：比较、mask、promote dtype 与 tail mask 均可在同一 DAG 内闭合。
- 失效：A2/A3 固定源码不闭合；非浮点输入当前 API 仍先转 BOOL。
- 未验证：本次知识提取未执行编译、真机、数值或性能测试。

#### 错误做法

不能直接对原始浮点值做 `ReduceMin`：例如所有元素均为非零负数时，数值最小值不是逻辑真值。固定源码用显式 `!=0` 正规化避免该语义错误。

### Trick T-002：分组 R 轴在单 Kernel 内以 promote partial + 全核 barrier 合并

#### 触发与源码依据

- 适用 Route：R-004、R-005。
- 触发条件：Host 计算 `groupR>1`，tuple 的 `loopRCount>0`。
- Golden 来源：[`pkg_inc/op_common/atvoss/reduce/reduce_sch.h:248-274`](https://gitcode.com/cann/opbase/blob/d574f5571391390f8b619c6a134b65c819842318/pkg_inc/op_common/atvoss/reduce/reduce_sch.h#L248-L274)

**官方源码（固定 Commit 连续逐字摘录）**：

```cpp
template <class... Args>
__aicore__ inline void ProcessGroup(Args... args)
{
    constexpr static ReduceSchLoopInfo groupSchLoopInfo = GetGroupSchLoopInfo();
    ReduceOpTilingData groupTiling;
    SetGroupTiling(groupTiling);
    if constexpr (isContiguous) {
        using SchTypeR = ReduceSchAux<&SchLoopInfo, std::remove_reference_t<decltype(*this)>, true, OpDag>;
        SchTypeR op(this, input_, &workspace_, &workspace_, tiling_);
        using SchTypeA = ReduceSchAux<&groupSchLoopInfo, std::remove_reference_t<decltype(*this)>, false, OpDag>;
        SchTypeA groupOp(this, input_, output_, &workspace_, &groupTiling);
        op.Process(args...);
        SyncAll();
        groupOp.Process(args...);
    }
}
```

#### 机制与设计原因

当单核不能覆盖整个 R 域时，第一阶段扩大并行度，让各核把 promote dtype 的部分最小值写到 group-major user workspace；`SyncAll` 保证所有 GM partial 可见，第二阶段再沿 groupR 归约。partial 不先降成 BOOL/UINT8，避免改变通用 DAG 的精度/存储约定；单 launch 也避免第二次 Host 调度。

#### 迁移边界

- 适用：归约运算可结合、存在跨核 R 分组且平台支持 kernel 内全核同步。
- 前提：Host 必须分配完整 userWS，设置 schedule mode 1，并保持 group workspace offset 公式。
- 失效：`groupR==1` 必须走单阶段；缺失 `SyncAll` 会造成 stage-2 读取未完成 partial。
- 未验证：本次知识提取未执行编译、真机、数值或性能测试。

#### 错误做法

把 `SyncAll` 删除或仅依赖源代码书写顺序是不安全的：不同 core 的 stage-1 GM 写入没有由单核程序顺序建立可见性。

## 限制与失败边界

- API rank 上限为 8；Tiling 内部前补一维，因此拒绝 `shapeSize>=9`。shape/stride、轴乘积和多处 `uint64_t` 乘法未见统一溢出检查；NDDMA loop size/stride 部分窄化到 `uint32_t`。
- `dim` 必须是非空指针；空数组表示全部轴，不表示 identity。重复轴、越界轴、私有 storage format、输出 shape 不匹配和不支持 dtype 在第一段报错。
- entry 对空 workspace/user workspace 静默返回；正常执行必须使用第一段返回的 `workspaceSize`，不能传自算的较小 workspace。
- 950 分组 selector 使用名为 `ASCENDC_TPL_MIX_AIV_1_0` 的模板标签，但可达 entry 在 AIC 直接返回，body 只有 Vector/NDDMA，不能据标签误判为 MIX_CV。
- AscendC `ReduceMin`、MicroAPI compare/mask、executor、Contiguous 和 ViewCopy 的库内部实现不在固定算子源码中；本卡只记录可见参数、顺序和边界。
- A2/A3 的公开支持与本固定源码只接线 ascend950 之间形成闭包缺口，因此未生成 `all.md`；不以 AICPU 文件存在推测 ACLNN selector。
- 本次知识提取未执行编译、真机、数值或性能测试。
