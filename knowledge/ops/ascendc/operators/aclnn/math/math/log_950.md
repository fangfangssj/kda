# Log 950 ACLNN 算子知识

## 算子速览

| 项目 | 内容 |
|---|---|
| 实际入口 | `aclnnLogGetWorkspaceSize` + `aclnnLog`，公开 ACLNN 两段式接口；本卡不包含 `aclnnInplaceLog`、`aclnnLog2`、`aclnnLog10`。 |
| 计算语义 | 对每个有效元素计算 `out[i] = ln(self[i])`。公开入口固定向内部 `Log` 传 `base=-1.0f, scale=1.0f, shift=0.0f`。 |
| 输入输出 | `self/out` 同 shape，公开文档为 ND、1–8 维；输入支持 BOOL、整数、FP16、BF16、FP32、FP64、COMPLEX64/128，核心 `Log` 输出对 BOOL/整数为 FP32，其余保持输入 dtype，随后框架 `Cast/ViewCopy` 写入用户 `out`。 |

## 接口与语义

### 计算语义

公开 `aclnnLog` 的唯一数学语义是自然对数：对展平后的每个有效元素 `i`，`out[i] = log_e(self[i])`。ACLNN 实现把内部通用 `Log` 的三个属性固定为 `(-1, 1, 0)`；`base=-1` 在 Host Tiling 与 AICPU 中都表示自然底，因而通用公式 `log(shift + scale*x)/log(base)` 的可达分支退化为 `ln(x)`。负数、零、NaN、Inf 和复数的结果由对应 MicroAPI 或 C++/Eigen `log` 语义决定，固定仓没有另加裁剪或域检查。

### 输入、输出与属性

| 参数 | shape/layout | dtype | 约束、默认值与语义 |
|---|---|---|---|
| `self` | 与 `out` 同 shape；公开文档为 ND、1–8 维，可非连续 | BOOL、UINT8、INT8/16/32/64、FLOAT16、BFLOAT16、FLOAT、DOUBLE、COMPLEX64/128 | 非空时先交给框架 `Contiguous`；FLOAT16/BFLOAT16/FLOAT 进入 R-001，其余进入 R-002。 |
| `out` | 与 `self` 同 shape；公开文档为 ND、1–8 维 | FLOAT16、BFLOAT16、FLOAT、DOUBLE、COMPLEX64/128 | 必须通过 `OP_CHECK_RESULT_DTYPE_CAST_FAILED`；复数输入的公开文档要求复数输出。核心 Log 后仍调用框架 `Cast` 和 `ViewCopy`。 |
| `workspaceSize` | 标量 Host 输出 | `uint64_t` | 空 Tensor 固定写 0；非空由 executor 汇总全部框架/核心任务 workspace。 |
| `executor` | Host 对象 | `aclOpExecutor**` | 第一段接口创建并移交所有权；第二段接口消费其任务图。 |
| `workspace` | Device 地址 | 字节缓冲区 | 由用户按第一段返回值分配；R-001 Log Tiling 单独请求 16 MiB，但 Log Kernel 的 `workspace` 参数未读。 |
| `stream` | ACL runtime stream | `aclrtStream` | 交给 `CommonOpExecutorRun`，负责框架节点与核心节点的顺序提交。 |

### 入口与版本

固定源码只公开一组 `aclnnLogGetWorkspaceSize/aclnnLog`，没有更高版本后缀；本卡因此覆盖 950 上实际可见的最新公开版本。公开文档明确支持 Ascend 950PR/950DT。950 AIV 实现同时由 `Log` OpDef 的 `.AddConfig("ascend950")`、`log_apt` 扩展名、`math/log/CMakeLists.txt` 的 `ascend950` 构建项和 `log_binary.json` 的三种 AIV dtype 共同确认。`aclnnInplaceLog` 虽复用同一内部实现，但具有原地语义，不并入本卡；Log2/Log10 也不是本入口的版本族。

## Host/Launcher 执行流程

### 参数校验与前处理

`aclnnLogGetWorkspaceSize` 的顺序是：`CheckNotNull2Tensor` → 根据平台选择 dtype 白名单 → `OP_CHECK_RESULT_DTYPE_CAST_FAILED` → `CheckSameShape1In1Out` → 创建 executor → 对非 ND storage format 只记录 warning → 空 Tensor 直接返回 `workspaceSize=0` → `Contiguous(self)` → 用固定属性调用 `l0op::Log` → `Cast(logOut, out dtype)` → `ViewCopy(castOut, out)` → 返回 executor 汇总 workspace。任一步返回空指针或非成功状态都会终止后续建图。

`l0op::Log` 先分配核心输出：BF16/FP16/FP32/DOUBLE/COMPLEX64/128 保持 dtype，BOOL/整数输出 FP32；再按 `self` dtype 做唯一 selector：BF16/FP16/FP32 调 `LogAiCore`，其余调 `LogAiCpu`。这一步不按属性选路，因为公开入口属性恒为自然对数常量。

### 参数、Workspace 与生命周期

executor 拥有 `selfContiguous`、核心 `logOut`、`castOut` 和任务描述，第一段结束时从 `uniqueExecutor` 转移到调用者的 `executor`。用户拥有外部 workspace，第二段把地址、字节数和 stream 原样传给 `CommonOpExecutorRun`。

R-001 的 Tiling 把 `currentWorkspace[0]` 设为 `16,777,216` B；Kernel entry 保留 `workspace` 形参但 body 没有读取，因此该切片不可当作可复用中间结果。R-002 的 AICPU OpDef 通过公共默认配置声明 `opInfo.workspaceSize="100"`；CPU body 同样没有显式 workspace 访问。`Contiguous/Cast/ViewCopy` 的额外切片、对齐、是否消除及总和只在 executor 框架中，固定算子仓不可见。

### 启动图与失败传播

```text
aclnnLogGetWorkspaceSize
  -> [可选框架节点] Contiguous(self -> selfContiguous)
  -> [核心节点二选一]
       R-001 LogAiCore: log(x, y, workspace, EleBaseTilingData32B), blockDim=blockNum
       R-002 LogAiCpu:  LogCpuKernel::Compute(ctx), AICPU runtime 切分 CPU shard
  -> [框架节点/可能消除] Cast(logOut -> out dtype)
  -> [框架节点] ViewCopy(castOut -> out)
aclnnLog(workspace, workspaceSize, executor, stream)
  -> CommonOpExecutorRun 按 executor 顺序提交
```

核心节点的输入是 executor 持有的连续 `selfContiguous`，输出是 executor 分配的 `logOut`。后续 `Cast/ViewCopy` 只有在核心节点成功后才可消费；具体 stream event 和框架任务消除规则固定仓不可见。第一段的任一 `CHECK_RET/OP_CHECK` 失败都不返回可执行图；第二段由 `CommonOpExecutorRun` 返回运行状态。空 Tensor 没有上述节点，直接交回空任务 executor 和 0 workspace。

## Route 与参数设计

### 分核与资源计算

R-001 将输出 storage shape 合轴为 `dim0 = Π shape[d]`（元素）。ATVOSS 计算 `coreNum = min(platformAivCoreNum, ceil(dim0 * dtypeBits / 32768))`，即至少约 4 KiB 数据才增加一个 AIV core；随后：

```text
blockFormer = align_up(ceil(dim0 / coreNum), 512)       # 源码单位实际为元素
blockNum    = ceil(dim0 / blockFormer)                  # 即最终 blockDim
blockTail   = dim0 - (blockNum - 1) * blockFormer
```

自然对数 DAG 是一条线性 `CopyIn -> LogCustom -> CopyOut`，`MemLevel::LEVEL_2` 下需要一对 MTE2 ping/pong 和一对 MTE3 ping/pong，没有额外 TBuf，故 `OpDag::BufferNum=4`。设 `s=sizeof(dtype)`，则：

```text
alignFactor = 256 / s                                  # 元素
ubFormerRaw = floor(UB_bytes / (4 * s))                # 元素
ubFormer    = floor(ubFormerRaw / alignFactor) * alignFactor
```

Device 用同一 `dim0/coreNum` 重算 block 和 tile 循环；`loopNum=ceil(blockLen/ubFormer)`，最后一次只处理 `tailNum`。R-002 不使用 AIV Tiling；BOOL/整数在 `data_num>35*1024` 时进入 `ParallelFor`，DOUBLE 在 `data_num>60*1024` 时并行，COMPLEX64/128 在 `data_num>18*1024` 时并行，其余走单 shard。

### Route 选择

| 顺序 | Route | Key/模板 | 精确选择条件与优先级 | 不适用去向 |
|---:|---|---|---|---|
| 1 | R-001 AIV 自然对数 fast DAG | `GET_TPL_TILING_KEY(1, 1)`；`LogKernel<1,1,DTYPE_X>` | 非空，`self dtype ∈ {FLOAT16,BFLOAT16,FLOAT}`；公开入口固定 `base=-1,scale=1,shift=0`，Tiling 得到 `attrWork=1` | dtype 不命中转 R-002；AIV Tiling dtype/shape/UB 失败则建图失败，不转 AICPU |
| 2 | R-002 AICPU 自然对数 | `LogCpuKernel::Compute` + `log_calls[Tin][Tout]` | 非空，且 `self dtype ∉ {FLOAT16,BFLOAT16,FLOAT}`，但通过公开 dtype 校验 | map 中无 `(Tin,Tout)`、属性或输入输出检查失败则返回 AICPU 参数错误 |

```text
if self.IsEmpty(): success, no core route
else if self.dtype in {FLOAT16, BFLOAT16, FLOAT}:
    LogAiCore
    if fixed attrs satisfy natural-log predicate: key=(schMode=1, attrWork=1) -> R-001
    else: dormant generic Log route（不属于 aclnnLog 可达路线）
else:
    LogAiCpu -> R-002
```

## Kernel 实现

### 公共执行流程

两条 Route 共用 ACLNN 前后图和 `l0op::Log` dtype selector。非空输入先形成连续 tensor，核心节点只接受一个输入并产生一个同 shape 临时输出；核心之后统一经过框架 Cast 和 ViewCopy。公开入口的 `base/scale/shift` 恒为自然对数常量，所以 AIV 的通用属性 DAG和 AICPU 的 Log2/Log10/shift/general 分支均不可达。核心节点之间没有 workspace producer→consumer 边；AIV 16 MiB 和 AICPU 100 B 都是任务保留空间，算子 body 不读写它们。

### Route R-001：AIV 自然对数 fast DAG

#### 适用条件

##### 选择证据

| 层级 | 文件 | 符号 | 源码谓词/参数 | 结果/下一跳 |
|---|---|---|---|---|

blockFormer = align_up(ceil(dim0/coreNum), 512)
blockNum = ceil(dim0/blockFormer)
blockLen = (blockIdx == blockNum-1) ? dim0-(blockNum-1)*blockFormer : blockFormer
base = blockIdx * blockFormer

for tile in [0, loopNum):
    n = (tile == loopNum-1) ? blockLen-(loopNum-1)*ubFormer : ubFormer
    pp = tile & 1
    ubIn[pp][0:n] = DataCopyPad(x[base + tile*ubFormer : +n], blockCount=1,
                                blockLen=n*sizeof(U), srcStride=0, dstStride=0, pad=false)
    VL = VECTOR_REG_WIDTH / sizeof(float)
    for reg in [0, ceil(n/VL)):
        mask = UpdateMask<float>(remaining n)
        if U == float:
            r32 = DataCopy<DIST_NORM>(ubIn + reg*VL)
        else:
            r16 = DataCopy<DIST_UNPACK_B16>(ubIn + reg*VL)
            r32 = Cast<float,U>(r16, ZEROING)
        z32 = MicroAPI::Log(r32, mask)
        if U == float:
            DataCopy<DIST_NORM_B32>(ubOut[pp] + reg*VL, z32, mask)
        else:
            z16 = Cast<U,float>(z32, NO_SAT, CAST_RINT, ZEROING)
            DataCopy<DIST_PACK_B32>(ubOut[pp] + reg*VL, z16, mask)
    DataCopyPad(y[base + tile*ubFormer : +n], ubOut[pp], blockCount=1,
                blockLen=n*sizeof(U), srcStride=0, dstStride=0)

## 算子特定优化

### Trick T-001：公开自然对数属性折叠为三节点 fast DAG

#### 触发与源码依据

- 适用 Route：R-001
- 触发条件：公开入口固定 `base=-1,scale=1,shift=0`，Tiling 得到 `invLnBase=1`，三个近似相等谓词同时成立。
- Golden 来源：[`math/log/op_host/arch35/log_tiling_arch35.cpp:103-114`](../../../../../../../cann-ops-raw/ascendc/ops-math/165d41f02a43a62324b434cb6bda7c533b14da3e/math/log/op_host/arch35/log_tiling_arch35.cpp#L103-L114)

**官方源码（固定 Commit 连续逐字摘录）**：

```cpp
float invLnBase = NearlyEqual(baseValue, -1.0f) ? 1.0f : 1.0f / log(baseValue);
float scale = scaleValueAttr == nullptr ? 1.0f : *scaleValueAttr;
float shift = shiftValueAttr == nullptr ? 0.0f : *shiftValueAttr;
attrInvLnBase = invLnBase;
attrScale = scale;
attrShift = shift;
if (NearlyEqual(scale, 1.0f) && NearlyEqual(shift, 0.0f) &&
    std::abs(invLnBase - 1.0f) < std::numeric_limits<float>::epsilon()) {
    attrWork = static_cast<uint64_t>(TPL_SCALE_IS_ONE_SHIFT_IS_ZERO_LNBASE_IS_ONE);
} else {
    attrWork = static_cast<uint64_t>(TPL_SCALE_NOT_ONE_SHIFT_NOT_ZERO_LNBASE_NOT_ONE);
}
```

#### 机制与设计原因

key 1 只实例化 `CopyIn<U> -> LogCustom<U> -> CopyOut<U>`，不执行通用路线的输入 Cast、Muls(scale)、Adds(shift)、Muls(invLnBase) 和输出 Cast。对 `aclnnLog` 这不是概率优化，而是由 API 常量保证的唯一 AIV 路线；它同时把 LEVEL_2 DAG 的 UB 需求压缩到一对 MTE2 与一对 MTE3 ping/pong，共四个 tile buffer。

#### 迁移边界

- 适用：元素级自然对数且内部属性与 `(-1,1,0)` 等价的 950 AIV 实现。
- 前提：FP16/BF16/FP32、ND 连续核心输入、950 `log_apt`，且 Host 与 Kernel 使用同一 key 约定。
- 失效：scale、shift 或底数改变时必须切换 key 2 的通用 DAG；该通用语义不属于公开 `aclnnLog`。
- 未验证：本次知识提取未执行编译、真机、数值或性能测试。

#### 错误做法

把 `aclnnLog` 的 fast key 复用于非默认属性会漏掉 scale/shift/base 变换；源码已提供 key 2 作为真实反例和正确去向。

### Trick T-002：16 位输入在寄存器中升 FP32 做 Log，再 RINT 回写

#### 触发与源码依据

- 适用 Route：R-001 的 FP16/BF16 实例。
- 触发条件：`T` 不是 `float`；每个 MicroAPI reg loop 使用有效 lane mask。
- Golden 来源：[`math/log/op_kernel/arch35/log_dag.h:75-87`](../../../../../../../cann-ops-raw/ascendc/ops-math/165d41f02a43a62324b434cb6bda7c533b14da3e/math/log/op_kernel/arch35/log_dag.h#L75-L87)

**官方源码（固定 Commit 连续逐字摘录）**：

```cpp
for (uint16_t loopIdx = 0; loopIdx < loopNum; loopIdx++) {
    mask = MicroAPI::UpdateMask<float, MicroAPI::RegTraitNumOne>(count);
    // OpCopyIn
    MicroAPI::DataCopy<T, MicroAPI::LoadDist::DIST_UNPACK_B16>(
        vregInput16, (__ubuf__ T*)(srcAddr + loopIdx * vlSize));
    MicroAPI::Cast<float, T, castTrait0>(vregInput, vregInput16, mask);

    MicroAPI::Log(vregOutput, vregInput, mask);

    MicroAPI::Cast<T, float, castTrait1>(vregOutput16, vregOutput, mask);
    // OpCopyOut
    MicroAPI::DataCopy<T, MicroAPI::StoreDist::DIST_PACK_B32>(
        (__ubuf__ T*)(dstAddr + loopIdx * vlSize), vregOutput16, mask);
}
```

#### 机制与设计原因

UB 仍以 16 位 U 存放，load 时用 `DIST_UNPACK_B16`，随后以 ZEROING mask 升到 FP32 RegTensor；`MicroAPI::Log` 只在 FP32 lane 上计算，输出再以 `NO_SAT + CAST_RINT + ZEROING` 降为 U 并 pack。这样没有额外 FP32 UB Tensor，精度提升只占用寄存器生命周期，同时 mask 阻止尾部无效 lane 写回。

#### 迁移边界

- 适用：可按 B16 unpack/pack 的 FP16/BF16 元素级超越函数。
- 前提：950 MicroAPI、FP32 Log 支持、目标舍入语义为 RINT，且地址步长仍以 `VL=VECTOR_REG_WIDTH/4` lane 组织。
- 失效：FP32 输入走 normal B32 load/store；若输出要求不同舍入/饱和语义，必须更改 CastTrait，不能照搬。
- 未验证：本次知识提取未执行编译、真机、数值或性能测试。

#### 错误做法

直接对 FP16/BF16 UB 数据使用与 FP32 路线相同的 normal load/store 会破坏 unpack/pack 布局；直接省略 FP32 Cast 也不再等价于源码的精度顺序。

## 限制与失败边界

- `aclnnLog` 只闭合自然对数。通用内部 `Log` 的自定义 base/scale/shift、Log2、Log10 和原地入口均不得从本卡推导。
- 公开文档把格式限定为 ND，并写明格式不支持会报错；固定实现的 `CheckFormat` 对非 ND 只 warning。实际框架是否在更深层拒绝或转换，固定仓不可见。
- 公开文档写 1–8 维且维度大于 8 报错；out-of-place `CheckParams` 没有显式 `OP_CHECK_MAX_DIM`，该检查是否隐藏在框架 helper 中固定仓不可见。不得仅凭实现删除公开约束。
- `dim0=Πshape[d]`、`coreNum/ubFormer` 向 int32 POD 的窄化没有显式溢出检查；超大 shape 的失败边界不能推测。
- R-001 Tiling 要求非零元素数、UB 可生成非零对齐 tile；ACLNN 空 Tensor 在此之前返回成功。Tiling 失败不会自动转 AICPU。
- AIV 的 16 MiB workspace 参数未被 Kernel 使用，AICPU 的 100 B workspace 也未被 CPU body显式使用；不能把这两个区域解释成算子中间结果。
- `Contiguous/Cast/ViewCopy/CommonOpExecutorRun` 的实现、任务消除、workspace 对齐、跨节点 event 与总 workspace 公式是固定仓不可见的框架边界。
- A2/A3 公开支持与本固定仓实现闭包不一致：缺少其 FP16/BF16/FP32 AICore OpDef/config/Kernel 接线，因此未生成 `log.md`。
