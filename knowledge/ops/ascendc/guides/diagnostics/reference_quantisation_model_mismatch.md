# 参考实现的量化建模与器件不一致时，精度缺陷会记在算子头上

## 症状

MXFP8 反向的 `dV` 在部分 `s2` 上超精度门限，另一些上通过，且形态"很像内核 bug"：

- 失败与通过按 `s2` 划分：128/256/512/1024 通过，384/640/768/896/1152 失败；
- 失败时**每个 kv 块退化程度相同**（逐行看 `k` 的标准差仅 0.0096，没有一行接近 1.0），
  不是某块被破坏；
- 与 `s1` 无关；换随机种子（4 个）结论不变；
- `dQ`/`dK` 全程正常。

于是很自然地去内核里找"随 kv 块数变化的状态"——**方向就错在这里**。真正的缺陷在**参考实现**。

## 判据一：量斜率，不要只量距离

`rel_l2` 把"系统性缩放"和"噪声"混在一起。改量回归斜率

```
k = <device, gold> / <gold, gold>
```

结构立刻显形：`k` **只取决于 kv 块数的奇部**（3、6、12 → 0.919；5、10 → 1.045；
1、2、4、8、16 → 0.997）。先预测后验证的 4 个点全中。

## 判据二：奇部 ⇒ 尾数 ⇒ 舍入网格，而不是循环

块宽本身是 2 的幂，所以 `odd(块数) ≡ odd(s2)`；而 softmax 后 `P ~ 1/s2`，

```
1/s2 = (1/odd) · 2^-k
```

2 的幂因子只平移浮点**指数**，**尾数**由奇部决定。"只随奇部变"是**舍入网格**的签名——
循环、缓冲区乒乓、竞态都不关心尾数。这一步就应该把嫌疑从内核转向数值格式。

本例的根因：golden 把 `P` 建模成扁平 **HiFloat8** round-trip，而器件把 `P` 量化成
**MXFP8**（E4M3 payload + 每 32 元素一个 E8M0 块缩放，沿收缩轴）。**块缩放的作用正是消除
量级依赖**，所以器件的相对误差与量级无关、golden 的与量级有关。HiFloat8 是**渐变精度**
（tapered）格式，尾数位宽随指数变化、离 1.0 越远越窄——这正是 golden 误差随量级摆动的根。实测 HiF8 对 `P` 的偏置
最大到 **+7.8%**。

## 判据三：用双方都没生产的第三方基准裁决

两个模型之间的差值，是关于**这一对**的证据，不能单独指认其中一个。用**精确 P** 和双方共用
的 E4M3 `dO` 离线重算 `dv_exact = p_exactᵀ · doDec`：

| s2 | HiF8 对 P 的偏置 | device vs EXACT | gold vs EXACT |
|---|---|---|---|
| 384 | 1.0779 | k=0.9991 rel=0.0524 | k=1.0789 rel=0.1217 |
| 640 | 0.9527 | k=0.9985 rel=0.0508 | k=0.9518 rel=0.0749 |
| 896 | 0.8963 | k=0.9994 rel=0.0544 | k=0.8961 rel=0.1287 |
| 1024 | 0.9979 | k=0.9953 rel=0.0525 | k=0.9956 rel=0.0502 |

**device-vs-exact 在 s2=128…1536 上平坦（rel_l2 0.051–0.059）；gold-vs-exact 与 HiF8 偏置
逐项对应（~1e-3 量级一致，非逐位相等）。** golden 的误差**就是**它 P 模型的偏置。

## 判据四：改一个器件证明不读的输入（零理论对照）

找一个算子**确证不消费**的输入（本例 `p_scale` 只出现在 kernel 入口签名里，从不被读），
改它并对比字节：

| P_SCALE | device `dv` sha256 | golden `dv` sha256 |
|---|---|---|
| 1 | `30f0345a4abc540b` | `52dc3a658d912de7` |
| 2 | `30f0345a4abc540b` | `52dc3a658d912de7` |
| 3 | `30f0345a4abc540b` | `5e2991bd989c5f25` |

器件输出**逐字节不变**而 golden 在变——**不需要任何机理假设**即可证明 **`p_scale` 这条通道上**的
差异全在参考侧。这条对照只承重这条通道；`s2` 失败的归因由判据三承重。
顺带：2 的幂缩放使 golden 字节完全不变，符合正规范围内浮点格式应有的行为，可作为
"这条通路确实只受尾数影响"的自检。

## 改法与复现的坑

把 golden 的 `P` 模型改成与器件一致（每 32 元素沿收缩轴取 `amax`，归一到 [256,512)，
E4M3 量化后乘回块缩放）。改后 `dV` 在全部 `s2` 上平到 rel_l2 ≈ 0.0466（原先 0.072–0.157）。

**写这个模型时会撞到一个坑**：把组最大值归一到 `[256,512)` 是对的，但 **E4M3FN 的最大正规数
是 448**（`0x7F`/`0xFF` 是 NaN），所以落在 `(448, 512)` 的组会 cast 成 NaN 并污染整张
golden（RN 舍入下越过约 464 即变 NaN，确切阈值与实现相关；一律钳到 448 最稳）。器件侧本来就有这个钳位，模型必须一并复制，否则只在个别 `s2` 上吐 NaN，很难归因。

## 边界

- 结论绑定实测硬件 Ascend950DT + CANN 9.2.0；HiF8 的具体偏置数值依赖该格式实现，换平台需重测。
- "奇部决定"是本例 `P ~ 1/s2` 带来的特化形式；可迁移的是**"只随尾数变 ⇒ 看舍入网格"**，
  不是 `odd` 这个函数本身。
- 一条**失败的预测**照录：预期 `P_SCALE=3` 会把原本通过的 `s2=512` 弄坏，实测没有（0.9949）。
  所以偏置不是"典型值尾数"的简单函数，只有 HiF8 网格的某些尾数区间是坏的；机理在
  "失败 s2 被修好"这个方向上成立，反方向未完全刻画。
- 本卡不含任何"该算子精度达标"的结论；它只说明**差值归属**的判定方法。
- 同族交叉：`quant_reference_must_not_share_lossy_step` 讲 golden **共用有损步骤**导致的*假通过*；
  本卡讲 golden **建错格式**导致的*假失败*。两者是参考侧失效的两个方向。
